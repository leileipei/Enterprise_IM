# 企业 IM P4-26 附件运行配置

## 适用范围

本说明对应 P4-26 正式 API 装配。附件业务总开关默认关闭；启用需要完成下列部署预检。本地正式进程验收不代表客户 IdP 联调、M4、安全评审、生产发行版、HA、容量或备份 DR 已通过。具体源码及七项门禁见[验收记录](开发增量-P4-26-验收记录.md)。

## 开关及能力

`U=IM_FILE_UPLOAD_ENABLED`，`B=IM_FILE_BUSINESS_ENABLED`；仅接受空值／`false`／`true`，大小写或空格变体拒绝。能力接口返回顺序为上传、发送、下载、名称搜索：

| U | B | 四项能力 | 实际入口 |
| --- | --- | --- | --- |
| false | false | false,false,false,false | 附件业务关闭 |
| true | false | true,false,false,false | 预约、PUT、本人状态、上传设置／历史 |
| false | true | false,true,true,true | 既有附件发送、授权 GET、名称搜索、本人状态、上传设置／历史 |
| true | true | true,true,true,true | 完整附件链路 |

能力表示装配开关，依赖故障时不会假装关闭能力；实际操作拒绝，就绪返回503。`typed_v1.download_available` 仍为 false，每次 GET 独立验证资格。保留策略／法务保全继续按原管理权限生效。关闭 B 不解析下载配置、不访问其对象存储或目录；关闭 U 不要求 API 上传凭据、上传 spool、scanner 或 qpdf。B 开启必须有数据库及有效 OIDC 配置。

## 变量矩阵

| 变量 | 用途及规则 |
| --- | --- |
| `IM_DATABASE_URL` | 当前进程独立数据库角色；通过受控凭据注入，日志不输出 DSN |
| `IM_OIDC_ENABLED=true`、`IM_OIDC_ISSUER`、`IM_OIDC_AUDIENCE`、`IM_OIDC_JWKS_URL`、`IM_OIDC_ALLOWED_CLIENT_IDS` | 沿用实际身份映射与当前任职，B 开启必需 |
| `IM_FILE_S3_ENDPOINT`、`IM_FILE_S3_REGION`、`IM_FILE_S3_BUCKET`、`IM_FILE_S3_PATH_STYLE` | 上传、下载共用定位；B 只允许 HTTPS 或本机 HTTP，私有且启用版本控制的桶 |
| `IM_FILE_DOWNLOAD_S3_ACCESS_KEY`、`IM_FILE_DOWNLOAD_S3_SECRET_KEY` | B 的独立只读主体；内部固定 `download_environment`，不能回退到上传／清理凭据，配置中的访问键不得相同 |
| `IM_FILE_DOWNLOAD_SPOOL_DIR` | B 的绝对路径，当前实际 UID 所有，0700，独占，无符号链接；文件0600 |
| `IM_FILE_DOWNLOAD_OWNER_ID` | B 的稳定小写、非零 UUID；每节点不同，同节点重启保持，不在每次启动重新生成 |
| `IM_FILE_READ_PROBE_VERSION_ID` | 引导主体写入固定探针得到的不可变、非空且非 null 的 VersionID |
| `IM_FILE_S3_CREDENTIAL_SOURCE=environment`、`IM_FILE_S3_ACCESS_KEY`、`IM_FILE_S3_SECRET_KEY`、`IM_FILE_SPOOL_DIR` | U 开启的上传主体与独立上传目录；API 不配置扫描工具 |
| `IM_FILE_WORKER_ENABLED=true`、`IM_FILE_WORKER_ID` | 独立扫描进程；Worker ID 为小写 UUID |
| Worker 的 `IM_FILE_S3_ACCESS_KEY/SECRET_KEY`、`IM_FILE_SPOOL_DIR` | 对应扫描主体与其私有目录，不能拿下载或清理角色代替 |
| `IM_FILE_QPDF_PATH`、`IM_FILE_CLAMD_SOCKET`、`IM_FILE_SCANNER_MANIFEST` | Worker 的真实工具、socket、可信运行与定义指纹；不能用 ready 文件代替 |
| `IM_REALTIME_REDIS_URL` 及既有 Stream 配置 | 启用时沿用 Redis／fanout 健康验证；Outbox 发布进程独立运行 |
| `IM_FILE_CLEANUP_S3_ACCESS_KEY`、`IM_FILE_CLEANUP_S3_SECRET_KEY` | 仅物理清理进程需要；repair-only 不需要、也不会构造对象删除器 |

部署时通过密钥管理或只允许服务账户读取的环境文件注入秘密；本文没有客户 DSN、token 或访问键示例。

## 独立对象存储角色与固定探针

| 主体 | 业务权限 | 必须实测拒绝 |
| --- | --- | --- |
| 上传 | 指定私有桶内 PUT、固定版本 GET、上传尝试版本查找 | DELETE、跨桶 |
| 扫描 | 固定版本 GET、扫描需要的版本查找 | PUT、DELETE、跨桶 |
| 下载 | 固定版本 GET，以及版本控制／ACL／桶策略只读检查 | PUT、DELETE、ListObjectVersions、匿名、跨桶 |
| 清理 | 固定版本 GET／版本枚举／精确版本 DELETE | 无 VersionID 删除、跨桶 |
| 引导 | 运维期间创建桶／角色／固定探针 | 不能作为 API 下载凭据 |

API 实际调用 `GetBucketVersioning`、`GetBucketAcl`、`GetBucketPolicy`；授权动作需按供应商实现配置，不可只给 GetObjectVersion 后忽略启动检查。本轮锁定 MinIO 的 ACL 查询授权使用 GetBucketLocation，版本删除先检查 DeleteObject；清理角色使用该版 `s3:versionid` 条件，仅在存在、非空且非 null 时允许，仍实际拒绝不带版本的删除。[锁定实现](https://github.com/minio/minio/blob/RELEASE.2024-11-07T00-52-20Z/cmd/auth-handler.go#L431)。生产对象存储需要重做原生 IAM 拒绝验收。

引导主体在桶 `_im_runtime/read-probe/v1` 写入精确字节 `enterprise-im-file-read-probe-v1\n`，最后是一个 LF。记录返回 VersionID，配置给下载进程。启动及 ready 只读取该固定版本，核对返回 VersionID 和完整内容，额外一字节即可失败，不读取业务文件，不自动 PUT 探针、不枚举版本。探针内容上限小于1KiB；桶必须始终私有、启用版本控制。

## 数据库和目录部署预检

1. 使用既有迁移000001～000021完成结构，再发布应用；本阶段无新增迁移。应用启动只读检查表、列、约束、唯一索引、触发器／函数定义及运行权限，不执行 DDL。
2. API 的附件启动检查所需 SELECT／INSERT／UPDATE／序列权限详见 `internal/policystore/file_business_runtime_check.go`。这只是附件检查的下限，API 原管理模块还需对应权限；不可把测试管理员 DSN 用作部署方案。
3. repair-only 角色对该文件 `fileAuditRuntimeTables` 中11张表具备 SELECT；对 conversations、file_objects、file_download_sessions 具备 UPDATE（含 PostgreSQL 行锁要求），对 file_download_terminal_events 具备 INSERT／UPDATE，对 file_worker_audit_events 具备 INSERT 和其序列 USAGE，并可执行依赖约束函数。不需 DELETE、DDL 或对象存储权限。
4. 下载目录与上传／扫描目录不能相同、互为祖先、经链接解析重叠或为同一 inode。每节点使用独立目录与稳定 owner；权限和 UID 必须由实际运行账户检查，不能以运维 root 的结果代替。
5. 首次可提供空的0700目录。应用取得独占锁并写入归属 manifest；重启只回收可证明属于此 owner 的未完成下载文件。未知文件、错误 owner、链接、权限错误都保留并拒绝启动，不能靠删除整个目录绕过。运行期间目录 inode 或 manifest 改变将使 ready 失败。

## 启动顺序和期限

U=true/B=true 时，在原上传15秒子预算内额外检查 `file_objects` INSERT／UPDATE、`file_lifecycle_events` INSERT、`file_upload_attempts` INSERT／UPDATE、`tenant_file_upload_policy` UPDATE 及这四表 SELECT／结构契约；API 不要求扫描 Worker 的写权限。U=false/B=true 不要求上传专用写权限。U=true/B=false 按已批准范围保留旧预检，不能据此声明旧路径已完整检查全部上传写权限。

先准备数据库迁移／角色、私有版本桶／独立 IAM／探针、私有目录与稳定 owner、可信 scanner、Redis，再启动文件 Worker／Outbox、正式 API 和审计修复进程。B 初始化在监听之前共享30秒上限；若 U 也开启，其子检查最多15秒且仍受同一剩余30秒约束。Worker 沿用90秒启动预算。启动失败非零退出、不开监听端口。

最终 `/health/ready` 共用2秒外层预算：数据库、启用的 Redis／fanout，以及 B 的下载目录和固定探针；不修改业务数据。依赖中断时 ready503、live仍200，恢复后重测 ready200。scanner 停机不把既有 ready 文件的读取变成扫描；新上传由既有扫描状态／期限控制，不能跳过检查。

一般 API 写期限10秒；名称搜索共用总5秒、statement4秒、lock1秒，最多500候选／20会话并返回续查游标。下载服务总60秒且每块使用原资格复核／1秒写边界；Web 调用下载上限65秒、完整 Blob 保存入口60秒、扫描轮询120秒，均未提高。

## 定义更新

病毒定义的24小时上限以 daily.cvd 内的官方发布 epoch 为准，下载时间或文件 mtime 不能代替它。更新需下载官方新定义，核对版本、真实 SHA256，重启实际 clamd，并重新生成与实际 PID／配置／工具／定义文件绑定的只读 manifest；再分别验证可信与限制负例运行证明。保留旧定义和旧 manifest，不能伪造时间或放宽上限。本轮长门禁确实跨过旧定义期限，已保留失败记录并以官方28144定义重新启动全部七项验收。

## 暂停、退出和恢复

实际进程验收包含收到32768字节正文后保持 TCP 连接、停止继续读取并发送 SIGTERM，核对中断终态、Prepared 目录释放与同 owner 重启。API 先写终态事实，机器审计由独立 repair-only 进程确认；重复修复仍只产生一次审计。

- 暂停新上传：设置 U=false、B=true，重启 API；旧授权附件继续发送／下载／搜索，不需要上传凭据或目录。单独控制扫描 Worker 是否继续处理存量任务。
- 关闭附件业务：B=false；U 可独立保留。开关关闭只控制入口，保留策略、法务保全和删除任务仍按各自授权运行。
- SIGTERM：HTTP 最多10秒等待，超时关闭连接并取消请求，再给资源 Close 独立10秒。强制关闭或清理失败返回非零，保留恢复证据；运维需先记录异常并检查归属，不能把未知内容批量清除。
- SIGKILL：同一稳定 owner 重启后只回收具备完整本节点来源证明的下载残留；未知内容仍保留并拒绝启动。进程重新 ready 后验证一个旧附件 GET 和名称查询。
- 在途撤权、JWT 到期、当前任职／上传者停用、hard deny、历史间隔及 TTL 都继续动态复核。已被内核接受的字节不可召回，测试分别记录已接受字节和之后的中止。

## 审计专用修复与物理删除

使用独立 repair 数据库角色，仅注入 `IM_DATABASE_URL`：

```sh
im-file-cleaner --execute --repair-only --once
im-file-cleaner --execute --repair-only
```

一次模式在失败时非零退出；连续模式每批最多20条、5秒，空闲1秒，故障退避1／2／4／8／16／30秒并支持取消。重复、未知或冲突参数在依赖初始化前拒绝。不加 `--execute` 保持默认关闭。修复使用原会话截止及来源证据，恰一次补齐终结与机器审计，结果可为 unknown／process_lost；不领取删除任务、不读取／删除对象、不把修复解释为下载成功。

物理清理仍是独立授权动作，只有准备好清理凭据和原保留／法务保全规则才运行：

```sh
im-file-cleaner --execute --once
```

该命令会处理原物理删除流程；不能为了补审计而运行它。检查异常退出、未结算会话、repair-only 的机器审计和实际 ready 恢复，各项分别留下记录。
