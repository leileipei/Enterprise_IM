# 开发增量 P1-02a 验收记录

**范围：**管理员 Scope、受限人员查询、单组织离职；依据 v2.2 的 G01、G02、G05、G11 场景。设计见 [规格](superpowers/specs/2026-09-28-p1-02a-access-directory-design.md)。

## 已实现

- `admin_grants` 以租户、选定任职和可选组织 Scope 记录集团或组织管理员授权；数据库拒绝跨租户 Scope、任职组织不符和无效角色组合。
- `GetManagedPerson` 从数据库校验管理员账号及选定任职，只返回获授权组织内的当前任职、职位和部门。跨租户或超出 Scope 的目标不返回人员详情，允许及拒绝结果均写审计。
- `EndMembership` 在单一事务中结束指定组织任职和当前部门任职、写审计，保留集团账号及其他组织任职。未来部门任职需先取消；重复结束返回冲突。审计写入失败时，事务回滚。
- 写操作按固定顺序锁定操作者与目标任职，在拿到行锁后读取操作时间，并在授权锁等待后重新校验有效期；管理员只读查询也在等待后复核授权有效期。
- API 入口仍只有 `/health/live` 与 `/health/ready`；本阶段未将内部服务暴露为未经认证的 HTTP 接口。

## 本地验证

环境：macOS、Go 1.27.1、仅绑定 `127.0.0.1:55432` 的临时 PostgreSQL 16 容器。每个数据库集成测试使用独立 schema。

| 检查 | 结果 |
| --- | --- |
| `IM_TEST_DATABASE_URL=... go test ./... -count=1` | P1-01 与 P1-02a 测试全部通过 |
| `go vet ./...` | 退出码 0 |
| `go build ./...` | 退出码 0 |
| 新迁移 Down 后重新 Up | `admin_grants` 已删除并可重新创建 |
| 注入审计写入失败 | 单组织离职返回错误，原任职保持有效 |
| 并发自离职与授权到期 | 一次操作成功、另一次因身份失效拒绝且两次均有审计；锁等待后到期的授权无法继续读取或结束任职；并发场景连续运行 5 轮通过 |

## 边界与后续

- 当前 `TrustedIdentity` 必须由未来认证入口构造；尚无真实 SSO/OIDC、登录会话或公共管理 API。不能把本地测试身份当成已验证用户。
- 普通员工通讯录仍需通信策略判定。本增量是管理员查看获授权人员信息的内部能力。
- 策略规则、版本发布和决策审计尚未持久化；P1-02b 应实现这些能力，再接入已认证的管理 API。
- 尚未使用客户脱敏组织数据进行端到端验收，也未验证生产容量、高可用或灾难恢复指标。
- 独立代码评审指出的并发锁升级和旧时间授权问题已用先失败、后通过的回归测试修复。此验证基于本机 PostgreSQL 16；未进行跨节点并发压测。
