# P3-06 群主转让设计

## 目标与范围

让现任群主将所有权交给本群另一位活跃成员。原群主降为普通成员，之后可自行退群。转让不改变成员区间、消息序号或通信策略，也不解除 `policy_blocked`。管理员任免、群消息与群解散另行实现。

## 接口与重试

`POST /api/v1/groups/{group_id}/owner-transfers` 接收严格 JSON：`client_request_id`、`source_interval_id`、`target_interval_id`，均为 UUID。首次成功返回 201，重试同一请求返回 200；响应包含两个区间 ID。请求 ID 在租户、群、发起用户内唯一；同 ID 修改选定任职、源或目标区间返回 409 `idempotency_conflict`。数据库保存成功请求记录，旧请求在后续再次转让后重试也只返回原结果，不回滚当前群主。

## 授权与事务

服务仅使用已验证身份。发起人选定的当前任职、账号及群内源区间均须有效，源区间须为活跃群主。集团统一用户可在入群时的来源任职结束后，改用本人另一有效任职转让群主，以免群主无法离开；源区间仍必须属于本人。目标须是同群另一位活跃成员，其来源任职与账号仍有效。`active` 和 `policy_blocked` 群可转让，`ended` 群不可转让。无效身份 403，非群主 403 `group_permission_denied`，群或目标不可用 404，无效请求 400，幂等冲突 409，存储或审计故障 503。

事务锁定群行，随后锁定源与目标区间、复核自然到期时间。先将原群主降为 `member`，再提升目标为 `owner`，满足活跃群主唯一索引。写入幂等记录及 `group_owner_transfer` 审计后才提交。非群主、幂等冲突，以及数据库能识别的冻结账号或失效任职均写拒绝审计；无法对应真实任职的身份直接拒绝，避免伪造审计主体。审计失败回滚角色变更。重复请求不重复写成功审计。

## 验收

覆盖普通成员与管理员接任、原群主退群、旧请求在两次转让后重试、同 ID 异参冲突、非群主、跨租户/跨群/失效目标、封锁与结束状态、任职到期、审计回滚及并发操作。数据库迁移验证请求唯一、同群区间外键和有记录时不可回退；HTTP 验证可信身份、严格 JSON、错误映射。
