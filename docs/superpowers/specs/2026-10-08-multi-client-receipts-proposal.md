## 1. 目标与基线

用户要求完成桌面／移动端、设备送达及已读。完成目标是可安装、连接真实后端的客户端和可恢复的回执状态；仅生成客户端项目、使用模拟 API 或通过共享逻辑测试，均不能作为该平台完成依据。

需求依据为 `enterprise_im_group_v2_2.docx` 第8、9.2、12章及现有历史读取授权逻辑。保持既有 tenant 隔离、多任职、群成员有效区间、hard_deny、保留期、法务保全、ACK/seq/Outbox 原子性及审计规则。

目前尚无桌面／移动项目、设备表或送达／已读表。现有 WebSocket 发出不含业务数据的 `sync_required`，客户端随后 HTTP 补拉；该通知不能产生送达回执。当前 Outbox 的类型与外键限定消息事件，不能直接塞入回执事件。

## 2. 客户端范围与方案选择

首批平台已确认 Windows、macOS、Android、iOS；采用推荐的 Flutter 方案。

| 方案 | 实现方式 | 取舍 |
| --- | --- | --- |
| A：Flutter，推荐 | 一个客户端工程，共用协议、同步与页面逻辑，分别构建桌面和移动应用 | 新增 Dart 技术栈，需要重建客户端页面；便于统一设备存储、生命周期和回执行为 |
| B：Electron＋Capacitor | 复用现有 Web 页面，分别适配桌面和移动容器 | 页面复用较多，但需改造 OIDC、桥接、跨域、本地存储与移动交互，维护两套平台容器 |
| C：各平台原生 | 桌面及两个移动系统分别实现 | 平台适配自由度高；重复实现与协议一致性验证成本最高 |

本提案建议 A，现有 Web 继续使用原有技术栈，并通过相同协议契约测试确保一致性。技术栈与平台范围已确认，精确依赖及构建门禁见客户端细化规格；尚未下载或安装依赖。

首批客户端功能：配置集团服务地址、外部浏览器 OIDC 登录、选择任职、目录查找、单聊、群列表与建群、群成员查看、文本收发、附件上传／扫描状态／授权下载、分页历史、断线恢复、未读数、送达／已读展示、本人设备列表与撤销。使用现有 API 提供的群管理动作。管理后台、保全及审计管理保留在现有 Web；产品整体其它未完成需求另有验收边界。

桌面使用会话列表与消息双栏，移动使用列表／会话分屏路由。后台通知打开指定会话须先复核身份及任职；通知默认仅显示“收到新消息”，不包含正文或不可见人员信息。

应用进程存活期间支持通知；移动系统挂起或应用被终止后，恢复前台必须补拉。APNs／FCM／私有推送网关作为独立配置适配与真机验收项，不能通过保持 WebSocket 声称已完成后台推送。

## 3. 三种状态

- 已发送：消息已在服务端事务提交，返回现有 ACK。保持当前语义。
- 已送达：接收用户至少一台当时有效的已登记设备，在连续补拉并接收消息后提交回执。服务器通知、HTTP 请求开始、发送端自身补拉均不算收件人送达。
- 已读：该用户在有效会话上下文中，将已经接收的可见消息展示给用户并提交阅读回执。多设备按用户合并；已读蕴含该消息已送达。
- 已读描述客户端提交的展示确认，不声称证明人实际阅读内容。附件卡片可标已读，文件下载／打开是独立行为。
- 状态只向前发展。设备后来撤销，阻止后续回执，保留此前合法确认事实；已撤销设备不能恢复为 active，重新登记产生新设备记录。
- 群消息统计排除发送者，按发送时有效的群成员区间确定接收用户集合，一人多个设备或多个任职只计一次。离群／再入群后不得用新阶段游标覆盖未授权区间。

## 4. 设备与登录

设备 ID 为服务端随机 UUID。登记需要当前已验证 OIDC 身份与有效任职，客户端不能提交用户或租户身份。登记返回一次性显示的随机设备凭据，数据库仅存摘要；后续请求同时携带有效 OIDC access token 和设备凭据，服务端检查所有者、有效期与撤销状态。

设备凭据是客户端安装实例的持有证明，不是硬件可信证明。持有被复制凭据的风险需通过撤销与操作系统安全存储控制；不以客户端提供的 `device_id` 直接授权。

推荐设备凭据有效期30天，续期需有效 JWT；集团配置范围1～90天。本人有效设备上限默认10、可配置1～100；超过上限拒绝新增并引导本人撤销，不能自动踢掉未知设备。Web 每个浏览器登录会话登记临时设备，凭据仅保存在页面内存，登出即撤销；刷新新建登录设备且定时过期清理，不能把共享浏览器的上一用户设备继续使用。

Native 登录使用系统浏览器、授权码与 PKCE S256；每个平台有独立的客户端 ID 与精确回调允许列表。桌面采用本机 loopback 回调，移动采用已登记应用回调；校验 state、nonce、issuer、client_id、回调与并发登录代次。无内置 client secret。不复用限定 `/web/` 的 Web 令牌兑换路由。

刷新令牌仅在 IdP 支持且配置允许时使用，存入操作系统安全存储；无刷新支持则到期重新登录。已有 JWT 在有效期内的 IdP 即时撤销仍由身份源集成另行实现；本增量不得扩大现有能力声明。

退出、账号切换及设备撤销时停止同步、取消在途请求、清空内存身份和密钥，并清除该用户本地缓存。服务地址变化不能复用原服务的设备凭据或登录回调。

## 5. 回执授权与分页证据

仅校验 `seq <= conversations.last_seq` 不足以授权回执：客户端可能跳过未拉取消息、群成员存在不可见区间、同一用户可切换任职、正文可能已到期。

设备补拉沿用既有分页授权，增加一个需要设备身份的专用同步接口。服务端在同一事务中完成当前及历史身份／策略／保留期检查、读取最终可见页面、保存短期同步凭证并审计。凭证绑定 tenant、user、device、acting membership、conversation、页起止 seq、可见消息 seq 及到期时间。

凭证为256 bit随机不透明值，数据库保存摘要；默认5分钟有效、最大覆盖500条，与现有分页上限一致。禁止返回可恢复明文凭据到日志或审计。断线造成凭证过期时重新补拉，不能依赖旧凭证推进状态。

客户端完整收到并校验连续序号后，Native 先提交本地事务，再提交送达；Web 在当前页面完整接收并接入其消息状态后提交送达，刷新仍重新补拉。序号缺口、解析失败、本地事务失败、取消、身份代次变化均不推进客户端游标或回执。

遮蔽占位用于推进同步扫描游标，不产生该消息的送达／已读事实。持久化维护扫描进度和实际可见消息的确认区间／集合；汇总时按消息匹配证据，不能仅将“最高 seq”解释为此前所有消息均已读。

阅读回执引用同步凭证或既有送达证据，明确提交本次可见消息 seq 集合，上限500；服务端验证是本人设备、该会话合法接收消息，并再次检查有效身份、历史区间、hard_deny和保留期。客户端只有会话激活、应用前台且消息实际进入可见区域才自动确认，不因列表预览、后台补拉、滚动尚未显示或服务器通知确认已读。

同一消息的回执以数据库约束及单调合并去重；并发／乱序／重试不回退状态、不重复统计、不重复产生状态事件。已读游标按用户持久化，但仍以实际消息证据区分不可见区间。重试旧请求若凭证已过期返回410并保持状态；客户端可读取现状或重新补拉，不新造阅读事实。

## 6. 数据与接口边界

新增迁移从 `000023` 起分阶段交付。具体字段与索引在首个回执设计定稿及实施计划中固定。

表的职责：

- `user_devices`：同租户用户设备、平台、凭据摘要、到期／撤销、最近有效使用时间。
- `device_delivery_cursors`：每个设备／会话／任职上下文的连续扫描进度与已确认高位。
- `conversation_user_read_cursors`：每个用户／会话已读高位，单调不回退。
- `message_receipt_ranges`：实际送达／已读覆盖的可见消息区间，按用户、设备、任职上下文归属，排除占位。高位不能代替覆盖证据。
- `device_sync_proofs`：短期同步证明、摘要、页范围及可见消息证据；消费与回执原子提交。
- `receipt_outbox_events`：回执状态改变的专用事务队列，避免修改现有消息 Outbox 的外键语义。

所有关联使用 tenant 复合外键，跨租户／跨用户凭据无效。回执写入、必要的最小审计和回执事件同事务，审计失败即回滚。凭证过期清理与撤销设备清理分离；过期临时证明可删除，合法历史回执受独立保留策略约束，不能随设备撤销删除。

建议 API（均需鉴权；登记、列表与撤销使用本人身份，消息动作另需任职上下文）：

| 方法与路径 | 行为 |
| --- | --- |
| POST `/api/v1/devices` | 登记本人设备，返回凭据一次 |
| GET `/api/v1/devices` | 有界分页列出本人设备，不含凭据摘要 |
| DELETE `/api/v1/devices/{id}` | 幂等撤销本人设备 |
| POST `/api/v1/devices/{id}/renew` | 有效身份与设备凭据续期 |
| GET `/api/v1/conversations/{id}/sync` | 单聊／群统一设备同步，分页＋短期证明 |
| PUT `/api/v1/conversations/{id}/delivered` | 用证明确认连续接收页 |
| PUT `/api/v1/conversations/{id}/read` | 确认本次显示的合法消息集合，更新用户已读 |
| GET `/api/v1/conversations/{id}/receipts` | 对本人发送的有界消息批次查询状态 |
| GET `/api/v1/conversations/{id}/receipts/{seq}/users` | 授权后查询群回执用户明细，有界分页 |

回执明细限制默认100、最大100，与会话／群成员及目录可见性联合校验；不向发送人暴露接收者设备名称、平台或 IP。失效身份403、不可查询会话／消息404、非法字段400、过期证明410、超量429、数据库／审计不可用503。均沿用项目现有错误封装，不回显凭据。

群回执聚合若涉及当前操作者不可知的成员集合，不返回能泄露成员存在的完整统计；允许查询范围及隐藏状态必须在首个细化设计中确定并测试。未读数只统计本人可见、未过期、非本人发送且尚未确认已读的消息，按当前授权实时核对，不能使用 `last_seq-read_seq` 简单计算。

## 7. 通知与恢复

回执事务提交后专用 Worker 投递既有 Redis 流及 `sync_required` 信号，敏感详情通过授权 HTTP 查询。订阅模块扩展接受回执事件但不向 WS 暴露用户／设备／正文；消息事件原合同不变。

同一设备重连：先验证设备和JWT，取得合法扫描起点，分页补拉并提交回执，再读取用户已读状态。另一设备合法确认的已读事实会合并，不影响本设备送达事实。

客户端中途退出或网络超时：复用原 client_msg_id 重试发送，复用合法同步证明重试回执；过期则重新补拉。Redis／WS漏通知通过既有兜底轮询和恢复前台补拉收敛。

单组织任职结束、集团离职、群成员区间变化、hard_deny、设备撤销均在 API 实时拒绝非法操作；保持此前合法事实，当前界面查询遵守当前可见性。不能以任职切换绕过原消息授权。

## 8. 客户端本地数据

Native 使用按服务／tenant／user隔离的本地事务存储，数据库密钥由操作系统安全存储保护。SDK／插件版本须在批准方案后核对四个平台支持情况，精确锁定并通过干净环境构建，不在本提案中猜测可用版本。

本地记录待确认发送、client_msg_id、同步进度与授权消息，禁止保存 Bearer 到普通文件或调试日志。Pending 发送不得因应用重启重造消息 ID；超出既有UUIDv7时间范围明确失败，允许用户再次发送时生成新ID。身份失效后不能继续发送队列。

响应包含服务端时间和内容有效期，客户端到期清除正文／附件缓存；恢复前台及重连重新授权。离线期间无法及时接收策略撤销，本期缓存阅读必须具有短期授权期限，到期锁定并联网验证；不得承诺离线期间即时撤销。具体离线授权期限和本地保留策略在客户端细化设计中评审后固定。

## 10. 首个回执增量的关键验收场景

1. Alice发送后仅已发送，Bob在线通知或API读取但未确认时仍未送达。
2. Bob设备B1完整接收确认后送达；B2再次确认只计Bob一人。
3. B1后台接收不已读；Bob前台显示后已读，B2同步状态一致。
4. 重复、乱序、并发回执单调；相同事件不重复排队，事务失败不留下部分状态。
5. 跳过一页、只有seq2没有seq1、伪造证明、借用另一会话／租户／用户／设备证明均拒绝。
6. 群成员退群再加入：不可见期间的占位推进扫描，但不计这些消息的送达／已读。
7. 任职结束、账号冻结、hard_deny、保留期到期与回执提交并发，验证实际提交边界。
8. 撤销设备后旧JWT＋旧设备凭据不能确认；合法历史状态保留，新设备重新补拉。
9. 附件卡片阅读与附件字节下载互不冒充；内容清理后查询不恢复正文或敏感明细。
10. Native本地事务失败、页面解析失败、切换账号时晚到响应均不推进确认。
11. 多设备同时刷新、回执Worker宕机／重试、Redis漏通知，最终通过授权查询收敛。
12. 群去重、发送时成员基数、隐藏成员与回执明细权限、未读数均有真实数据库案例。
