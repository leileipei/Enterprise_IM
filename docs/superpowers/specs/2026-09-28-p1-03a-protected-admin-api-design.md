# P1-03a 受保护管理 API 设计

## 目标

将现有人员查询与单组织离职领域服务接入 HTTP，但只接受认证适配器验证后的租户和用户身份。首个外部身份源尚待确定，因此本阶段定义可替换认证接口，不启用生产管理路由。

## 身份与请求

认证适配器从严格的 Bearer 令牌中返回 `tenant_id`、`user_id`；请求不能自报这两个字段。管理员通过 `X-Acting-Membership-ID` 显式选择本次任职；领域服务重新校验其归属、有效状态和授权。目标用户 ID 与目标任职 ID 只来自路径，均要求规范 UUID。不得接受请求传入角色、组织范围或操作时间。

## 路由与响应

- `GET /api/v1/admin/users/{id}`：调用 `GetManagedPerson`，返回已获授权的任职与部门，使用稳定的 snake_case JSON 字段。
- `POST /api/v1/admin/memberships/{id}:end`：调用 `EndMembership`，成功返回 204，无请求体。

缺少或无效令牌返回 401；缺少或无效的选定任职返回 400；领域身份失效返回 403；无授权范围、跨租户或不存在返回 404；状态冲突返回 409；审计或数据库故障返回 503。错误响应只有固定错误码和简短描述，不回传底层错误详情。未经验证的请求由 HTTP 入口记录，进入领域服务的授权结果由其现有审计事务记录。

所有 `/api/v1/admin` 路径先认证，再分发方法与路径；格式错误、未知路径、错误方法及非空请求体在入口写拒绝日志并返回统一 JSON 错误。日志不包含令牌或人员详情。

## 启用边界

新的受保护路由构造器要求认证适配器与领域服务都存在，否则直接报错。`cmd/im-api` 在真实身份源及用户映射接入前继续只暴露健康检查，防止上线时出现伪认证或绕过验证的管理入口。

## 验证

HTTP 测试覆盖路由未启用、缺失及无效令牌、认证身份传递、选定任职校验、字段过滤、单组织离职、错误映射和错误信息不泄露。现有 PostgreSQL 集成测试负责授权范围与审计事务；后续身份源确定后补充令牌校验和从登录到管理操作的端到端测试。
