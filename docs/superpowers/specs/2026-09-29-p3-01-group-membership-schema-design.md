# P3-01 群会话与成员区间数据基础

## 目标和边界

依照 v2.2 第 8.1、8.2 章建立群聊持久化边界。此增量只交付数据库迁移与约束，为后续建群、邀请、退群、群消息和历史补拉提供可信结构；不开放群聊 API，也不把现有单聊消息接口扩展到群聊。既有单聊、消息与收件列表行为保持不变。

## 模型选择

`conversations` 已承载会话 ID、状态和连续 `last_seq`。继续共用它，并以 `kind` 区分 `direct` 与 `group`；用互斥检查约束要求单聊只填写双方用户/任职字段，群聊只填写群名、创建人任职、创建组织和创建法人快照。复合外键将创建人、任职、组织、法人绑定在同一租户；触发器冻结会话类型和群创建来源。这样一行会话不能同时冒充两种类型。群成员历史单独存入 `conversation_membership_intervals`，避免用当前成员覆盖过去的授权证据。相比再建一套群会话主表，共用现有会话序号与消息外键更直接；群专属属性以后可按需要扩展。

每条群成员区间保存租户、群会话、集团用户、加入时的组织任职、组织/法人快照、角色、`join_seq`、可空的 `leave_seq`、加入策略版本及起止时间。消息序号 `s` 属于该区间，当且仅当 `join_seq <= s` 且 `leave_seq` 为空或 `s <= leave_seq`。加入时应写 `last_seq+1`；退出时应写 `last_seq`。因此尚无消息就退出时允许 `join_seq=1, leave_seq=0` 的空区间，重新加入会新增一行。

数据库保证成员关系属于同租户的群会话与真实用户任职，组织/法人快照与该任职一致；拒绝负数或倒置区间、无效状态和角色、同一用户重叠的历史区间、重复的当前有效成员以及多个当前群主。`leave_seq` 与退出时间、状态必须一致。已关闭区间不可更新或删除，活跃区间的来源、加入序号和策略版本也不能改写，只允许关闭或调整活跃角色。现有 `btree_gist` 扩展支持区间排斥约束。群创建与成员变更的事务将负责核对 `last_seq`、至少一名群主、人数上限和逐对策略；本增量没有写入入口，不将这些应用层约束误称为已完成。

## 迁移与兼容

新增 `000009_group_membership` Up/Down。Up 保留原单聊唯一索引和现有消息外键，增加群字段、互斥约束、群成员区间表与访问索引。Down 在存在群会话时拒绝执行，避免静默删除群历史；确认没有群数据后恢复原单聊约束。测试辅助迁移到最新结构，并覆盖 Up/Down 与旧单聊写入、补拉的兼容性。

## 验收

PostgreSQL 集成测试证明：合法的初始区间、退群空区间和再入群可保存；错租户、错创建人任职、错用户任职、错组织/法人快照、重叠区间、重复活跃成员与第二位活跃群主被数据库拒绝；旧区间无法重开、延长或删除；单聊行仍有效且混合字段被拒绝；含群数据的 Down 无损拒绝。全量 Go 测试、并发检测和构建通过。真实建群、邀请、策略变更后的 `policy_blocked` 与群历史正文验收留给后续增量。
