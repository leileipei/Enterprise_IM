## 1. 目标与已确认范围

集团员工能够在现有 Web 单聊／群聊中完成选择文件、上传、查看扫描状态、发送附件消息和请求受控下载，并在单会话与个人跨会话范围内按文件名查找附件。集团管理员可以编辑租户上传限制和文件保留策略，查看变更历史。

用户确认采用完整范围 A，保持当前文本搜索合约，生产启用另行验收。继续沿用当前助手逐项实现的执行方式。成功标准是实际浏览器与真实后端完成上述流程，并证明失效任职、撤权、扫描拒绝、到期、物理清理和跨上下文响应均不能暴露文件或形成重复消息。

本轮不做附件正文索引、OCR、Office 解析、在线预览、Range、断点续传、批量上传、跨会话复用、独立文件分享、外链或预签名 URL。不扩大为生产启用、客户集成、HA、容量、备份／DR 或 M4 总体验收。

## 3. 模块划分与能力声明

采用现有原生 JS 与 Go 模块，避免在 app.js 继续堆积整个附件状态机。

- `file-transfer.js`：预约、二进制上传、本人状态轮询及冻结的上传上下文。
- `file-messages.js`：附件发送草稿与幂等重试、类型化卡片与下载操作。
- `file-search.js`：单会话和跨会话名称搜索、分页、结果卡片及上下文失效。
- `file-policy.js`：上传／保留设置及分页历史，复用现有管理页面交互。
- `app.js`：提供当前身份、会话、能力声明与取消通知，完成消息合并和现有文本发送协调。
- Go HTTP 层：能力声明与独立名称搜索合约；存储层：有界候选读取、统一文件可见性证据与最终复核。

新增已认证的 `GET /api/v1/file-capabilities`，严格拒绝查询参数、请求体和其他方法；使用现有 Bearer＋任职头，并验证当前任职有效。返回四个布尔字段：`upload_enabled`、`message_send_enabled`、`download_enabled`、`filename_search_enabled`，无对象定位或管理员权限明细，no-store／nosniff。

能力由实际服务器装配决定，租户上传策略是否允许上传仍需读取 `/api/v1/file-upload-policy`；前端不能通过环境变量、URL、localStorage 或静态配置自行启用。生产装配的后三项始终 false，上传项沿用现有开关。测试专用装配显式注入完整服务与能力，不为 cmd/im-api 新增生产发送／下载开关。能力响应不是逐文件授权；每个实际请求继续独立认证和授权。新增 /files/search 和 /file-capabilities 的专用匹配须先于通用 /files/{id} 元数据路由，避免把 search 当文件 ID；闭合装配亦使用准确路径匹配。

页面在登录／任职切换时重新读取能力；失败按不可用处理。上传控件仅在上传、发送和下载三个能力均为 true、租户上传允许且会话当前可发送时开放，避免上传后无法分享。测试装配验证完整流程，生产默认状态显示已有文字消息和附件占位。管理配置页面使用现有服务权限，不受员工分享控件是否开放影响。

## 4. 上传与扫描交互

### 4.1 选择与预约

一次选择一个文件，每个页面最多一个上传／待发送附件草稿；另有未结算文字消息时先处理该文字草稿。绑定 `{identityEpoch, actingMembership, conversationEpoch, conversationID, kind}`；任何成员切换不能将草稿迁移到新会话或新任职。

客户端预校验大小、文件名和租户允许类型。名称按 UTF-8 字节数 1～255 校验，拒绝控制字符、路径分隔符、冒号、首尾空白及 `.`／`..`；不静默重命名。大小 1～租户限制且不超过 26,214,400 字节。声明 MIME 从允许的四种类型映射：File.type 是已知规范类型则使用；为空时仅按 pdf/png/jpg/jpeg/txt 扩展名映射；未知类型拒绝。该映射只形成声明，实测内容与可信扫描仍由服务器判定。

生成一次 `upload_request_id`，冻结名称、声明类型、大小和来源，调用既有 `POST /api/v1/conversations/{id}/files`；群聊也使用这个预约路由。请求超时或响应丢失时，用户可用同一 ID 与同一冻结参数重试预约，不生成新 ID 猜测未成功。

### 4.2 二进制上传与恢复

使用 `PUT /api/v1/files/{id}/content`，请求体为原 File、Content-Type 为 application/octet-stream，不用 multipart，不读取 Base64，不往 URL 写认证信息。先显示“上传中”，成功响应仅意味着服务端封存，不能显示扫描通过或消息已保存。不展示虚构百分比进度。

上传响应未知时停止自动 PUT，查询本人状态：uploaded／scanning／ready 表示服务器已有内容；allocated 不能证明没有在途或恢复中的上传。界面提供“查询状态”和用户明确触发的“重试原文件”，后者只使用原 File／file ID，继续接受服务端 upload_in_progress、upload_recovery_pending、file_already_uploaded 和 upload_expired 等结论；绝不盲目创建第二文件或自动重传。

状态轮询只有一条在途请求，间隔 2 秒，单次 10 秒超时，每次开始／继续最多 120 秒；到达时间上限显示“仍在处理，可查询”，不把等待超时当成扫描失败。隐藏页面暂停新增轮询，恢复可见后重新查询。用户重新查询开启新的有界等待窗口。HTTP／网络错误停止本窗口，不紧密重试。

| 服务端状态 | 页面行为 |
| --- | --- |
| allocated | 待上传／结果待核实，不可发送 |
| uploaded、scanning | 扫描处理中，不可发送 |
| ready | 可编辑说明并点击发送；服务器最后复核 |
| rejected | 安全检查未通过，禁止发送，重新选择生成新草稿 |
| scan_failed | 检查未完成，禁止发送，允许查询；不提供伪造的扫描重试按钮 |
| delete_pending、deleted | 附件不可用，禁止发送 |
| 404／410 | 显示不可用或预约已过期，不继续轮询 |

取消／退出／切换上下文会 abort 本地请求、停止轮询并释放 File 引用，不声称删除已封存的服务器文件。未绑定文件由既有到期清理流程处理。刷新不恢复 File 内容、令牌或未确认发送；不新增恢复列表／本地持久化。

## 5. 发送、卡片与受控下载

### 5.1 发送幂等

发送使用现有单聊／群聊 messages 路由，显式 `message_type=file`、file_id、caption 和一次生成的 UUIDv7 client_msg_id；其校验长度、归一化与重试窗口沿用 P4-23，不另造消息协议。

首次点击时冻结整个请求。发送中禁止重复点击和修改说明。网络或 5xx 结果未知时保留冻结请求，仅允许用同一 client_msg_id／file_id／caption 重试；服务器 ACK 或重复 ACK 才显示“已保存”。不通过产生新 ID 或新附件来规避幂等冲突。明确拒绝提示服务端原因；若之前存在未知结果，继续保留原请求供核对，不允许直接编辑后重发。超过既有重试窗口先核对历史，重新选择操作不得暗示原消息没有保存。

切换上下文清除页面敏感草稿，原请求可能已在服务器完成，页面不能自动重发到新上下文。刷新后通过消息补拉核对；不承诺跨刷新草稿恢复。附件与文字共享单个待发送槽，避免两条未结算消息的序列／按钮状态混淆。

### 5.2 类型化卡片

能力完整的 Web 使用现有 `message_format=typed_v1` 补拉。继续支持原有文字和旧格式附件占位，既有 seq、去重、分页／实时提示合并逻辑保留。redacted 消息先遮蔽，不读取或渲染其附件字段。

卡片只用 textContent 显示服务器返回的名称、实测大小、已检测类型与说明；拒绝 HTML 或对象路径。缺失、错误类型、异常大小／ID 或不完整附件结构按不可用处理，不把错误 DTO 当成文本渲染。

本轮 `typed_v1.download_available` 继续保持 false；该字段尚未建立生产启用合约，Web 不将其解释为当次下载许可。测试装配中仅在全局 download_enabled 与卡片 available 同为 true 时显示“请求下载”，点击后的真实 GET 决定是否有权获得内容。既有卡片元数据的历史可见性不自动升级为下载授权；文件名搜索使用第 6 节更严格的可见性。

### 5.3 浏览器下载

增加二进制请求函数，捕获原 token／任职／身份和会话 epoch，使用同源 fetch＋Authorization／X-Acting-Membership-ID；credentials=omit、cache=no-store、redirect=error。设置 65 秒客户端总时限，服务端继续执行不超过 60 秒的限制。不使用可直接导航的服务器 URL，不在下载链接中携带 token。

仅接收完整 200 响应，校验 attachment Content-Disposition、application/octet-stream、no-store、nosniff 和 Content-Length（1～25 MiB）；拒绝 Location、异常 Content-Encoding、错误 MIME、无长度及重定向。下载 reader 逐块累计，不能超过声明大小和全局上限；中断、长度不足或超长均销毁内容，不创建保存入口。使用经过校验的服务器文件名，不用 JSON 错误体作文件；Content-Disposition 解析不接受路径、控制字符或不完整编码。

每页最多一条下载；完整读取及身份／会话再次确认后生成短时 Blob URL，显示明确的“保存文件”操作供用户点击。成功点击后立即移除链接并释放 URL；未点击最多保留 60 秒，到期或切换／退出时销毁。页面不持久化字节，不自动预览，服务器完成日志不宣称文件已落盘。已保存的用户文件不能撤回；不能把后续撤权说成可以删除用户磁盘文件。

CSP 保持现有 default-src／script-src／style-src／connect-src 的限制；Blob URL 仅用于临时下载链接，不用于脚本、图片、iframe 或导航预览，不加入宽泛 blob: 来源。真实 Chrome 必须验证保存流程可用；若被策略阻止，停止并报告失败，不静默放宽 CSP。

## 6. 独立文件名搜索

### 6.1 HTTP 合约

新增三条 GET 路由，不改变 `/messages/search` 的文本返回结构；成功及错误响应均设 no-store／nosniff：

| 路由 | 范围 |
| --- | --- |
| /api/v1/conversations/{id}/files/search | 单聊 |
| /api/v1/groups/{id}/files/search | 群聊 |
| /api/v1/files/search | 个人跨会话，kind=all／direct／group |

q 必填，使用现有 NormalizeMessageSearchQuery：去首尾空白后 2～100 Unicode 字符，Go ToLower 后字面子串匹配，不做 Unicode 规范化／音译／正则；`%`、`_` 和正则符号只是文字。只匹配 original_filename，不匹配 caption、附件正文、对象 key 或任何审计副本。

limit 默认 20、范围 1～50，使用规范十进制；cursor 可选、非空时最长 2048 字节。跨会话可附 kind；单会话不接受 kind。重复／未知参数、无效 UUID、请求体、ForceQuery 和其他方法按严格合约拒绝。已认证的生产关闭装配统一返回 503 `file_search_unavailable`；不能因为手工构造 URL 绕过关闭能力。

返回 `{matches, has_more, next_cursor}`，每个 match 字段固定：conversation_id、conversation_kind、message_id、seq（十进制字符串）、sender_user_id、server_time、file_id、original_filename、actual_size_bytes（十进制字符串）、detected_media_type。无 caption、全文、URL、token、摘要或对象定位。无结果返回空数组，不返回隐藏结果数或 total_count。

无效输入 400 invalid_file_search；当前身份无效 403 invalid_identity；单会话不存在或无历史权限统一 404 not_found；依赖或审计故障 503 file_search_unavailable。跨会话无匹配是空页，不逐个揭示无权会话。

### 6.2 授权与到期

搜索仅遍历当前用户历史候选，不能以 tenant 全库名称 LIKE 得到候选或结果。仅已绑定消息的 ready 文件有资格；本人未发送上传不进入消息名称搜索。

名称输出的权限采用 P4-24 下载资格的完整证据：当前有效任职、所属 tenant／组织／法人／用户状态、匹配的原上传者及当前有效任职、单聊参与关系或群历史区间和当前有效参与关系、active 会话、双向 send_message 与 file_download 策略及 hard deny、消息／附件／封存来源一致性、正文仍可见且未到期、文件保留期未到且非 pending／deleted、完整可信扫描证据。管理员不能绕过这些规则，离群后的历史可见性不能替代当前文件访问资格。

允许复用／拆分 P4-24 授权的事实加载和纯判断函数，不用下载 Prepare／Authorize 服务来搜索，避免对象 GET、spool、并发槽、下载 session 或下载成功日志副作用。名称搜索资格不保证对象存储当次可读；下载仍独立执行完整准备及流中复核。

同一次返回在短事务内加载完整证据，沿用现有锁顺序及 NOWAIT／有界重试；保留指针、身份、会话和来源字段的保护锁至事务提交。所有事实加载结束后取数据库最终时间，再纯计算有效期、策略及来源条件；最终时间之后不再加载授权事实。审计插入／提交可以继续，但不能后读事实改变资格。后续变化于下一页／下一次请求重新判断；事务后至客户端收到响应的窗口不被描述为零。

### 6.3 分页与成本

单次最多扫描 500 条 file 消息候选；跨会话每次最多 20 个个人候选会话、总计 500 条，不按名称预先过滤。单会话按 seq 升序；跨会话沿用个人文本搜索的会话 UUID 升序、会话内 seq 升序，不伪装为全局最新时间排序。限定 file 消息类型并复用已有来源关联／复合键索引；不新增持久化名称全文副本。

游标独立版本／类型，绑定 tenant、user、actingMembership、规范 q、kind／会话和扫描进度，严格规范编码；文字和文件游标互不接受。跨会话复用现有候选边界与 within／after 进度语义。只记录处理过的时间线位置，不编码文件名、匹配数、私有对象信息。无匹配但还有候选时允许空页＋游标，界面显示“本页无结果，可继续”，不自动扫完整历史。

达到结果上限后推进到最后处理的候选；最终复核导致结果减少时允许不足页，但不能跳过未处理候选；不得在筛选已结束后额外推进到尚未处理的第 501 条或第 21 个会话。损坏关联按不可用且继续有界进度；数据库异常不当成无结果。每次服务总时限 5 秒，statement_timeout 4 秒、lock_timeout 1 秒；仅并发类错误在总时限内至多重试 2 次，任何页面不返回部分未提交结果。

最小审计 action：file_name_search／file_name_search_all，记录人员／任职、会话或 tenant 引用、allow／deny 与闭集原因 completed／invalid_identity／not_available。成功审计提交后返回名称；审计失败不放行。日志和审计不保存 q、名称、caption、原始游标或结果内容；验证网络代理访问日志同样不记录查询字符串。非法输入不以其原文进入错误输出。

### 6.4 页面行为

现有单会话和跨会话搜索面板增加“文字／文件名”切换，文字模式使用原接口与原 JS 合约。文件模式由独立 file-search.js 管理，切换模式清空结果和游标并取消旧请求；结果卡片包含会话类别、消息序号、文件名／大小／类型，不展示附件说明。

每次查询由用户触发，分页手动加载，每次 15 秒客户端超时。响应校验 schema、身份／会话 epoch、查询和模式，再追加去重结果；游标重复／倒退、类别错误或超过 limit 判为协议错误并停止。跨会话结果可点击“打开会话”，仍复用现有会话授权和补拉；不能依靠搜索结果绕过群当前状态校验。下载使用第 5 节相同入口，切换会话会取消原上下文的在途下载。

## 7. 管理设置与变更历史

复用已存在的 `/api/v1/admin/file-upload-policy`、`/history` 和 `/api/v1/admin/file-retention-policy`、`/history`。服务端现有角色及 tenant scope 授权为准；普通员工只读现有有效上传策略，不授予配置写权限。

上传页面提供 enabled、max_size_bytes、allowed_media_types、upload_ttl_seconds、tenant_storage_budget_bytes；保留页面提供 file_retention_days 和 cleanup_enabled。类型仅四种且至少一种；上传 TTL 60～3600 秒、存储预算 25 MiB～1 TiB、大小 1～25 MiB、保留 1～3650 天。数值按 API 十进制字符串提交，界面单位换算须为精确整数，不用浮点舍入静默改变额度。

每次保存附原 expected_version 与非空 approval_reference，先展示拟变更值再提交。CAS 冲突不自动合并／覆盖，重新读取后让管理员审阅；结果未知先重读当前版本及历史，不自动补发写请求。历史手动分页、校验游标，显示操作者、任职、版本、批准引用和时间；响应不能混入新身份页面。

保留期页面明确当前策略适用于已有文件；延长不能恢复 delete_pending／deleted。cleanup_enabled 是租户清理资格，不能启动默认关闭的清理命令。法务保全仍通过既有会话设置；清理承诺未结算时保全创建冲突按 P4-24 处理，本轮不增加绕过功能。员工界面“已取消上传”不等于服务器对象已删除。

## 8. 安全、兼容与失败处理

- token、File、Blob、名称搜索结果只在页面内存中；不新增 localStorage／IndexedDB／Service Worker 离线缓存，不写日志或埋点内容。
- 在途请求统一登记 AbortController。任职／身份／会话切换、退出、失效任职或令牌过期，先取消再清 UI；迟到响应禁止恢复按钮、草稿、卡片、结果或保存入口。
- 401 沿用退出登录，403 invalid_identity 沿用任职清除；404 不区分文件存在但无权和不存在；429 不自动无限重试；503 显示服务不可用并保留明确的核对／原请求重试路径。
- WebSocket／Redis／Outbox 继续只传消息引用和补拉提示，无新增文件名称、URL、说明或下载令牌。
- text 搜索字段、游标与过滤保持；旧客户端无需升级即可看到已有占位。
- P4-24 下载复核 DB 故障审计分类 Minor 不在本轮扩大修复范围；若统一资格判断拆分改变该路径，则须保留已有行为并用原下载门禁证明无回归。
- 生产默认关闭接口仍须有测试；UI 隐藏不是服务端授权机制。

## 9. 验收要求

所有新增关键浏览器流程必须对接真实 Go 服务、PostgreSQL、私有版本化 S3 和实际扫描 Worker；mock／静态页面检查仅算辅助证据。使用专用测试装配、测试 tenant、OIDC 和带计划标记的资源，不改真实客户数据。以下门禁在实施计划冻结具名测试及脚本。

| 门禁 | 必须证明 |
| --- | --- |
| 上传 happy path | 四种允许类型；真实 Chrome 预约→PUT→扫描→ready，客户端声明不替代检测 |
| 发送 | 单聊／群聊附件 ACK 与实时补拉；原内容重试仅一个绑定、消息、seq／Outbox；说明冻结 |
| 恶意及失败文件 | EICAR、损坏／加密 PDF、类型伪装、超限、scan_failed 不可发送 |
| 预约／上传未知 | 预约重放、PUT 丢失响应、in progress／recovery pending、预约到期，无自动重复文件 |
| 下载 | 完整浏览器保存字节与源一致、中文名、60 秒服务边界；断流／长度不足／超长不产生 Blob 保存入口 |
| 下载撤权 | 权限／任职／策略／TTL 在途失效，停止流；服务端结果与实测输出对应，不声称已输出字节可撤回 |
| 名称搜索 | 单聊、群聊、跨会话；字面大小写、中文、Unicode、通配符；caption／正文不匹配；文本合约不变 |
| 搜索泄露防护 | 隔离 tenant／来源、离群／重新加入区间、上传者失效、hard deny、到期、pending／deleted、损坏 seal 均无名称 |
| 搜索并发／分页 | 在最终复核前改变权限／保留期／成员；500／20 上限、空页游标、跨模式游标拒绝、无遗漏／重复 |
| 管理设置 | 权限隔离、CAS 冲突与未知写结果、精确额度、批准引用、历史翻页；清理开关不启动命令 |
| 浏览器上下文 | 上传、扫描、发送、搜索、下载／Blob 等各阶段切换任职／会话、退出、刷新和令牌失效；旧响应零回填 |
| 默认关闭 | cmd/im-api 手工调用发送／下载／名称搜索仍关闭；能力后三项 false；旧文本与占位正常 |
| 隐私与兼容 | 原旧浏览器、消息幂等／补拉／搜索／retention 门禁；无名称、令牌、URL 或说明进入日志／存储 |

运行 Go 全仓测试、受影响授权／搜索／HTTP／下载包 race、原文件上传扫描／消息／下载保留脚本和新增 P4-25 浏览器脚本；固定产品 commit 归档执行，记录 PASS／FAIL／SKIP。新必选场景不得通过 SKIP 伪称验收。性能只报告实测扫描量／耗时，不替代生产容量结果。交付保留独立草稿 PR、中文验收记录、私有无凭据证据及仅本计划资源清理。
