# P1-02b 通信策略版本与决策审计

## 目标

把 P1-01 的纯函数通信判定接到 PostgreSQL 中可发布的租户策略快照。发布者必须是当前有效的集团管理员任职；每次判定读取一个完整已发布版本，并记录版本、动作、结果及命中/覆盖规则。依据 v2.2 第 5、6、11、12 章；本阶段不开放未经认证的管理 HTTP API。

## 发布模型

`policy_versions` 记录租户内连续版本、发布人、原因和状态。`policy_rules` 保存每个版本的完整规则；`policy_current` 指向唯一当前版本。发布服务在一个数据库事务中锁定租户行、核验发布者任职和集团管理员授权、比较调用方提供的 `expected_version`，写入新版本和全部规则、标记发布、切换当前指针并写管理审计。并发发布只有一个可成功；另一个收到版本冲突，重新读取当前版本后再决定是否重试。版本 0 表示尚未发布任何策略，此时同组织按基础规则允许，跨组织默认拒绝。

已发布规则不可修改或删除；新策略通过新快照发布。规则 ID 在同一版本内唯一。`allow` 和 `exception_allow` 必须有申请人、审批人、原因及有限有效期；`exception_allow` 还须指定双方任职与本版本内被覆盖的隔离规则。所有组织、任职、申请人与审批人引用均受同租户外键约束。`hard_deny` 不受例外覆盖。策略输入仍按 P1-01 的已知操作枚举校验，未知操作不能发布。

## 判定与审计

内部服务接收经认证入口提供的租户、操作者 user ID、选定任职 ID、目标任职 ID、动作，以及已经由调用方验证的 Scope 与资源状态。服务从数据库重新读取两端账号、任职、组织和法人状态，不信任调用方传入的组织/法人/任职状态字段；读取当前版本规则后调用 `policy.Evaluate`。每次返回允许或拒绝前，在同一事务写入 `policy_decision_events`，包含版本、原因和命中/覆盖 ID；审计失败时不返回允许。跨租户或不存在的目标只得到拒绝结果，不泄露目标详情。版本不可用、规则读取失败或数据库不可用时默认拒绝并返回服务错误。

## 验收边界

PostgreSQL 16 集成测试覆盖：发布权限、跨租户引用、例外审批与覆盖关系、版本冲突、已发布不可变；同组织默认、跨组织允许/拒绝、hard_deny 优先、例外到期和判定审计。继续保留 P1-01/P1-02a 回归。本阶段没有 SSO、公共管理 API、缓存广播和跨节点撤权时延实测；后续接入 HTTP 前须验证认证来源与 Scope 计算。
