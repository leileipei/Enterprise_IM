# P1-04a 普通员工通讯录任职详情设计

## 目标与范围

集团员工用已验证的 OIDC 访问令牌和显式选定的本人任职，查看一个目标任职的通讯录详情。此增量只做按任职 ID 的详情读取，作为后续组织浏览和可见人员搜索的策略基线；管理员检索仍沿用独立的管理授权。

## 接口与身份

`GET /api/v1/directory/memberships/{id}` 要求 `Authorization: Bearer <access-token>` 与 `X-Acting-Membership-ID: <uuid>`。外部令牌只确定本地租户和用户，服务端再核验选定任职确实属于该用户且当前有效。目标 ID 来自路径，均须为 UUID。成功返回目标用户 ID、姓名、集团工号，以及该任职的组织、职位、主任职标志和当前有效部门；不返回目标用户在其他组织的任职。

## 授权与数据一致性

同一数据库事务中，按固定顺序锁定本人和目标任职，读取当前策略版本与规则，对 `directory_view` 调用现有 `policy.Evaluate`，读取允许的目标详情，并写入 `policy_decision_events` 后提交。跨租户、失效目标、组织隔离和 `hard_deny` 均返回 404，不泄露人员详情；本人任职失效返回 403。审计或数据库故障返回 503，不返回未经审计的数据。默认同组织可见，跨组织只有已发布的对应规则或有效例外可见。请求字段不得声明 Scope、资源状态、策略版本或目标用户身份。

## 验证与边界

PostgreSQL 集成测试覆盖同组织、跨组织默认拒绝、发布放行、强制拒绝、跨租户、失效身份、部门过滤和审计失败。HTTP 测试覆盖鉴权、路径与方法、错误映射和稳定响应。此增量不提供普通通讯录列表、搜索、发起会话或实际客户 IdP 联调。
