# P2-07 浏览器身份上下文设计

## 目标

浏览器完成集团 SSO 后，需要知道当前账号在集团内有哪些有效任职，才能要求用户选择 `X-Acting-Membership-ID` 并调用通讯录、会话和消息接口。新增 `GET /api/v1/me`，仅凭已验证的 Bearer 访问令牌读取本人身份；不接受请求方提供的租户、用户或任职 ID。

## 接口

请求不带查询、正文或 `X-Acting-Membership-ID`。成功响应为 `tenant_id`、`user_id`、`display_name`、`global_employee_no` 和 `memberships` 数组。每项包含任职 ID、组织 ID 与名称、法人 ID 与名称、职位和主任职标志，按主任职优先、组织名、任职 ID 排序。只返回账号、租户、组织及法人当前有效，且任职状态为 active、处于有效期的记录；账号有效但暂无任职时返回空数组。响应设置 `Cache-Control: no-store`。

缺失或无效令牌返回 401，身份映射暂不可用返回 503；令牌映射后若租户或账号在查询前失效返回 403；数据库故障返回 503。请求参数或任职头不合规返回 400，其他方法返回 405。原有业务接口仍必须使用选定任职头和数据库复核；`/me` 的输出不能作为客户端授权依据。

## 一致性与边界

查询在单个数据库事务内锁住本人用户和租户行，并以同一时点过滤任职、组织与法人状态。只允许读取已验证令牌映射到的本人资料。当前审计表强制要求 acting membership，无法记录选择任职前的自助查询；本增量不伪造任职审计字段，后续统一设计登录审计时再增加无任职事件。本阶段不实现 OIDC 授权码浏览器登录或 Web 页面，客户身份源仍需联调。

## 验证

真实 PostgreSQL 测试覆盖多任职、过期和停用过滤、空任职、跨租户、冻结账号与数据库故障。HTTP 测试覆盖 Bearer-only、输入约束、错误码和不缓存。签名访问令牌到 `/me` 的集成链路须通过，完整测试、竞争检测、静态检查和构建须通过。
