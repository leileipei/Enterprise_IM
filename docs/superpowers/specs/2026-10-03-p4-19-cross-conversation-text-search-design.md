# P4-19 跨会话文本搜索设计

## 1. 目标与交付状态

员工在一个当前有效任职下，一次搜索本人可读取的单聊与群聊历史正文。结果必须服从现有历史授权、当前 hard_deny、正文保留期及物理清理状态；集团管理员身份不增加读取他人消息的权限。

基线为 P4-18 `33b3b8eebdc8f70afe51a6ebed1af8f6ba1c3170`、草稿 PR #65。本文是待用户审阅的设计，尚未实现新 API、迁移或页面；现有 P4-17/P4-18 代码保持其已交付合约。后续先交付 API 与真实数据库验证，再交付 Web 跨会话入口。

用户授权继续推进跨会话文本搜索的授权范围与有界查询设计。下文的页预算、排序、新路由及事务组织为本次推荐设计；审阅通过后进入实施计划。附件索引、外部搜索服务、按相关度排序、拼音／模糊查询、总命中数、自动跳转定位、客户身份源和生产容量验收不在此切片内。

## 2. 已核对的源码事实

| 已有行为 | 源码 | 对本次设计的影响 |
| --- | --- | --- |
| 单聊列表只列当前选中任职、active 会话 | `internal/policystore/conversation_list.go` | 不能直接当作全部历史候选 |
| 群列表只列当前 active 成员区间及 active／policy_blocked 群 | `internal/policystore/group_list.go` | 不能覆盖已退群但仍可读的历史 |
| 单聊历史按用户参与关系及发送时双方任职／组织快照判定 | `internal/policystore/message_pull.go` | 当前任职是查询身份，不能代替消息历史任职 |
| 群历史允许曾入群用户进入，逐消息检查双方区间及发送者任职 | `internal/policystore/group_history.go` | 候选须含历史区间，退群不等于历史全部不可读 |
| 单会话搜索在历史读取后匹配，每页最多检查 500 条 | `internal/policystore/message_search.go` | 复用字面匹配与历史过滤，跨会话须用合计预算 |
| 消息已有 `(tenant_id,conversation_id,seq)` 唯一索引；群区间已有 `(tenant_id,user_id,conversation_id)` 索引 | 迁移 `000006`、`000009` | 可按会话／序号续查；单聊参与人枚举需要补索引 |

历史读取没有以当前会话状态作为拒绝历史的统一条件，因此候选枚举不擅自剔除 ended／policy_blocked。是否能返回某条正文始终由同一历史授权逻辑决定。法务保全只暂停清理，不延长普通用户可见期。

## 3. 方案比较与选择

| 方案 | 收益 | 代价与限制 |
| --- | --- | --- |
| **推荐：服务端 PostgreSQL 候选枚举＋历史授权＋有界扫描** | 统一身份、预算、审计和分页；沿用现有策略；不用新增消息索引副本 | 按会话与序号排序；稀疏命中需要多次续查；须整理事务内读取接口 |
| Web 枚举现有会话列表，逐会话调用 P4-17 | 单个搜索接口可复用 | 列表遗漏旧任职和退群历史；大量请求；预算与审计分散，无法形成一致页面失败语义 |
| 新增外部全文搜索／索引投影 | 可扩展相关度和大规模索引 | 正文副本、清理传播、授权重检及索引延迟需要新设计，当前容量证据不足 |

首版采用推荐方案。500 条扫描是消息行工作量限制，不是生产时延保证；历史区间数量、锁等待与数据库执行成本另受超时控制及专项测量。

## 4. 查询范围与授权不变量

认证提供 tenant、user，`X-Acting-Membership-ID` 提供当前任职。拒绝来自参数的租户、用户、任职和任意会话 ID 列表。

- 单聊候选：同租户、kind=direct、调用用户为 low／high 参与人。不限当前会话绑定任职；最终使用现有历史发送快照验证正文。
- 群候选：同租户、kind=group、调用用户至少有一个历史成员区间。区间 active／left 都可作为候选，多个区间只枚举一次会话。
- 当前用户、任职、组织／法人和租户必须有效；候选资格不授予正文权限。群消息仍只在读者及发送者有效区间重合处可见，退群空档、无法证明身份快照、发送者任职不匹配全部不返回。
- 逐条应用现有 hard_deny、保留期限、body_cleared_at 与正文缺失规则，之后才进行关键词匹配。不得先按隐藏正文关键词筛选候选或进度。
- 返回前在本页同一最终校验时间再次校验当前身份及全部待返回正文；锁等待之后重新取时间。若身份失效，整页拒绝。正文到期或 hard_deny 遮蔽时移除正文，游标仍按已处理时间线前进。
- 不返回候选会话名称、对端姓名、组织、群成员或不可见正文占位。结果仅携带已授权消息的会话 ID 和类型；未来名称补充须单独经过通讯录／群元数据授权。

这保持与现有单会话历史读取的权限含义一致。当前任职始终参与 hard_deny，不会把不同任职的授权并集作为一次搜索身份。

## 5. 新 API 合约

`GET /api/v1/messages/search?q=关键词&kind=all&limit=20&cursor=...`

| 参数 | 规则 |
| --- | --- |
| q | 必填；复用 P4-17 NormalizeMessageSearchQuery：有效 UTF-8、无 NUL、Go TrimSpace 后 2～100 个码点，Go 简单小写的字面子串匹配 |
| kind | 可省略，默认 all；仅 all／direct／group，小写且不允许空值 |
| limit | 可省略，默认 20；规范十进制 1～50，不接受符号或非整数 |
| cursor | 首页省略；提供时非空、规范 Base64URL、最多 2048 字节 |

拒绝重复／未知参数、非法 URL 编码、GET 正文和显式空 cursor。正常响应 200、no-store；匹配数组始终为 `[]` 或数组。

```json
{
  "messages": [
    {
      "conversation_id": "00000000-0000-4000-8000-000000000001",
      "conversation_kind": "direct",
      "id": "00000000-0000-4000-8000-000000000002",
      "seq": "9007199254740993",
      "sender_user_id": "00000000-0000-4000-8000-000000000003",
      "text": "工单片段",
      "server_time": "2026-10-03T02:00:00Z"
    }
  ],
  "has_more": true,
  "next_cursor": "opaque-progress"
}
```

seq 保持十进制字符串。跨会话 seq 不作全局比较，结果按 PostgreSQL UUID 会话 ID 升序、会话内 seq 升序排列；接口文档与未来页面明确不是时间或相关度排序。不返回总数、扫描数量、隐藏命中或候选列表。

错误：400 invalid_search；401 未认证；403 invalid_identity；503 unavailable。不存在个人候选或无可见命中是 200 空页，不用 404 暗示其他用户会话是否存在。方法错误 405，并设置 Allow。请求拒绝日志不写原查询串、关键词或正文。

## 6. 游标与分页算法

游标为版本化规范 JSON 的 Base64URL：绑定 v=1、tenant、user、当前任职、规范化 q、kind，保存会话进度 ID、该会话内 after_seq 字符串及 `phase`（within 或 after）。within 表示下次从同一会话 after_seq 之后继续；after 表示该会话已处理完，下次只枚举更大的会话 ID。after_seq 为规范非负 int64 字符串，after 阶段固定为 `0`；首页不需要伪造最小 UUID。

更换身份、任职、关键词或 kind 必须从首页开始。limit 可以调整，因其仅决定结果页大小。游标不具备授权效力，也不承诺保密；篡改到更大进度只可能跳过本人结果，不能扩大候选集合或正文权限。严格检查版本、字段集合、类型、大小写、编码、phase 与进度一致性。within 的会话必须重新验证本人候选资格；资格消失时直接从大于该 ID 的候选继续，不查询该会话正文。跨页无共享快照，新会话插入或新消息到达可能位于已遍历区域，需从首页刷新；这不是持续完整快照搜索。

每页预算：最多 **20 个会话**，合计 **500 条时间线消息**，最多 limit 条授权匹配。

1. 在当前身份下按 ID 获取候选，最多 20 个及 1 个仅用于探测后续的候选。within 续查会话也计入 20。候选不携带正文或名称。
2. 在每个候选中按 seq 前进，历史读取只使用剩余合计消息预算；没有消息的候选仍消耗一个会话预算并进入 after 阶段。
3. 只对授权后的正文匹配。扫描或结果预算耗尽立即停止，不开始下一会话。最后交付的匹配之后未交付的消息不得被游标跳过。
4. 达到结果上限时，游标最多推进至最后已处理且已交付的匹配；后续不确定时可返回 has_more=true，再由下一页确认空末页。每个正常续查游标须严格前进。
5. 已扫描但遮蔽／不匹配的消息仍推进时间线进度；耗尽当前会话后用 after，尚未耗尽用 within。has_more 只表示仍需检查进度，不保证下一页有匹配。
6. 会话／消息后续探测只看关系与序号，不按正文命中决定扫描进度。消息 lookahead 最多每处理会话额外 1 行，因此读取行最多 500＋20；其中最多 500 条进入授权／匹配管道。合并后候选探测上限 21 个；三个来源各取最多 21 个 ID，因此 all 范围内候选 SQL 最多向服务传递 63 个 ID（群区间去重的底层扫描另计）。

空页可以有 cursor。全部候选遍历完成才返回 has_more=false、next_cursor=""。不在服务端自动递归扫到命中，避免稀疏关键词导致单请求无界工作。

## 7. 事务、失败与复用边界

单次页面使用一个显式 READ COMMITTED 事务。先验证并锁定当前身份关联行，固定本页策略与保留期，枚举候选并复核候选资格。按 UUID 升序取得会话共享锁，读取并保留历史授权证据；成员区间、发送时任职／组织、正文状态沿现有读取逻辑校验。所有相关锁保留至提交；会话批量最多 20 个。

将 `readTextMessages`／`readGroupTextMessages` 内部拆出可接收 pgx.Tx 的事务内历史读取与最终可见性校验助手。助手不自行 Begin、Commit 或写成功审计，不直接返回未经授权的正文给 HTTP。既有单会话补拉／搜索包装器仍负责其原审计、合约和提交；不能通过循环调用现有独立事务搜索拼接跨会话页面。

跨会话页面在最终时间点复核所有结果后，写一条 `audit_events`：action=`message_search_all`、resource_type=`tenant`、resource_id 为可信 tenant，outcome=allow、reason=`cross_conversation_search_page`。不写关键词、正文、游标或隐藏结果数。当前身份失效时记录同动作 deny／invalid_identity；审计不可用或提交失败返回 503，整页结果与游标不返回。参数错误在 HTTP 层拒绝，不虚构成功读取审计。

不逐候选提交成功审计，也不返回部分成功。候选关系在事务内消失时安全跳过，真实数据库错误则整页失败。锁排序必须与既有发送、成员管理、策略发布及清理路径一起核对；对 PostgreSQL 40P01／40001 最多重试整页两次，每次重新取时间与授权，超出或请求取消返回 503。已有单会话路径的错误合约不能被本次重构无意改变。

服务内部整页 deadline 5 秒，重试共享同一 deadline；statement_timeout=4 秒／lock_timeout=1 秒使用事务局部设置，不污染连接池。超时不返回部分结果或游标。扫描预算不能证明复杂群区间读取、sort／group、策略判定或等待都低于固定成本；实施阶段必须测量并保留这些限制。

## 8. 候选索引与数据变更

规划新增迁移：为 conversations 增加两个仅 kind=direct 的索引 `(tenant_id,direct_user_low_id,id)`、`(tenant_id,direct_user_high_id,id)`。单聊两个参与方向分别以索引 keyset 获取少量 ID，在服务内合并；同一用户不可能同时是同一会话双方。

群候选沿现有 `(tenant_id,user_id,conversation_id)` 区间索引按 ID keyset 去重枚举，回到同租户 conversations 检查 kind。合并三条有序候选流后最多取 21 个；不得查询整个租户会话后在内存筛用户。群区间去重的实际行数可能超过候选数量，超时与 EXPLAIN 测量需覆盖大量重复区间。

不新建正文副本、全文索引或搜索缓存，不改变消息、Outbox、ACK、清理和法务保全数据模型。索引迁移在隔离数据库验证 Up／Down；生产建索引窗口及体量需另行评估，不能把本地迁移通过当作生产无阻塞证明。

## 10. 验收矩阵

- 范围：当前与旧任职单聊；当前、已退、再入群；同用户双任职；集团管理员不能读无参与消息；不存在、跨租户、仅其他用户参与及伪造进度不能返回正文。
- 历史：退群空档、发送者任职不匹配、缺失组织快照、hard_deny、生效策略切换、过期／已清理正文、法务保全仍不延长可见期。
- 预算：超过 20 会话、超过 500 消息、空会话、大量隐藏／不匹配正文、多个历史区间、命中跨会话边界；确认预算合计、游标前进、无重复遗漏及空页续查。
- 合约：q Unicode NEL／FEFF／İ／sigma、字面百分号与下划线、严格 kind／参数／GET 体、规范游标及身份绑定、大 seq 保真、跨会话独立 seq、no-store。
- 并发：真实 PostgreSQL 两连接控制身份冻结／任职到期、保留期变化、成员移除、策略发布、清理与行锁等待；返回前旧结果重新过滤；READ COMMITTED 不受连接默认隔离级别影响。
- 原子性：中间会话读取失败、最终身份失效、审计写失败、提交失败、deadline、中断、死锁重试；都无部分正文／游标，成功页审计恰好一次。
- 集成：真实 OIDC 的双 API 跨节点续查，核对身份、同一规范化 q／kind、成功及拒绝审计；未认证与数据库不可用错误。最终跑完整 Go、必要 race、构建及静态检查。
- 查询测量：EXPLAIN ANALYZE 候选及消息 keyset，包含大量群区间和个人会话；记录本地数据量、扫描行数及时间，不声明已满足生产 SLA。
