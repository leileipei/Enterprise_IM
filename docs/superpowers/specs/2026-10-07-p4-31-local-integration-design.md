## 5. 专属资源和凭据边界

### 5.1 PostgreSQL

新建 PG16 容器，环回随机端口、独立临时数据，不连接已有业务实例。文件进程夹具使用其现有合同要求的数据库 `enterprise_im_files`；其他隔离验证可使用独立数据库/schema。实例启用测试 TLS，生成本轮 CA、错误 CA 和服务器证书，以供完整比较工具 TLS 用例；服务端健康和实际连接均须确认。

管理员连接只用于夹具建库、迁移、种合成数据、权限准备及故障注入。正式 API、repair 和导入产品路径使用各自普通角色。严格只读比较继续创建并实际验证无写权限的账号，不能拿 writer 账号代跑只读 profile。导入十四门禁保留独立 writer 与无外网只读夹具；旧批准清单 oracle 按原清单哈希运行，新迁移由对应当前门禁验证。

包间数据库/角色/扩展变更串行执行 `-p 1`，已有服务内多连接、多实例竞态不减弱。记录门禁边界的 schema/角色基线及残留；测试失败后的残留不能因最终销毁容器而冒充单个测试正确清理。

### 5.2 Redis

新建独立 Redis 容器、环回随机端口；本轮流、票据与测试键仅在此实例。测试清理只能针对本轮实例，不能清空共用 Redis。验证 PING 和实际 Stream/连接场景；健康检查不能替代双节点/重连用例。

### 5.3 对象存储与 IAM

新建锁定 MinIO 容器。准备主桶和策略反例桶，启用 versioning，初始与结束状态私有。为兼容已有 P4-26 校验，桶名采用 `p426-p431-<本轮随机标识>` 前缀并使用两个不同名称；本轮资源登记中的 stage/owner 明确为 P4-31。

上传、扫描、下载、精确版本清理分别使用四个不同 IAM 主体；另有本轮管理与引导主体。按已有合同配置只读/写入/版本枚举/精确版本删除权限；不向正式进程传递管理凭据。固定读探针由引导主体建立，记录其 VersionID，不让 API 自动创建。

权限以实际服务调用验证：匿名访问拒绝；下载不允许写入/删除/版本枚举；扫描无 PUT；精确版本清理允许且无版本删除拒绝。策略负向用例仅改变反例桶并恢复；不接触其他桶。版本清单、探针和故障注入均来自真实对象操作。

### 5.4 配置与环境

私密根目录 0700，凭据文件 0600，扫描 manifest/配置按既有合同 0400。每轮生成凭据，公开记录只含逻辑角色、资源归属与哈希；不提交、不打印 DSN、密码、访问键、私钥、token、cookie 或 env 值。

子进程采用显式变量白名单。完整 Go 套件环境移除继承的 `PG*`、`HOME`、`USERPROFILE` 等比较驱动禁止的变量，明确设置 PATH、TMPDIR、Go 缓存、工具路径及本轮测试变量；不得放宽 `internal/importcompare/driver.go` 环境守卫。浏览器确需 HOME 时，仅在其子进程设置本轮私密目录，不泄漏回 Go/只读命令环境。旧只读 CLI 子进程保留自身更严格白名单与陷阱测试。父套件不接收 `IM_APPEND_CHILD_SCHEMA`、`IM_TEST_REALTIME_API_CHILD` 等子进程启动开关；这些只能由对应真实父用例传给其子进程。

## 6. 扫描器、浏览器与正式进程

### 6.1 原生扫描器

复用安装的锁定 qpdf/ClamAV 二进制，但启动本轮原生 clamd 进程和私有 Unix socket，不复用共用守护进程。定义库从真实来源复制到独立目录，先核验签名/真实构建版本与时间，再启动；需要更新时只更新本轮目录。不得改日期、mtime 或产品有效期限来使陈旧定义通过。

正向和未证明限额的负向 clamd 分别使用不同 PID、配置、socket 与 manifest。manifest 绑定真实 PID/argv、二进制/配置/定义哈希、启动时间及运行用户；PID 重用、绑定不符、陈旧定义或权限不符立即拒绝。

正向维持已有 stream25MiB、child0、global250MiB、递归16、文件10000合同；负向保留原反例配置。执行实际 clean、EICAR、嵌套和展开限额、流边界证明；负向被拒绝不能替代正向 ready。Linux 512MiB/1CPU 完整解析和 1MiB tmpfs 磁盘满门禁使用当前源码编译程序与锁定资源镜像，不填满主机磁盘。

### 6.2 浏览器与 OIDC

使用已安装 Node/Playwright/Chrome 的实际版本和路径；每用例新建私有浏览器 profile，由测试关闭浏览器和 TLS/PKCE 身份源。验证完整登录、真实页面操作、文件收发/检索、撤权及重连/离线补拉，不以静态页面或伪造业务 DTO 代替。

OIDC 发行者仍为本轮 TLS 测试身份源；真实签名验证、本地身份映射及授权由正式 API 执行。通过不等于接入客户 IdP。

### 6.3 同源正式进程

使用同一固定源构建的 `im-api`、`im-outbox-worker`、`im-file-worker`、`im-file-cleaner`，并在既有正文清理场景构建相应程序。记录实际启动程序哈希、PID/开始时间、节点 owner、退出码和退出期限。代理仅转发正式响应并注入已有网络故障，不提供替代成功返回。

正式子进程只接收当前用例需要的配置；测试管理凭据留在夹具进程。业务开关矩阵沿用现有测试，程序默认关闭行为不变。readiness 失败须保存脱敏原因并修正具体问题，不增加等待时间来掩盖启动拒绝。

## 8. 编排结构与验证工具自身正确性

各职责独立：来源固定与解包、工具/镜像预检、资源/凭据管理、环境构造、现有门禁适配、事件解析/证据校验、最终清理。每层返回结构化状态及安全错误码；普通异常和取消均进入 finally 清理。共享只读元数据不包含私密配置。

复用现有门禁判断逻辑和严格必需名集合，避免重写业务断言。P4-30 子脚本目前默认还运行自己的完整套件，不能在不完整环境再跑一次并替代统一全套；本阶段允许增加明确的“仅必需门禁”调用模式。该模式必须写明完整套件未执行、不提供 full-suite PASS；旧默认行为和已有 gate 单元测试保留。统一编排再使用完整夹具执行本阶段全仓及 race，且对子报告再次校验源码/十四门禁/日志哈希。

编排工具自身需要先失败后通过的判定测试，覆盖：缺夹具、空匹配、必要子例缺失、Go 非零退出但日志含 PASS、截断/损坏 JSON、重复门禁、不同源码或哈希、普通 SKIP、辅助入口缺调用方/进程证据、清理失败、取消、错误资源归属、自动删除未完成，以及凭据不进入分享产物。合法的辅助入口条件有正向测试，其余均有反例。单纯检查自己刚写的字段值不作为充分测试。

长命令异步执行并持续给用户简短进展；不让单次阻塞等待超过60秒。Go 单包超时30分钟，单门禁外层期限60分钟，全轮含准备与清理总期限6小时；任一期限到达标为失败/取消，不自动重试 SQL 或生产请求。公共依赖获取失败保留该尝试，下一次使用新证据目录，不覆盖失败日志。

## 9. 故障处理和修正闭环

先对 P4-30 已保存失败/跳过按实际错误归类，不推测全部是环境问题。按完整环境重现后分类：

1. 夹具问题：IAM/角色、定义陈旧、白名单、路径或权限不符合既有合同。修正本轮资源，产品限制保持不变。
2. 验证工具问题：迁移清单、来源标签、统计或清理错误。增加反例测试并最小修正工具。
3. 产品问题：真实请求、持久化、授权、恢复或资源边界不符合既有合同。先取得真实失败证据，再最小修正并回归。
4. 契约变更：需要新功能/授权规则或支持新的客户环境，交付证据及具体方案后另行确认。

修正涉及代码或工具时，固定新提交、重新执行全部必需门禁和完整/race 套件。未解决问题、缺少组件或已超出期限时只能输出未通过记录及剩余事项，不能以旧提交或部分绿色包装为完成。

## 10. 资源登记、停止与恢复

每轮 owner 为新随机标识。资源型子脚本在创建前登记其子owner，并及时写入实际资源ID；允许给既有验证脚本增加可选的私密登记参数/资源标签，旧默认业务验证契约保持。父编排不能仅依赖子脚本正常退出后的cleanup字段来处理取消或遗留资源。登记实际容器 ID、精确标签、PID/开始时间/命令身份、目录归属和网络/卷；测试子进程也纳入本轮登记或父用例提供的可核对记录。清理前核验归属，不按宽泛前缀批量停止其他服务。

成功、失败、SIGINT/SIGTERM 和取消都先停止新测试、关闭本轮服务及扫描器/浏览器，等待退出，再删除本轮容器和私密文件；容器自动删除有完成等待与确认，不能将删除中的 inspect 成功误判成可复用或重复 rm。停止/检查有截止，不挂住用户会话。

硬退出后的重新执行先检查本轮私密登记；只有可证明的遗留资源可回收，不以名字或重用 PID 推断归属。无明确归属时清理失败并报告具体资源标识，不强行删除。清理失败保留最少的私密恢复登记，权限仍0700/0600；分享产物不含凭据。证据原件若含实际运行凭据，正常收尾前必须脱敏或删除并记录处置与原始哈希，不能以私密证据名义保留可用凭据。下一轮使用新 owner，不隐瞒上一轮残留。

测试故障和需要研究的日志先保存为私密证据；分享版只保留脱敏副本与各自 SHA256。正常关闭确认后删除 DSN、IAM secret、OIDC/TLS私钥、浏览器会话、配置和工作数据。不清理缓存中不含秘密的公共依赖或其他项目资源。

## 11. 证据格式和计数

公开 `verification.json` 至少含：schema_version、source_commit、source_archive_sha256、orchestrator_sha256、工具/镜像/平台、各门禁 argv 模板（无 env 值）、退出码、开始/结束/耗时、顶层/子测试/包 PASS/FAIL/SKIP 分开统计、普通跳过与辅助入口跳过、实际执行名与必需名、日志和二进制哈希、资源清理结论，以及 customer/production_acceptance=`not_executed`。

每个执行结果保留实际来源；包级 FAIL 不当作具名测试失败，包级 PASS 不当作顶层测试。重复执行为门禁事件计数，不宣称唯一用例数量。缺少或损坏可解析日志不得用零 FAIL 判成功。阶段“未执行”明确表示 not_executed，不用空集当PASS。

失败与跳过完整名称保留；安全问题不能回显凭据或真实业务响应。分享日志按本轮已知凭据做精确脱敏，另检查 token/私钥等格式；不把这称为全仓穷尽密钥审计。运行期间无法安全发布的原始日志先留在私密目录，不纳入仓库；收尾依第10节处置其中的可用凭据，不把日志保留等同于秘密已清理。记录原始私密与分享副本的不同哈希和权限。
