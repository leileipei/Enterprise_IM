# P1-03b OIDC 访问令牌验证与本地身份映射

## 目标

在 P1-03a 的受保护管理 API 上接入首个真实身份源。当前默认采用 OIDC 提供方签发的 RFC 9068 JWT 访问令牌；IM API 是受保护资源。此增量验证已有访问令牌，不实现浏览器跳转、授权码交换或客户端 UI。

## 令牌边界

通过 `IM_OIDC_ENABLED=true` 显式启用。配置必须包含 HTTPS 发行方、HTTPS JWKS 地址、IM API 受众，以及允许调用本 API 的客户端 ID 列表。服务启动时读取 JWKS，持续复用并刷新验签密钥；配置缺失、URL 非 HTTPS、JWKS 重定向或密钥端点不可用时不启用管理路由。令牌必须携带非空 `kid`，验签只使用 `use=sig` 的密钥，避免依赖库在省略 `kid` 时尝试整个密钥集。未知密钥编号的刷新受请求取消、短超时及限流控制；刷新失败期间的未知密钥返回认证服务不可用，直到密钥端点成功恢复。只接受 RS256 签名、`typ=at+jwt` 或 `application/at+jwt` 的访问令牌；必须验证发行方、受众、签名、过期时间、签发时间、主体、令牌 ID、客户端 ID。ID Token 和来自其他 API/客户端的令牌均拒绝。

参考：[RFC 9068](https://www.rfc-editor.org/rfc/rfc9068) 对访问令牌的类型及验证要求；[go-jwt 官方文档](https://pkg.go.dev/github.com/golang-jwt/jwt/v5) 的发行方、受众、算法和到期选项。此阶段限定符合上述 profile 的身份提供方；其他厂商的非标准或不透明访问令牌需另设适配器。

## 本地映射

新增 `external_identities`：以 `(issuer, subject)` 全局唯一绑定一个本地 `(tenant_id, user_id)`，同一发行方的同一本地用户只能绑定一个主体；支持同一个集团用户未来绑定多个身份源。仅查找 active 绑定、active 租户和 active 用户；不按邮件或姓名自动关联，也不从令牌接受本地 tenant/user/管理员角色。绑定由受控数据导入或后续管理流程写入，当前没有匿名注册端点。绑定失效或不存在视为认证失败，数据库故障视为认证服务不可用。

## 启用与限制

启用后 `cmd/im-api` 挂载 P1-03a 管理路由，领域层继续复核操作任职与授权并写审计。未启用时仍仅开放健康检查。部署方必须先执行第 4 个迁移、导入经核对的外部身份绑定及授权数据，再提供真实 IdP 配置。此增量的本地签名令牌和临时 PostgreSQL 验证不等同于客户 IdP 联调或生产登录验收。

## 验证

先测试令牌拒绝矩阵与映射查找，再实现。PostgreSQL 测试覆盖唯一绑定、跨租户外键、禁用绑定、冻结用户及回滚迁移。运行完整 Go 测试、静态检查和构建，并由独立审阅检查认证边界。
