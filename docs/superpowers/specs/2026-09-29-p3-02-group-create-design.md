# P3-02 建群接口与原子策略检查

## 目标与边界

在 P3-01 的群会话和成员区间结构上交付可调用的建群能力。已认证用户通过当前任职创建一个群，指定 1 至 20 位初始成员任职；每位用户只能出现一次。成功后群主及初始成员从 `join_seq=1` 加入，群的 `last_seq=0`。邀请、退群、群消息、群列表和策略变更后的群阻断留给后续增量；现有单聊接口保持原语义。

## 接口

`POST /api/v1/groups` 接收严格 JSON：`client_request_id`、`name`、`member_membership_ids`。请求 ID 是调用方生成的 UUID；群名去除首尾空白后为 1 至 120 个 Unicode 字符，拒绝控制字符；成员任职 ID 为 UUID，不能包含当前任职或重复 ID。仅从已验证令牌取得租户、用户和当前任职。新建返回 201，等效重试返回 200，响应包含 `id`、`type=group`、`last_seq`、`policy_version`、`member_count`。请求 ID 对同一租户和创建人唯一；同 ID 不同内容返回 409。无效请求返回 400，身份失效返回 403，任一成员不可用或策略拒绝返回无人员细节的 404，存储/审计不可用返回 503。

## 事务与策略

服务在一个事务中按 UUID 顺序锁定所有任职，再锁定租户记录，避免任职或政策发布在检查与提交之间改变。读取当前发布策略版本及规则，实时验证创建人和所有目标任职有效、同租户且每人不同。对全部成员的每个有向组合执行 `create_group` 策略判断，包括非创建人之间的组合；跨法人组合须获得该动作的明确审批。即使前面的组合被拒绝，仍记录全部有向组合的策略决策事件，事件包含真实的策略源用户和任职；另写一次以请求人为主体的建群操作审计。逐对审计结束后，以写入前的新时间复核任职及规则有效性，防止处理期间自然到期的授权继续建群。任一判断失败时只提交拒绝审计，不创建群或部分成员。成功时一次提交群行、全部成员区间、审计，审计写入失败则整体回滚。

`000010_group_create_request` 为群会话增加请求 ID 和规范化请求内容的 SHA-256 摘要，建立租户/创建人/请求 ID 唯一索引，并冻结这些字段。摘要包含创建人当前任职、群名和排序后的初始成员任职。进入策略检查前先读取等效已提交请求；并发相同请求在唯一索引上汇合，失败方读取先提交的结果。Down 在存在建群请求记录时拒绝，以免丢失重试保护。摘要只用于判断请求内容是否相同，不作为授权依据；重试仍需有效的当前身份。

## 验收

集成测试覆盖同组织建群、多成员任职快照、初始区间、跨组织/跨法人逐对拒绝、拒绝时完整逐对审计、授权自然到期复核、无部分写入、无信息泄露、身份变化、审计失败回滚、相同/冲突及跨任职请求重试与并发重复请求。HTTP 测试覆盖严格 JSON、可信身份、状态码及响应。全量 Go 测试、关键路径并发检测、构建和迁移 Up/Down 回归通过。
