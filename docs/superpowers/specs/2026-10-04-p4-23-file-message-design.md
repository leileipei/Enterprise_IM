## 1. 目标与已确认约束

员工在单聊或群聊中发送已经完成真实扫描的文件，接入现有可靠消息链路。断网重试不得重复创建消息、消耗 seq 或绑定文件；当前身份、会话成员和通信策略必须在实际提交前有效。

依据 P4-21 第 7.2 节和本轮用户确认：

- 每条附件消息恰好绑定一个 ready 文件。
- 文件必须属于原租户、原会话、原上传用户和原任职，只能绑定一次。
- 消息、附件关联、幂等记录、seq、Outbox 和成功审计原子提交。
- 同一逻辑发送返回原 ACK，重试不能重新授予文件下载权限。
- 增加正式消息类型，补拉、遮蔽、清理和搜索均处理类型边界。
- 旧文本请求和旧 Web 可继续工作。
- 在 P4-24 下载能力完成前，生产附件发送保持关闭。

本阶段交付数据库迁移、内部发送服务、HTTP 合约、补拉兼容及验收证据。文件下载、对象清理与文件保留配置属于 P4-24；Web 上传／附件卡片和文件名搜索属于 P4-25。

## 3. 方案选择与组件边界

采用扩展现有 `POST .../messages` 的方案。相比独立附件发送路径，减少两套消息接口合约的维护，且保持 P4-21 已确定的路径。HTTP 仅负责严格解析和 DTO 投影；数据库服务负责实际授权和原子写入；附件关联与摘要辅助代码保持独立文件。

新增类型化请求及内部发送入口，现有 SendTextMessage／SendGroupTextMessage 保留作为兼容入口。只抽取两种消息共有的必要步骤，不合并重写单聊／群聊全部策略实现。

类型化补拉是同一路径的显式 opt-in；默认响应仍为旧合约。不得让旧客户端把附件说明当作普通文本消息。

## 4. 发送协议

### 4.1 路径与请求

沿用：

- `POST /api/v1/conversations/{id}/messages`
- `POST /api/v1/groups/{id}/messages`

旧文本请求保持：

```json
{"client_msg_id":"<UUIDv7>","text":"工单说明"}
```

可显式声明文本类型：

```json
{"client_msg_id":"<UUIDv7>","message_type":"text","text":"工单说明"}
```

附件请求：

```json
{"client_msg_id":"<UUIDv7>","message_type":"file","file_id":"<UUID>","caption":"请核对附件"}
```

- 只有缺省 message_type 才按旧 text 解释；显式空值、NULL 或未知类型拒绝。
- file 请求必须有 file_id；caption 缺省等于空字符串，显式 NULL 拒绝。说明保持原始字符串，不 trim、不规范化换行。允许空或空白说明，须合法 UTF-8、无 NUL，最多 16 KiB。
- text 维持现有非空、非空白、合法 UTF-8、无 NUL、最多 16 KiB 规则；禁止带 file_id 或 caption。
- file 禁止带 text。客户端不能提交 SHA、文件名、对象定位、租户、上传者或任职等服务器事实。
- 新 file 请求拒绝重复 JSON 键、未知字段、额外 JSON 值和非字符串字段；保留现有 Content-Type、请求体上限、无查询参数和 UUIDv7 校验规则。
- 身份全部来自现有可信认证和受保护任职上下文。

### 4.2 ACK 与错误

成功 ACK 的 message_id、conversation_id、seq、server_time、duplicate 与现有协议相同。只有事务提交成功才返回。ACK 不返回 URL、下载授权或文件内容。下表中的错误字符串为 HTTP 合约；内部错误值复用或扩展现有服务错误。

| 情况 | 响应约定 |
|---|---|
| 请求格式、类型、caption 或 file_id 无效 | 400 invalid_request |
| 当前身份无效 | 沿用现有 403 语义 |
| 会话不可用／不是当前参与者／文件不存在或来源不匹配 | 404，使用统一不可用响应，禁止暴露他人文件状态 |
| 自有同源文件未 ready、处于删除状态或已经绑定另一消息 | 409 file_not_bindable；客户端需重新核对自有文件 |
| 相同幂等键但类型、file_id、原始 caption 等不同 | 409 idempotency_conflict |
| 摘要已退役 | 410 retry_window_expired（内部 ErrRetryExpired），沿用现有合约 |
| 超限、策略拒绝、暂时依赖故障 | 沿用当前消息错误映射；故障不伪称保存成功 |
| 生产附件发送关闭 | 503 file_message_unavailable，不检查或泄露指定 file_id |

只有验证当前身份及参与关系后，才能区分同源文件的不可绑定原因。幂等冲突和拒绝审计不得保存正文、文件名、原始指纹或对象定位。

## 5. 数据模型与迁移

新增 `000020_file_message` 迁移，前进迁移将历史消息标记为 text，不改变其正文、时间、seq、摘要、幂等期限或清理状态。

### 5.1 messages

- 新增 `message_type`，默认 text，闭集 text／file，创建后不可修改。
- 非清理 text 保持原正文约束。
- 非清理 file 的 text_body 存原始 caption，可以是空字符串，但不能为 NULL，字节上限仍为 16 KiB。
- 物理清理后两种类型都须 text_body=NULL、body_cleared_at 非空；不能恢复或修改清理时间。
- 不将文件卡片、文件名或 JSON 放入 text_body。caption 在 HTTP 中按类型投影，不能被旧文本渲染或搜索当作正文。

### 5.2 message_attachments

| 字段 | 约束与目的 |
|---|---|
| tenant_id、conversation_id、message_id | 复合消息引用；每条消息唯一附件 |
| sender_user_id、sender_membership_id | 复合引用原发送身份，并与消息、文件来源一致 |
| file_id | 同租户文件只允许出现一次；永久占用该绑定，即使文件删除或摘要退役 |
| sealed_sha256 | 内部 32 字节封存指纹，仅用于规范幂等校验；不得公开或进入日志 |
| fingerprint_retired_at | 与该消息／幂等记录的 digest_retired_at 同时设置；退役后指纹必须为空 |

必要的消息及文件来源复合唯一键、复合外键证明同租户、会话、发送用户、任职和对象一致。延迟约束证明每条 file 消息恰有一个附件，text 消息没有附件；同一 file 不得创建两个关联。

绑定插入时锁定原文件，检查 ready、完整 clean 扫描证据及扫描／封存 SHA 相同；sealed_sha256 必须等于服务端事实。应用事务和数据库守卫共同验证，不信任客户端或仅靠应用 if 判断。

关联的来源、message_id、file_id 和未退役指纹不可修改或删除。只允许指纹与消息摘要按下文原子退役，退役后禁止回填。关联表不复制文件名、caption、扫描输出、对象 key／version 或 URL。

### 5.3 回退

有 file 消息或附件证据时，down 迁移必须在修改任何结构前明确拒绝；不得删除数据、改写成文本或丢失关联。无附件数据时可恢复旧文本约束及结构，历史文本和已清理记录保持有效。生产回退优先关闭入口、回退应用，保留迁移及证据。

## 6. 新发送事务与并发

1. 严格解析请求；校验可信当前身份和会话参与关系。
2. 开启与现有发送相同的显式 READ COMMITTED 事务，先读取幂等证据；按当前发送链路锁定成员，复核原任职及当前身份。重试仍须由原发送用户及任职发起。
3. 按现有顺序锁定当前成员、会话和策略，复核单聊当前选择或群成员历史区间，先检查参与资格，再处理 policy_blocked。
4. 无已有同键发送时，检查会话 active、当前双方／全群 send_message 策略、原上传者任职有效性。
5. 检查当前租户文件配置 enabled、大小和允许类型仍允许该封存文件；锁定配置使并发变更形成确定先后。ready 不自动授权发送。
6. 锁定文件及相关绑定，检查同源、ready、未绑定和完整同指纹扫描证据。绑定与删除以同一文件锁串行化；若删除先提交，本次绑定失败。
7. 规范计算附件摘要，二次检查同键结果；消耗现有消息限流配额，分配 seq，写入消息、关联、幂等记录、Outbox 和成功审计。
8. 沿用现有临时写入 savepoint／最终时间复核机制。锁等待或审计等待跨越任职／规则期限时，使用新鲜时间重判；失败回滚临时消息写入和限流计数。
9. 提交，再返回 ACK。数据库异常、关联失败、Outbox 或成功审计失败时全部回滚。

所有附件发送与相关守卫统一先获取现有成员／会话锁，再获取文件锁；关联和摘要锁沿用消息锁后顺序。禁止先独立提交 fileTransaction，再提交消息。既有 SQLSTATE 40P01／55P03 等有界重试策略沿用，不无限重试。

两次不同幂等键争用同文件：最多一条消息提交，另一条失败且不增加 seq。相同键并发：一条新写入，其余返回同一 ACK；重复成功不再消耗速率配额或产生 Outbox。拒绝可留下既有安全审计／策略暂停证据，不能留下临时消息、附件绑定或 seq 消耗。

## 7. 幂等摘要、删除与退役

### 7.1 摘要规范

文本沿用已有 raw-text SHA-256。附件使用 UTF-8 JSON 字符串数组，按以下固定顺序编码后取 SHA-256：

`["file-message-v1","file",tenant_id,conversation_id,sender_user_id,sender_membership_id,file_id,sealed_sha256_lower_hex,caption]`

编码固定使用 Go encoding/json.Marshal 对字符串数组的默认规则：无缩进、无结尾换行、保留默认 HTML 字符转义；新写入与重放共用同一个编码函数。所有 UUID 使用规范小写；caption 保持原始值；文件 SHA 只能从 ready 文件事实取得。不得使用字符串拼接、客户端 SHA 或随机对象 ETag 替代。缺省 caption 和显式空字符串是同一请求；显式 file 与同键 text 是冲突。

### 7.2 已有发送重试

发现已有同键记录后，先验证消息、幂等记录和关联一致性，以及当前原发送身份／参与资格。摘要未退役时从绑定的内部封存指纹重构请求摘要，不从可能已经删除的文件重新取 SHA。类型、file_id 或 caption 改变则冲突。

一致重试返回原 ACK，即使 file_objects 已进入 delete_pending／deleted、caption 已物理清理、原发送后通信策略普通变化或文件配置已禁用。沿用既有发送重放边界，不重新执行新发送、分配 seq 或授予下载权限。当前身份或参与资格不合法时仍拒绝。生产入口关闭优先拒绝，不因历史成功开放附件入口。

### 7.3 指纹退役

DigestWorker 的既有前提保持：正文已物理清理、幂等记录期限已到、会话无生效法务保全。在同一事务以同一时间戳清空 messages／message_idempotency 的 content_digest，以及附件关联的 sealed_sha256，并写原退役批次证据。

数据库延迟约束要求 file 消息的三份退役状态和时间一致；任一缺失、单独退役或回填都拒绝。整个退役事务失败不能部分清空。关联 ID、file_id 和来源仍保留最小绑定证据。此后重试返回 ErrRetryExpired（HTTP 410 retry_window_expired），不允许删除键再创建第二条消息。

这份绑定指纹仅为消息幂等证据；原 file_objects 的扫描／封存证据仍按独立文件生命周期与保留政策管理，不把消息摘要退役误称为文件已删除。

## 8. 补拉、旧协议与遮蔽

### 8.1 显式类型化补拉

单聊／群聊 `GET .../messages` 新增可选参数 `message_format=typed_v1`。缺省保持旧 DTO；未知值、重复参数沿用严格请求校验拒绝。分页 after_seq／limit、next_after_seq、has_more 语义保持现有时间线。

类型化 text 返回原文本字段并声明 message_type=text。可见 file 返回 message_id、seq、sender_user_id、server_time、message_type=file、caption，以及最小附件结构：file_id、available；仅在文件 ready 且元数据完整时附 original_filename、actual_size_bytes、detected_media_type。

文件删除、待删除或元数据不完整时 available=false，隐藏文件名、大小与 MIME；卡片只呈现不可用状态。P4-23 始终 download_available=false，无 URL、token、SHA 或对象定位。元数据补拉可见性沿用历史消息边界，不伪称已通过 P4-24 更严格的文件下载授权。

### 8.2 默认旧协议

可见 file 用旧 text 字段返回固定中文占位 `附件消息（当前客户端不支持查看）`，不返回 caption、file_id 或文件名。此字符串只是响应兼容投影，不写入数据库或搜索索引。现有 Web 无须提前实现上传／下载界面。

### 8.3 统一遮蔽

以下任一条件成立，仅返回 `seq` 与 `redacted=true`：消息正文逻辑到期、正文已物理清理、历史成员区间不允许查看或当前历史 hard_deny。message_id、发送者、时间、类型、caption、附件 ID 与卡片字段全部省略，旧格式和 typed_v1 一致。

补拉在最终授权过滤之后投影 DTO；原有页面最终时间复核同样覆盖附件。法务保全暂停物理清理及摘要退役，不延长普通客户端逻辑可见期限。文件保留期限与消息正文期限相互独立；正文遮蔽不证明对象已删除。

## 9. 搜索、实时与审计

- 单会话／跨会话文本搜索查询与分页候选显式限定 message_type=text，保持当前关键词匹配、遮蔽、排序、游标和最终复核语义。
- file 的 caption 和名称不进入现有文本搜索。P4-25 再定义文件名搜索；不能通过 SQL 直接读取 text_body 泄露附件说明。
- 附件仍产生原 message_created Outbox，含原消息引用，无正文或文件事实；Redis 广播及 WebSocket ready／sync_required 合约保持。
- 实时收件人解析沿用原授权机制；客户端接到提示后按当次身份补拉。旧客户端得到占位，未来附件客户端 opt-in 得到类型化结果。
- 成功和拒绝审计使用闭集原因码及最小消息／会话引用；不记录 caption、文件名、SHA、对象定位、下载 URL 或扫描原始结果。ACK 表示服务端已保存，不代表接收者已收到或已读。

## 10. 生产装配边界

P4-23 提供内部能力与测试装配，生产 `cmd/im-api` 对 file 发送始终返回 file_message_unavailable。本阶段不提供可绕过 P4-24 前置条件的启用环境变量；测试可通过显式测试依赖装配调用内部发送和 HTTP 处理器。

生产仍可运行既有文本接口与已批准的 P4-22 上传／扫描配置。类型化补拉合约可装配但无生产附件新写入。P4-24 完成下载再授权及其真实集成验收后，另行设计实际启用条件。未完成下载、Web 入口或生产验收时，不声明完整文件分享 F01 闭环完成。

## 11. 验收要求（均为待执行项）

| 层级 | 必须覆盖 |
|---|---|
| 规范与 HTTP | 旧文本／显式 text、空与缺省 caption、16 KiB 边界、类型不一致、NULL、重复键、未知字段、超限体、关闭入口统一响应 |
| 真实数据库迁移 | 历史文本及清理记录兼容；file 与附件一对一；来源复合 FK；跨租户／会话／用户／任职拒绝；未扫描绑定拒绝；直接 SQL 不可改写／复活关联 |
| 单聊／群聊发送 | 真 ready 文件通过；inactive／policy_blocked／非当前成员／原任职变化拒绝；当前文件配置禁用、类型与大小变化拒绝；审计和 Outbox 原子性 |
| 并发与注入故障 | 同键同文件、不同键同文件、同键不同类型／文件／caption；锁等待后的期限复核；删除竞争、成员撤销、策略切换；失败无消息／绑定／seq／配额残留 |
| 重放 | 原 ACK 稳定；文件删除、正文清理、普通通信策略变化后同请求重放；禁止换原任职；无下载授权副作用；摘要退役后 HTTP 410 retry_window_expired |
| 退役与保全 | file 三份摘要／指纹同时退役；中途失败全部回滚；单独 SQL 清空拒绝；会话保全及锁等待竞态；退役后不能恢复／删除键重用 |

| 真链路 | PostgreSQL 消息事务＋Outbox＋Redis＋WebSocket 提示＋HTTP 补拉；旧 Web 文本回归和附件占位；生产进程附件关闭 |
| 回归与交付 | 受影响包 race、既有全量门禁；固定提交归档运行并保存通过／失败／跳过数量；一次最终独立评审及必要修正；中文验收记录和草稿 PR |

真实 ready 证据须由受控真实对象上传和 ClamAV 扫描生成；约束负向测试可以构造专门夹具，但不作为扫描集成通过证据。过期扫描库、旧 manifest、已经停止的运行器必须重新核验，不能直接复用为就绪证明。

单元、数据库、组件和生产运行验收分别报告；没有执行的要求不能写成 PASS。测试过程中创建的对象、容器及进程由本轮记录归属并清理，保留必要日志，不删除既有用户数据。
