## 1. 目标、假设与方案

为已有集团租户准备组织主数据接入：先验证输入文件，再与同一数据库事务快照中的存量比较，识别新增记录、完全一致的重复记录以及必须人工处理的差异和冲突。面向持有专用数据库读取权限的部署运维人员，输出不包含人员原文的 JSON 报告。

沿用用户已确定的 JSON 命令行路线和暂未选定客户身份源的前提。用户于 2026-10-07 确认本书面规格，采用目标库只读比较路线。

| 路线 | 作用 | 本次取舍 |
| --- | --- | --- |
| 独立只读比较命令，推荐 | 使用当前 JSON 契约核对已有库，提供后续导入的冲突依据 | 先交付这一增量 |
| 管理后台预览与写入批次 | 可提供业务审批、审计和受控执行 | 另行设计 Web 授权、批次与写入流程 |
| LDAP／AD／OIDC 自动同步 | 持续维护外部身份与任职 | 身份源、稳定主键与停用语义仍需客户确认 |

成功标准是：输入及存量已在声明范围内完整检查，新增候选没有发现已支持的键、关系或区间冲突，且全程没有修改业务数据。成功报告不代表允许导入、实际身份正确或稍后写入仍无并发冲突。

## 2. 范围

1. 新增 `cmd/im-import-compare` 与 `internal/importcompare`，不增加 REST 路由、Web 页面、迁移、Worker 或同步任务。
2. 九类数据及字段沿用 [P4-27 §4.1](2026-10-06-p4-27-import-preflight-design.md)：租户、法人、组织、部门、人员、组织任职、部门任职、外部身份、管理员授权。
3. 每次只选择一个已存在租户。输入九张数组均保留，`tenants` 必须恰有一个目标租户；所有记录必须属于这个租户，并且文件内部引用闭合。多租户文件必须先按租户拆成独立、闭合的文件。
4. 仅预检追加新记录和忽略完全相同的记录。同主键内容不同、身份改绑、名称／状态／法人／上级变更、任职缩短、管理员授权变化均报告冲突，不产生覆盖或更新计划。
5. 不创建租户，不按姓名、邮箱或近似工号合并人员，不导出库存原文，不保存输入或数据库快照，不产生执行 SQL。
6. 新命令的数据库配置不会进入原 `im-import-preflight`；原命令仍只离线检查、忽略连接环境变量，其输出及上限不变。

## 3. 命令、配置与身份边界

```sh
im-import-compare --input /absolute/path/tenant_data.json --tenant-id 00000000-0000-4000-8000-000000000001
```

仅支持 `--input`、`--tenant-id`、`--help`、`--version`。参数缺失、重复、未知、混用或租户 UUID 非法返回固定用法与退出码 2，不回显参数值。帮助／版本不读取文件或数据库配置、不连接数据库。

配置仅从以下显式变量读取：

| 变量 | 契约 |
| --- | --- |
| `IM_IMPORT_COMPARE_DATABASE_URL` | 必填显式单目标连接串，最大 8 KiB，不接收命令行凭据 |
| `IM_IMPORT_COMPARE_SCHEMA` | 可省略，默认 `public`；1～63 字节，ASCII 小写字母起始，其后小写字母、数字或下划线 |

连接串仅接受 `host`、`port`、`dbname`、`user`、`password`、`sslmode`、`sslrootcert`、`sslcert`、`sslkey`、`connect_timeout`。主机、数据库、用户和 TLS 模式必须显式指定；单端口为 1～65535，Unix socket 若省略 port 固定使用 5432，不从 `PGPORT` 补值。密码或客户端证书可以在这些显式字段中提供，专属本地 trust 测试夹具可以不含密码。`connect_timeout` 若提供只接受 1～3 秒，不得扩大父预算。

拒绝多主机、service 配置、replication、运行参数、连接串内 `options`／`search_path` 和未知键；不回退到 `PG*` 环境、系统用户名、密码文件或其他 IM 连接配置，也不改写进程全局环境来实现隔离。连接策略需要在实现中针对当前锁定 pgx 版本验证。TCP 连接要求 `sslmode=verify-full`；`disable` 只允许显式 Unix socket，连接失败不降级到其他地址或模式。

操作者通过专用数据库凭据获得读取权限，不通过文件中的 `admin_grants` 授权自己。该凭据需要读取九表，并具备查询输入全局键是否被占用的能力，因此属于数据库运维接入，不开放给普通 IM 用户或子公司管理员。

启动检查当前有效角色：拒绝 superuser、BYPASSRLS；九表必须有 SELECT 权限，且没有 INSERT、UPDATE、DELETE、TRUNCATE 权限；各表必须是普通持久表且未启用 RLS。角色、权限或对象不符合时返回固定 `DATABASE_ACCESS_UNSUPPORTED`，不尝试修改权限。连接本身仍需目标 DB 的 CONNECT 和 schema 的 USAGE 权限。

此约束只规定新工具使用的有效权限，不宣称凭据在整个数据库的所有对象上均无写权限。产品 SQL 固定为受控读取及事务设置，不调用输入指定的函数、不使用临时表、不执行任意 SQL。

## 4. 执行步骤与一致性

1. 共享 P4-27 的安全本地文件读取：普通文件、逐级拒绝符号链接、大小上限、同一次读取计算 SHA-256、取消和输出错误处理。
2. 复用文件结构、字段、键、关系、图和区间校验。文件无效或不完整即停止，不连接数据库；再检查单租户和选择参数一致。
3. 解析显式数据库配置并连接一个目标，使用 `REPEATABLE READ READ ONLY` 开始事务。在任何业务读取前验证隔离级别及只读模式，之后所有表／全局键检查使用该事务。
4. 在该事务内验证权限、读取投影结构、确定性 collation 及必要主键／唯一／区间约束结构。九表使用明确限定的 schema，数据值全部参数化，不能依赖外部 search_path。
5. 读取目标租户的一条 `tenants` 记录及另外八表的全部目标租户记录，使用固定表序、固定主键序。目标租户不存在则完整返回 `TARGET_TENANT_NOT_FOUND`，不创建它。
6. 对输入主键作有界批量全局占用查询：UUID 表主键和外部身份 `(issuer, subject)`。非目标租户仅查询与输入键对应的占用布尔值；不拉取或输出其他租户的人员、租户 ID、组织或原始记录。
7. 完整读取与全局占用查询后结束只读事务并关闭连接，再在剩余预算内完成比较和合并模型检查。读取错误、取消、权限／结构不支持、结果超限或异常事务结束均返回 incomplete，不把部分库存当作完整库存。
8. 在有界内存中生成完整报告并输出；不重连取得另一份库存，不自动重试并混用两个快照，不写入审计表或其他业务表。

首版基于 PostgreSQL 16 与仓库现有迁移投影。`REPEATABLE READ` 保持本事务各次读取的快照一致；`READ ONLY` 限制事务内的数据修改，但不是物理磁盘零写的承诺。设计依据见 [PostgreSQL 16 事务文档](https://www.postgresql.org/docs/16/sql-set-transaction.html)。

只核对本规格的读取投影、必要键／区间约束及模型规则。允许现有迁移添加的非投影字段，如租户保留设置；不解析任意自定义触发器／额外约束的执行语义。报告始终 `additional_database_rules_checked=false`。因此 valid 不能表示实际 INSERT 的全部数据库规则一定允许执行。

文本唯一键的 collation 必须是 deterministic；非确定性配置返回 `DATABASE_PROFILE_UNSUPPORTED`，不能用 Go 字节比较冒充目标库的等价判断。[PostgreSQL collation 文档](https://www.postgresql.org/docs/16/collation.html)说明了不同配置的比较语义。

## 5. 比较规则

### 5.1 行匹配与差异

- UUID 按值匹配，外部身份按 `(issuer, subject)` 精确匹配，不折叠文本大小写或 Unicode，不推测同一人员。
- 相同主键、P4-27 声明的全部字段相同：`identical`，不会二次增加到合并视图。
- 相同主键、任一声明字段不同：`conflict`。按固定字段顺序报告 `STORED_VALUE_DIFFERS`，只指出输入行和字段，不输出新旧值。
- 主键未存在且全局未被占用：先视为新候选，再检查业务唯一键、引用、组织／部门图及所有区间规则；通过后归为 `new`。
- 跨租户 UUID 主键或外部身份复合主键被占用：输入行报告 `GLOBAL_KEY_CONFLICT`，不提供占用方信息。
- 法人／组织 code、部门组织内 code、集团工号、同用户同 issuer 的主体唯一性沿用 P4-27。数据库与输入的新候选之间发生业务键冲突时报告 `STORED_UNIQUE_CONFLICT`；相同姓名而不同工号不构成自动合并依据。
- 数据库生成列及非投影字段不参加相等比较。可空值仍区别于空字符串；默认值按 P4-27 规范化，时间按 UTC 微秒时刻比较。

### 5.2 合并视图及存量完整性

库存投影须先独立满足当前模型的引用、图、标量与区间规则。不能完整表示的库存时间（包括 infinity 或超出当前输入年份范围）、过长字段／不支持枚举，返回 `DATABASE_DATA_UNSUPPORTED`；违反已有模型规则的库存返回 `DATABASE_DATA_INVALID`。两者都属于 incomplete，不输出库存错误行的内容。

库存记录最多 20,000 条，不调用离线文件的 10,000 行顶层限制来处理它，也不提高旧命令的限制。转换库存记录使用共享字段规范及单条标量校验；纯模型校验器使用规范化记录。

建立“库存 + 没有主键／字段／业务键冲突的新候选”的合并视图。完全相同的输入行仅作为库存别名关联。拒绝覆盖冲突行；文件中的关系若依赖一个拟修改的库存行，不能据此假设该修改已经发生。

组织／部门任职区间检查仍使用 `[from, to)`，包含 ended／suspended 历史记录。相邻区间合法；同组织任职、组织主任职、同部门任职、部门主任职、部门区间包含关系均核对库存与候选之间的交叉冲突。

模型检查使用明确的记录来源表，将内部组合行号转换回原输入行号；库存内部行号永不输出。区间冲突的扫描方向不能决定是否被看见：冲突位于库存一侧时，也必须投影到涉及的输入行。两个输入行相互冲突时可以使用原输入 `related_row`，涉及库存时省略它。意外只涉及库存而无法归因的模型问题按 `DATABASE_DATA_INVALID` 返回 incomplete。

最终三类计数以输入记录为单位，九表各满足 `new + identical + conflict = input_count`。任何字段差异或跨库存模型冲突使相关输入行成为 conflict；一行多问题只计一个冲突行。`new` 仅表示本规格中无冲突的新候选，不表示已授权写入。

## 6. 上限和取消

| 项目 | 固定上限 |
| --- | --- |
| 输入 | 保持 P4-27 的 10 MiB、10,000 行、16 层、单字符串 4,096 字节 |
| 目标租户库存 | 九表合计 20,000 行；多读取一行用于判断超限 |
| 库存字段内容 | 规范化字段 UTF-8 内容合计 64 MiB；单字符串仍最多 4,096 字节 |
| 合并模型 | 最多 30,000 条规范化记录，不能通过分页规避总量限制 |
| 全局键查询 | 每批最多 1,000 个输入键，最多返回每个输入键一个占用结果 |
| SQL 次数 | 同一次运行最多 128 条，含事务、模式、权限与结构检查，禁止逐行 N+1 |
| 连接时间 | 最多 3 秒，且不能超过父预算剩余时间 |
| 单条 SQL | 最多 5 秒，且不能超过父预算剩余时间 |
| 总处理时间 | 从读输入开始共享 30 秒；不按表、阶段或重试重新计时 |
| 输出 | 最多 200 个固定诊断明细，报告最多 256 KiB |

达到库存／字节／查询／合并上限返回 incomplete。文件自身违反原格式或原输入资源限制仍沿用 invalid 语义。超过问题明细上限继续完成检查和统计，不把未展示的问题当作不存在。

取消／SIGTERM／超时返回 incomplete 和退出码 2；先中止数据库操作，再在最多 1 秒独立诊断预算内释放连接和输出固定失败报告。输出阶段保留 P4-27 的短写、错误、SIGPIPE 和取消处理，不保留原始连接错误，也不输出部分成功 JSON。

这些是工具上限，不是生产人员规模或吞吐承诺。超过可检查规模时返回不完整，未来独立设计更大规模的数据库侧有界比较。

## 7. 报告及退出契约

新增命令使用独立报告，原离线报告不改版：

| 字段 | 含义 |
| --- | --- |
| `report_version` | 1 |
| `validation_profile` | `group_identity_database_v1` |
| `scope` | `database_snapshot_insert_compatibility` |
| `status` | valid／invalid／incomplete |
| `file_status`, `file_checks_complete` | 本次原始文件的校验结果 |
| `checks_complete` | 文件、选择范围、库存和全部适用比较是否完整完成 |
| `database_checked` | 全部适用库存检查完成时 true；发现完整检查中的业务冲突仍为 true |
| `input_sha256` | 同一次完整文件读取的 SHA-256；未完整读入为 null |
| `counts` | 原文件九表及 total 的数量，含义沿用 P4-27 |
| `classification_counts` | 九表及 total 的 new／identical／conflict 三项；数据库阶段不完整时全部为 null |
| `errors_total`, `issues`, `issues_truncated` | 去重后的固定诊断数量、前 200 项、截断标志 |
| `identity_provider_checked` | 恒 false |
| `additional_database_rules_checked` | 恒 false |
| `write_concurrency_checked` | 恒 false |
| `import_authorized` | 恒 false |

有效单租户参数与输入不符、目标租户不存在均为 invalid；前者不连接数据库，后者仅完成适用的目标存在性检查，不声称完成九表数据比较。两种情况 `checks_complete=false`、`database_checked=false`、分类均为 null。其他输入 invalid 且数据库未运行时亦遵循此规则。

只有文件 valid、比较完整、零冲突／错误时整体 valid、退出 0。完整比较发现冲突，或输入无效时退出 1。配置、连接、权限、结构、数据库不可表示、资源限制、取消、超时及输出失败退出 2，整体 incomplete。帮助／版本是独立的退出 0 模式。

每个 issue 含固定 `stage=file|database`、entity、原输入 row、固定 field、固定 code，可选同表输入 related_row。文档级 row 为 null；排序先 stage，再沿用原表／行／字段／code／related_row 顺序，重复项按完整元组去重。分类计数为 null 与合法零不能混用。

新增固定码：`TENANT_SELECTION_MISMATCH`、`TARGET_TENANT_NOT_FOUND`、`STORED_VALUE_DIFFERS`、`GLOBAL_KEY_CONFLICT`、`STORED_UNIQUE_CONFLICT`；模型交叉问题使用原关系／图／区间码并标记 database stage。运行码：`DATABASE_CONFIG_INVALID`、`DATABASE_CONNECT_FAILED`、`DATABASE_ACCESS_UNSUPPORTED`、`DATABASE_PROFILE_UNSUPPORTED`、`DATABASE_DATA_UNSUPPORTED`、`DATABASE_DATA_INVALID`、`DATABASE_READ_FAILED`、`DATABASE_LIMIT`；取消和输出码沿用 P4-27。

命令顶层及本工具自有输出协程处理可恢复异常，仅输出固定失败码；系统不可恢复崩溃不承诺产生完整 JSON。报告、stderr、应用日志与可恢复异常处理不得输出姓名、工号、UUID、issuer／subject、文件／证书路径、schema／DB／角色名、DSN、密码或原始错误。没有库存导出功能，不写审计表；如操作者自行保存报告，保存位置和系统级操作审计由部署环境管理，不能称为 IM 业务审计已完成。

相同输入和相同库存状态必须输出相同报告字节。报告不包含数据库当前时间、连接地址或事务 ID；并发变更后再次运行可以得到不同报告。报告不能作为后续写入可复用的快照票据，实际导入需要再次校验。

## 8. 模块边界及兼容

- `internal/importpreflight` 继续承担无数据库依赖的字段、结构、关系、图、区间及诊断。只允许增加返回规范化文档、固定字段描述或单条规范化的内部复用接口，不引入 pgx 或读取连接配置。
- `internal/importinput` 提取现有安全本地读取能力供两个命令使用。旧命令兼容性须以原 CLI、进程、平台和报告字节回归验证；不复制一套较弱的文件打开流程。
- `internal/importcompare` 负责显式配置、只读快照读取、目标结构／权限验证、来源映射、追加兼容性比较和新报告。数据库访问与纯比较分开，不把原始连接错误传给报告生成器。
- 两个命令各自处理参数和最终输出，不能用一个模式开关把原离线命令隐式变成联网命令。
- 不改消息、策略、身份认证或附件运行开关，不把这次只读预检当作 M4、客户 IdP 或生产验收。

## 9. 必须编写并执行的验收
