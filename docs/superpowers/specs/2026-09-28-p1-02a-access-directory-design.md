# P1-02a 管理授权与通讯录最小闭环

## 目标与范围

在 P1-01 的集团身份、组织及任职表上，形成可验证的管理授权闭环：集团管理员可管理本租户；组织管理员只能查看和变更授权组织内的任职；用户在某组织离职时保留集团账号和其他组织任职。对应 v2.2 的 G01、G02、G05 和 G11。此阶段不接入真实 SSO，也不开放接受自报身份的公共管理接口。

## 身份与授权边界

调用方必须提交由未来认证适配器验证过的 `tenant_id` 与 `actor_user_id`，并显式选择 `acting_membership_id`。领域服务从数据库重新读取账号、任职和组织状态；不信任请求携带的组织、法人或角色字段。缺失、跨租户、失效或歧义的任职默认拒绝。管理员角色也不能绕过租户边界。

授权采用独立的 `admin_grants` 表，当前支持 `group_admin` 和 `organization_admin`。集团授权作用于整个租户，组织授权作用于明确的 `organization_id`，不自动继承子组织。授权记录有生效区间与状态；同一用户可有多个授权。当前管理动作只包括 `directory_view` 和 `membership_end`。后续部门管理员、审计员和细粒度动作通过新迁移扩展。

## 数据与操作

迁移新增 `admin_grants` 和 `audit_events`。授权通过复合外键绑定同租户管理员任职及目标组织；主体用户由该任职解析，不另存一份。数据库拒绝跨租户关联及与角色不匹配的 Scope。`audit_events` 记录操作者、选定任职、动作、资源、结果、原因和发生时间；拒绝也应写入审计。审计写入失败时，管理变更整体回滚；只读操作不能返回未审计的人员详情。

领域服务提供：

- `GetManagedPerson`：按目标用户 ID 查询其获授权组织内的有效任职和部门，未授权组织的信息不返回；若目标没有可见任职，返回拒绝或未找到，不暴露人员详情。这是管理员查询，不代替普通通讯录通信策略。
- `EndMembership`：在事务内关闭指定组织任职和其部门任职，检查动作时间落在当前有效区间，并写审计；其他组织任职和集团用户状态不变。若存在尚未生效的部门任职，先返回冲突，留给后续显式取消流程。若主组织被结束，不自动把另一任职设为主组织，交给后续显式任职变更流程处理。

对这两个操作，必须先解析选定任职，再校验对应动作的管理员授权与目标组织范围。无授权、租户不符、任职无效和资源不存在均使用明确错误码；外层 API 映射时应隐藏未授权资源是否存在。使用服务端时钟决定有效期，调用方不能指定过去时间绕过授权。对有效租户中的拒绝访问写审计；无法解析的租户或未经验证的外部请求交给未来认证入口记录。

## 验证与限制

PostgreSQL 集成测试覆盖集团/组织管理员范围、一人多任职可见性、跨组织拒绝及审计、单组织离职和跨租户 ID。每项失败场景先写测试再实现。现阶段认证适配器、管理 HTTP API、策略规则存储与版本发布留待 P1-02b；因此不能宣称已完成 P1 整体或真实登录到通讯录的端到端验收。
