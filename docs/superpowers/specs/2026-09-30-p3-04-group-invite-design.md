# P3-04 群成员邀请设计

## 目标与范围

基于 P3-03 群成员区间交付单人邀请。群主或群管理员使用已验证令牌中的当前任职邀请一个目标任职；成员仅从 `last_seq+1` 开始可见。批量邀请、移除、群主转让、群消息和自动恢复 `policy_blocked` 留给后续增量。

## 接口和重试

`POST /api/v1/groups/{group_id}/invitations` 接收严格 JSON `client_request_id`、`target_membership_id`，均为 UUID；拒绝未知、重复或大小写变体字段。首次成功返回 201，响应 `interval_id`、`join_seq`、`policy_version`；同一群、邀请人及请求 ID 的等效重试返回 200 和原区间，即使受邀者已退群或重新入群。同 ID 变更当前任职或目标任职返回 409 `idempotency_conflict`。无效请求 400，无效当前身份 403，非管理员 403 `group_permission_denied`，群/目标不可用或策略拒绝统一 404，`policy_blocked` 群 409，存储/审计不可用 503。

## 事务与策略

在事务中验证邀请人当前任职，再锁群会话，核查其活跃区间角色。读取活跃成员和目标任职，并用 NOWAIT 按任职 ID 排序锁定；并发成员/任职变化引起锁冲突时返回可重试的服务错误，不部分写入。已有活跃的目标用户不能通过另一任职重复加入。

读取同一发布策略快照，对新成员和**每位现有活跃成员**执行 `invite_group` 双向策略判断；邀请人当前任职与其入群任职不同时，也额外参与双向检查。跨法人须明确审批。完整记录每个有向决策，即使有拒绝也继续审计其他组合；权限、封锁和策略拒绝均记录操作拒绝审计。检查后用新时间复核任职及规则，防止处理期间自然到期。成功时写入新成员区间、邀请请求账本与操作审计，全部同事务提交；审计失败整体回滚。群 `last_seq` 不变，`join_seq=last_seq+1`。邀请账本由迁移 `000011` 创建，用于持久重试保护；数据库约束确保账本引用的区间属于同一群和目标任职。

## 验收

测试覆盖同组织邀请、双向与非邀请人组合校验、跨法人审批、封锁群、非管理员、跨租户与重复用户、加入序号、退出后旧邀请重试、冲突请求、审计失败回滚及并发相同请求。HTTP 测试覆盖可信身份、严格 JSON、状态码和无内部错误泄露。
