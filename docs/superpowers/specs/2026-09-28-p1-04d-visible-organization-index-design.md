# P1-04d 普通通讯录可见组织索引设计

## 目标与范围

员工在选定本人有效任职后，获得可用于构建组织树的节点列表。直接可见节点必须至少有一个当前任职通过已发布的 `directory_view` 策略；为显示路径，只补充这些节点的有效祖先。隐藏组织、无可见人员的分支与跨租户节点不得出现。本阶段不返回成员人数或人员列表；按组织查看成员属于下一增量。

## 接口

`GET /api/v1/directory/organizations`，需与普通通讯录相同的 Bearer 令牌和 `X-Acting-Membership-ID`，不接受查询参数。成功返回 `organizations` 数组，节点含 `id`、`parent_id`、`name`、`org_type`、`has_visible_members`。数组按层级深度、名称和 ID 稳定排序，父节点先于子节点。只有补路径的祖先节点 `has_visible_members=false`；若祖先停用，则不显示它，并把其下可见节点作为当前结果的根节点。无可见组织返回空数组。

认证层拒绝无效令牌或冻结账号（401）；选定任职失效返回 403；审计、数据库或锁冲突失败返回 503。接口不会推断 `start_chat` 或群聊权限。

## 授权与一致性

在一个事务中验证本人任职，读取当前已发布策略。默认把本人组织作为候选；从当前 `directory_view` 放行/例外规则提取可能的目标组织，若规则未限制目标组织则考虑所有组织。这只是保守的候选缩小范围，最终可见性逐任职调用同一个策略引擎判定。

按固定组织与任职顺序检查候选组织的当前有效任职，检查期间锁定目标任职并再次确认其组织归属。组织元数据和祖先行按 ID 加共享锁，防止其状态或父节点在投影期间改变；遇锁冲突失败关闭。每次判定写 `policy_decision_events`；一个组织找到首个允许任职后即可停止检查该组织。整个请求另写一条不含组织枚举详情的 `directory_organization_list` 审计。所有审计与响应所据读取在一个事务中提交；任一失败不返回部分节点。

## 验收与限制

测试覆盖同组织、跨组织默认隐藏、发布放行和强制拒绝、虚拟根祖先、停用祖先、跨租户、冻结/失效任职、审计失败和受保护 HTTP 参数。此版本按需实时判定，尚未做集团规模下的缓存与性能基准；大量全部被拒绝的任职可能增加查询耗时，正式部署前需要容量测试。
