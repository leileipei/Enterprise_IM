# P1-04e 普通通讯录按组织浏览可见成员设计

## 目标与范围

员工从 P1-04d 可见组织索引选择 `has_visible_members=true` 的组织后，分页查看该组织当前允许其查看的任职。每条人员结果只包含这个组织中的可见任职；其他组织的兼岗不会被顺带返回。通讯录可见性仍使用当前已发布的 `directory_view` 策略，不代表可以发起单聊。

## 接口

`GET /api/v1/directory/organizations/{organization_id}/members?limit={1..20}&after={membership_id}`，要求普通通讯录的 Bearer 令牌和 `X-Acting-Membership-ID`。`limit` 默认 20；`after` 可省略，提供时须为上一页最后一个可见任职的 UUID。请求只接受这两个单值参数。

成功返回 `people`、`has_more`、`next_after`。每个人员含 ID、姓名、集团工号和仅本组织的一项可见任职，按集团工号、用户 ID、任职 ID 稳定排序。`has_more` 只由下一名可见人员决定；有下一页时 `next_after` 为本页最后一个任职 ID，否则为 `null`。无直接可见成员的组织、不存在或跨租户组织统一返回 404；有效可见锚点后再无人员时返回 200 空页。已失效或隐藏的锚点返回 404，格式错误返回 400。身份失效与审计故障沿用既有 401/403/503 语义。

## 事务和授权

一个事务内验证本人选定任职和目标组织有效性，读取当前策略。提供 `after` 时先锁定锚点任职和用户，按当前策略重新验证它仍属于本组织且本人可见；若验证失败，不执行后续查询。按工号、用户 ID 和任职 ID 的键集顺序分批扫描本组织当前任职，锁定候选任职及其用户，逐项执行 `directory_view` 并写决策审计。只读取判定允许的资料，得到 `limit+1` 名可见人员后即可停止，最后一名仅用于计算 `has_more`。

每次请求另写 `directory_organization_members` 审计；不存在和隐藏统一记为 `not_visible`，审计记录不存原始查询参数。判定、资料与请求审计在同一事务提交，任何审计或锁故障不返回部分结果。跨页不是长事务快照：人员调动、策略变更或锚点失效后，客户端应从第一页重新浏览。

## 验收与限制

测试覆盖同组织可见、跨组织及强制拒绝、双任职仅单组织字段、隐藏候选不影响分页、可见/隐藏/失效锚点、跨租户、冻结身份与两类审计故障。HTTP 与签名令牌链路覆盖参数和状态码。初版使用实时策略判定；大组织中大量隐藏任职的最坏查询成本及索引仍待容量测试。
