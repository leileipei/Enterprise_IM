# P2-09 当前任职的单聊会话列表设计

## 目标与范围

P2-08 页面只能打开本次搜索发起的单聊，刷新后无法重新找到已有会话，也无法发现对方新发起的会话。本增量提供当前任职下的可分页单聊列表，并让页面在选择任职、收到实时通知或降级轮询时更新列表。仅展示会话元数据；不新增未读数、消息预览、送达/已读、群聊或跨刷新保存令牌。

## 服务端契约

`GET /api/v1/conversations?limit=20&cursor=<opaque>` 使用现有 Bearer 与 `X-Acting-Membership-ID` 身份校验，无请求体。`limit` 默认 20，允许 1～50；`cursor` 是服务端生成的 URL 安全不透明游标，非法、重复参数或未知参数返回 400。返回 `conversations`、`has_more` 和仅在还有下一页时出现的 `next_cursor`。每项包含 `id`、`type=direct`、`last_seq`、`updated_at`、`peer_visible`；只有 `peer_visible=true` 时才包含对方的 `display_name` 和 `organization_name`。列表不返回消息正文或未读数。

查询只读当前租户、当前用户是参与者、`kind=direct`、`status=active`，且会话中存储的本人选定任职与请求任职一致的记录。按 `(updated_at DESC,id DESC)` 排序，以这两个字段构成游标，页大小取 `limit+1` 判断 `has_more`。游标不承担授权；每页重新校验租户、本人和任职。当前任职无效返回 403。跨租户、非参与者和其他任职的会话不出现在结果中。

迁移为单聊两侧分别建立部分索引，覆盖租户、参与者、选定任职和列表排序键，避免集团中大量不相关会话挤占分页扫描。

对方资料独立按现行 `directory_view` 策略判断。对方任职或账号失效、策略拒绝时，返回 `peer_visible=false` 且没有个人资料字段，页面显示“联系人不可见”；已有会话 ID、序号仍可用于受保护的历史补拉。策略判定与审计、列表请求审计在同一事务内完成；审计不可用则整个请求失败，不降级成未经审计的数据。读取期间锁定策略发布指针及相关人员记录，提交前复核本人任职仍有效，避免同一响应混用新旧策略。发送仍由既有 `send_message` 入口独立复核，不把列表可见性当作发送授权。

## 浏览器交互

选定任职后请求第一页，显示最近单聊和“加载更多”。用户打开一项时从 `after_seq=0` 补拉正文。搜索发起单聊后刷新列表，并打开该会话。`ready` / `sync_required` 实时信号触发列表更新和当前会话补拉；实时不可用时每 5 秒刷新当前列表第一页与当前会话。连续通知合并为串行刷新，慢请求完成时仍先更新页面。列表请求失败保留现有页面内容并显示错误，下一次通知或轮询重试。切换任职或退出清空列表和游标，旧请求响应不能覆盖新任职页面。所有名称以纯文本渲染。

## 验证边界

PostgreSQL 测试覆盖参与者/租户/任职隔离、倒序与游标、策略拒绝后的资料隐藏、任职失效和审计失败。HTTP 测试覆盖查询参数、身份与响应字段。浏览器模拟覆盖登录后已有会话显示、接收方新会话出现、加载更多、切换任职时丢弃旧响应以及实时/轮询刷新。真实 IdP、生产网关与大规模性能仍需部署环境验收。
