# P3-05 群成员移除设计

## 目标和范围

支持群内角色授权的单人成员移除，并保持成员历史区间。使用明确 `interval_id` 定位目标，旧请求重试只返回旧区间结果，不影响目标重新入群后的新区间。群主转让、管理员委派、自动解除 `policy_blocked`、群消息另行实现。

## 接口

`POST /api/v1/groups/{group_id}/removals` 接收严格 JSON `{"interval_id":"<uuid>"}`，拒绝未知、重复或大小写变体字段。首次移除和同一区间重复移除均返回 200，内容为 `interval_id`、`status=removed`、`leave_seq`。无效请求 400，无效当前任职 403，权限不足 403 `group_permission_denied`，群或目标区间不可用 404，移除群主 409 `owner_transfer_required`，审计/存储不可用 503。

## 授权和事务

调用人须为群内活跃群主或管理员。群主可以移除其他管理员和普通成员；管理员只能移除普通成员；不能用移除接口移除自己，须使用退群接口。群主不可被移除。`active` 与 `policy_blocked` 群都允许移除，`ended` 群不允许新的移除。

在同一事务中验证调用人的当前任职，锁住群会话、调用人和目标区间，复核调用人任职有效期，然后把目标区间标记 `removed`，`leave_seq` 记群当前 `last_seq`，`left_at` 不早于 `joined_at`。移除不增加消息序号。成功或明确权限拒绝均写操作审计；审计失败则回滚状态。重试已移除的旧区间返回原结果，不写第二次成功审计。目标新加入后也不能被旧区间 ID 影响。

移除时不自动切换 `policy_blocked` 到 `active`；恢复须在后续群策略复核能力中逐对重新判定剩余成员与当前策略。

## 验收

覆盖群主和管理员权限、策略封锁群、序号截断、重复请求及重新入群、跨租户和其他群隐藏、任职自然到期与审计失败回滚。HTTP 覆盖可信身份、严格 JSON、状态码和内部错误隐藏。
