# P2-08 Web Client Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现授权码登录、任职选择和可操作的基础 Web 单聊。

**Architecture:** Go 同源托管静态页面并代浏览器向固定令牌地址兑换授权码，现有认证器校验所得访问令牌；页面保留令牌于内存，直接调用已有受保护业务接口。

**Tech Stack:** Go 1.27、标准库、现有 JWT/OIDC 认证器、原生 HTML/CSS/JavaScript。

**Spec:** `docs/superpowers/specs/2026-09-29-p2-08-web-client-design.md`

## Global Constraints

- 仅显式启用 Web 和 OIDC 时暴露页面；回调与身份源地址均为 HTTPS。
- 浏览器使用授权码 + PKCE S256；令牌不进入持久化存储、URL 或日志。
- 兑换目标与 redirect_uri 只取服务器配置；只返回经过现有验证器核验的访问令牌。
- 所有业务 API 仍依赖选定任职并在服务器逐次复核。
- 客户真实身份源和生产入口联调不在本地测试覆盖内。

## Review Focus

- 攻击者提供的令牌端点、回调或重复 JSON 字段不得覆盖固定配置。
- 跨源表单或缺失 Origin 不得触发授权码兑换。
- IdP 重定向、超时、超大响应或非 Bearer 令牌不得泄漏数据。
- 页面刷新、切换任职、退出后不得沿用旧令牌或游标。
- 实时故障时仍能补拉，ACK 文案不能误报对方已收。
