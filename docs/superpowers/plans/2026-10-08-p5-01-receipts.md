# P5-01 设备、送达、已读与 Web 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 当前会话由同一实施者逐项实现，不默认派代理。

**Goal:** 交付真实后端支持的本人设备管理、单聊／群消息送达与已读、Web展示和多设备恢复。

**Architecture:** 复用policystore的历史授权事务；短期同步证明绑定实际返回页，逐消息device/user事实保证区间准确及用户去重。回执状态、审计和独立Outbox同事务，WS只通知补拉。

**Tech Stack:** Go1.27.1、PostgreSQL16、现有pgx/Redis/OIDC、原生JavaScript及现有Playwright。

**Spec:** `docs/superpowers/specs/2026-10-08-p5-01-receipts-design.md`

**Status:** 待用户评审规格与计划。复用P4-31固定源新分支，尚无产品实现。

## Global Constraints

- 所有业务数据带tenant；OIDC验证身份来自现有认证器，acting membership实时验证。
- 保留既有消息写入、ACK、UUIDv7、Outbox、历史区间、hard_deny、动态保留与法务保全语义。
- 新增开关IM_RECEIPTS_ENABLED默认为false；关闭时新增路由404，旧消息接口兼容。
- 同步证明有效期固定300秒；每页默认100、最大500；read每批1～500个去重seq；状态批查最多100条。
- 新协议seq、revision与游标以规范十进制字符串传输，范围0～9223372036854775807。
- 逐消息事实为真相；最高游标不替代区间证据；read蕴含delivered，历史合法事实不随撤销设备回退。
- 每设备最多20份未过期证明；64KiB写请求；集团配置使用规格第3节完整默认及范围。
- 不升级go.mod/go.sum；测试真实PG/Redis，缺夹具产生的SKIP不能算验收通过。
- 每任务完成后只提交本任务明确列出的文件；保留其它修改，不自动合并或部署。
