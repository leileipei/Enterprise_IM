# P4-22 服务端上传与可信扫描 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有可信身份及通信边界内，实现文件预约、应用服务端有界上传、固定版本封存、可对账恢复和真实内容扫描。

**Architecture:** 沿用P4-21领域模型；短PG事务负责资格、状态、事件和审计，外部I/O在事务外执行。对象版本与SHA256绑定；人员上传与Worker扫描分别记录来源。以下10项共同组成一条上传／扫描链，每项独立提交和验证。

**Tech Stack:** Go（沿用go.mod的1.27.1）、pgx/v5、PostgreSQL、AWS SDK for Go v2 S3、私有版本化S3兼容存储、ClamAV clamd、qpdf、现有OIDC/API/Redis/Chrome测试基础。

**Spec:** [已确认设计](../specs/2026-10-04-p4-22-upload-scan-design.md)。设计提交359656d；产品基线a6dcd0b（P4-21草稿PR #69）。本计划待审阅，所有复选框尚未实施。

## Global Constraints

- 实施方法已选定：当前助手逐项执行，使用executing-plans；最终独立代码评审。不重复选择执行方式，不合并／部署。
- 复用当前隔离工作树；路径与分支以执行前git核对为准。保留P4-21草稿，在当前`codex/p4-22-upload-scan-design`分支做增量，未来P4-22草稿PR以P4-21分支为base。
- internal/files无SDK／HTTP依赖；P4-21八状态、13边、摘要和来源合约不变。初始version=0，真实状态边每次+1；租约更新不修改file_objects。
- 单文件声明及实测大小1～26,214,400；名称UTF-8 1～255字节且沿用既有校验；规范MIME长度1～127、无参数。首批application/pdf、image/jpeg、image/png、text/plain。
- 持久化默认enabled=false；max_size_bytes=26,214,400（范围1～该值）；upload_ttl_seconds=900（60～3600）；tenant_storage_budget_bytes=1,073,741,824（26,214,400～1,099,511,627,776）；version=0。允许类型非空、排序去重、仅验收通过的首批子集。
- 预算统计所有state!=deleted的声明大小，包含失败和过期预约；锁配置行防超售；降到已预留量以下409。上传重试不重复预留，不延TTL；本轮无删除／预算释放。
- 上传并发4，无排队；扫描并发默认1。接收60s／总I/O150s，上传租约180s／续约15s且不超预约TTL；扫描总90s／租约120s／续约15s。
- 扫描最多3次，失败重试延迟10s／30s；上传对账最多3次（同样10s／30s）。图片最多40,000,000像素，结构Worker512MiB／1CPU；AV库更新时间距当前不超过24h。
- 数据库显式READ COMMITTED；锁后clock_timestamp()复核时间，最多3次纯DB事务重试，外部PUT不得进入重试闭包。
- 锁序：按UUID排序的身份→会话／成员→当前通信策略→上传配置→文件→attempt/job；兼容旧锁序采用NOWAIT／40P01有界重新授权重试。
- S3 key固定tenants/<tenant>/files/<fileID>，单次受控PUT含服务器attempt元数据，禁SDK自动PUT重试；version ID非空且不是null；精确版本完整回读核对大小／SHA，不以ETag代替。
- 预约／封存及人员审计原子；扫描状态／事件／机器审计原子；Worker不冒充人员封存。未知对象保留隔离，不能选latest、重PUT或删除。
- PUT已封存统一409且不读body；未封存恢复只接受原上传者同一原任职重新授权和相同字节。GET仅本人当前原任职／当前参与资格，policy_blocked可查看本人状态。
- DTO大小／version用十进制字符串，时间RFC3339，no-store／nosniff；无key/version ID/sha/job/token/下载URL/扫描原文。401／403／404／409／429／413／415／410／503按设计映射；资格判断优先于资源状态。
- API／Worker部署开关默认关闭，租户开关另行持久化。无依赖跳过不能作为组件验收；真实依赖测试先检查环境，报告实际PASS/FAIL/SKIP。
- 附件发送、下载与保全感知物理清理、Web文件交互／名称搜索分别属于P4-23／24／25；P4-19既有组合预算测试补强留后续。生产发行版、容量／客户IDP验收不由本地联调替代。
