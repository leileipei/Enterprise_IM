### 保留的失败尝试

1. `red` 的速率夹具初次用了非法 sent_count=0，违反 CHECK；不计为有效完整 RED。`red-valid-fixture` 使用合法旧窗口，确认 14 个失败叶子；群速率锁旧实现已有保护，不能将其冒充新发现的失败。
2. 首轮 `green` 产品测试通过，但辅助统计器把包级 PASS 的空 Test 当成数值，导致证据汇总失败；修正统计器后 `green-verified` 重新执行通过。
3. `full-regression` 只配 PostgreSQL / Redis 时实际退出 1：附件正式进程要求 S3、scanner、IAM 等完整夹具，部分入口不使用 SKIP。该失败日志保留，不标为 PASS，也不与后续结果拼接。
4. 新夹具预检首次失败：manifest / 配置须为 0400 而初次为 0600；MinIO 精确版本删除还需要带非空、非 null versionid 条件的 DeleteObject 权限。仅修正本轮夹具，保持产品代码、扫描期限、定义文件和未版本化删除拒绝不变。`fixture-preflight-corrected` 及完整回归随后重新执行。
5. 新候选包首次解包工具的 Python 不支持 tarfile filter 参数；按归档成员路径和类型显式校验后解包，未改变源码。
