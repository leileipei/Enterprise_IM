# 开发增量 P1-02b 验收记录

**范围：**通信策略完整快照发布、当前版本判定和决策审计；设计见 [规格](superpowers/specs/2026-09-28-p1-02b-policy-store-design.md)。

## 已实现

- PostgreSQL 保存租户策略版本、规则、当前版本指针和判定事件；规则引用受同租户外键约束，已发布版本与规则不可修改。迁移可以回滚并重建。
- 数据库阻止当前版本指针改属其他租户，首版必须为 1；发布时检查例外确实覆盖同动作的隔离规则。
- 有效集团管理员以明确的选定任职发布完整快照。事务内核验预期版本、规则审批和例外覆盖关系，再切换当前版本并写管理审计；并发发布只有一笔成功。
- 判定服务从数据库重验两端账号、任职、组织及法人状态，读取当前完整快照后调用既有策略核心。结果包含版本与命中规则，并在返回前写 `policy_decision_events`；审计写入失败时不返回允许。
- 未发布任何策略时使用版本 0：同组织基础允许、跨组织默认拒绝；仍记录判定事件。

## 本地验证

环境：macOS、Go 1.27.1、仅绑定 `127.0.0.1:55432` 的临时 PostgreSQL 16 容器。每个数据库集成测试使用独立 schema。

| 检查 | 结果 |
| --- | --- |
| `IM_TEST_DATABASE_URL=... go test ./... -count=1` | P1-01、P1-02a、P1-02b 全部测试通过 |
| `go vet ./...`、`go build ./...` | 退出码均为 0 |
| 迁移 Down 后重新 Up | 策略版本表删除后可重新创建 |
| 双连接并发发布同一预期版本 | 仅一笔成功，另一笔返回版本冲突 |
| 强制判定审计写入失败 | 服务返回错误，不返回允许结果 |
| 评审回归 | PostgreSQL 拒绝跨租户改写当前版本指针及错误例外发布；跨法人群审批不足时保留命中规则 ID |

## 尚未实现与限制

- 认证适配器与公共管理 API 尚未接入。发布服务与判定服务只供内部已验证的调用方使用；`ScopeAllowed` 和 `ResourceActive` 由未来业务入口负责正确计算。
- 没有缓存、跨节点策略广播和撤权时延测试。当前每次判定查询 PostgreSQL，生产容量和延迟尚未验证。
- 尚无策略编辑界面和审批工作流；申请人、审批人和原因由已验证的上游流程提供，数据库保存并约束引用。不能将字段存在误称为已完成审批流程。
- 未使用客户真实或脱敏组织数据做端到端验收；SSO、消息和客户端仍未实现。
- 独立评审的两项重要约束缺口和一项审计可解释性问题已通过先失败、后通过的测试修正；本地验证未覆盖跨节点并发或生产数据库权限模型。
