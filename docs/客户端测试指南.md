# Enterprise IM 客户端测试指南

更新日期：2026-10-18。适用于已批准的 P5-02 测试阶段。

## 1. 当前可测试范围

已有固定源码的本地 Go 全量／race、Python及17项集成门禁结果；移动端另有 API24／API36 和 iOS 模拟器连接生产 Go 后端的专项结果。详见[四平台验收状态](P5-02-四平台客户端验收.md)。历史通过仅属于各报告列出的源码、平台和夹具，不自动覆盖当前代码或客户环境。

用户本轮明确暂缓两台真机验证。它仍是待验门禁；Windows实际运行、客户SSO、iOS真机签名安装、正式签名／分发及远端CI分别保留。测试包使用临时测试签名，禁止作为正式发行包。

## 2. 离线证据核验入口

`scripts/test-native-clients.py` **只核对本地证据合同与文件完整性，不构建、不安装、不发消息、不启动平台测试，也不认证证据生产者**。其通过结论必须与可信runner及原件复核一起使用。不能用手写“passed”替代运行证据。

```sh
python3 scripts/test-native-clients.py \
  --source SOURCE_COMMIT_FROM_INPUT \
  --manifest docs/verification/p5-02-acceptance-input.json \
  --output /private/tmp/enterprise-im-native-acceptance-new.json \
  --defer-physical
```

将 `SOURCE_COMMIT_FROM_INPUT` 替换为输入文件的完整 `source_commit`，不能使用浮动分支名。每次使用一个不存在的输出文件；已有输出和符号链接均不覆盖。

| 退出码 | 含义 |
| --- | --- |
| 0 | 输入合同中四平台及跨设备门禁均满足；仍不代表客户／生产放行 |
| 2 | 证据缺项或真机暂缓，四平台验收未完成 |
| 1 | 输入无效、源码／摘要不匹配、命令失败、测试失败／跳过、清理不成立，或无法创建输出 |

`--defer-physical` 只把缺少的真机用例标为 `deferred`，不能删除门禁，也不会把失败转为通过。当前输入不包含新的同源四平台完整运行证据，因此预期退出 **2**。

## 3. 证据输入约定

输入schema为 `native_acceptance_input_v1`：`source_commit` 是Git中存在的完整40位提交；`platforms` 按 macos、windows、android、ios分开；`historical_reports` 仅作历史原件完整性目录。路径相对仓库根目录，引用形式为 `{ "path": "相对路径", "sha256": "64位小写摘要" }`。拒绝绝对路径、父路径跳转、路径中的符号链接和重复JSON键。

平台记录包括固定 `architecture`、应用归档 `artifact`、`build_mode`、`artifact_target`、单列的 `signing` 声明和 `cases`。macOS／Windows／Android的build用例必须是release。需要不同产物的用例通过 `case_artifacts` 单列 `{artifact, build_mode, artifact_target}`，不允许未定义用例覆盖；iOS模拟器和设备必须使用不同摘要，目标分别为 `ios_simulator`／`ios_device`，不能强迫两者共享同一Mach-O。签名声明不是密码学签名验证；iOS真机证据必须另外证明签名安装。应用归档须由对应构建runner预先检查没有私钥、凭据或临时身份资产；本入口只核对归档摘要，不扫描归档内容。

每个平台要求 build、launch、oidc、text、files、receipts、storage、lifecycle、recovery、groups、revocation、retention；移动端还需 simulator 和 physical。平台用例schema为 `native_case_evidence_v1`，固定提交、平台／架构、SDK提交与源码归档摘要、pubspec.lock摘要、构建模式／目标与当前应用摘要必须相符。输入顶层的 `backend_source_commit` 必须是仓库中存在的完整Git提交，业务用例和跨设备证明必须与它一致；这只是预期输入绑定，不能据此声称该后端本轮已运行。源码中的工具链锁与pubspec.lock从指定Git提交读取，不采用工作区临时修改。

用例必须保留非空命令参数、真实整数 `actual_exit`、stdout／stderr文件摘要、正数通过数量及零失败／错误／跳过、已完成的清理及空失败列表。业务用例必须连接生产API；平台原生用例不能以shared环境替代。桌面恢复需两次原生重启；真机需 `hardware=true`、硬件身份摘要及生产API上的生命周期、回执、安全存储三项，iOS另需签名安装证据。SDK版本相同而提交／文件不同、布尔false冒充退出0、只有共享测试通过都不合格。

跨端schema为 `native_cross_device_v1`：至少Alice一个设备、Bob两个不同设备／独立进程，且至少两个账号；检查发送、设备送达、已读、断线、重启、丢ACK、回执重试、退出、撤销、权限和保留期变化。参与者至少关联两个组织，必须明确验证跨组织群；每个参与者必须绑定平台／架构、SDK提交／归档摘要、锁文件、构建模式／目标和当前平台记录中的应用摘要，不能借用另一平台或旧版本结果。

原始命令行可能包含敏感数据，应由runner在采集阶段使用既有脱敏／原件处置流程。核验输出不复制原始命令行、正文或异常内容；不要把客户令牌放入JSON、终端历史或仓库。

历史目录检查报告本身及它声明的 `raw_evidence_sha256`。没有该原始清单时，只验证报告文件，不能声称其全部附件已审计；历史结果永不满足当前源码的用例门禁。

## 4. 实际平台运行入口

移动构建与已有模拟器专项：`python3 scripts/build-client-mobile.py --help`。`--verify-real-backend` 目前要求自有模拟器，两个身份仍在同一原生测试进程，**不能拿来完成双真机验收**。完整准备及清理约束见[移动端验证操作](P5-02-移动端验证操作.md)。

桌面使用已有 `scripts/build-client-macos.sh`／`scripts/build-client-windows.ps1` 及原生集成入口；Windows必须在实际Windows runner运行。不能通过修改平台标签把macOS输出算作Windows结果。共享测试和宿主widget集成保留为独立层。

移动入口现在支持 `--export-acceptance`：仅在实际运行与清理成功后，创建输出目录下的 `acceptance/`，不覆盖旧目录。输出目录必须位于本仓库内，路径不能含符号链接。原始 `result.json`／preflight／日志／产物继续保留；导出失败使整轮退出非零。已准备工具目录的调用示例（在仓库根运行，替换绝对路径）：

```sh
python3 scripts/build-client-mobile.py --target android \
  --flutter-sdk /ABS/FIXED_FLUTTER --pub-cache /ABS/PUB_CACHE \
  --android-sdk /ABS/ANDROID_SDK --java-home /ABS/JDK --gradle-cache /ABS/GRADLE \
  --verify-simulator --simulator-runtime 'system-images;android-36;default;arm64-v8a' \
  --simulator-device-type pixel_7 \
  --output /ABS/REPO/.superpowers/NEW_ANDROID_RUN --export-acceptance
```

iOS使用 `--target ios-simulator`、相同固定Flutter／pub-cache、明确的 `--developer-dir` 和新的仓库内输出目录；未传 `--verify-simulator` 时只构建模拟器目标，不证明运行。iOS ZIP排除资源分叉、扩展属性、隔离信息及ACL附带记录，必须与应用文件清单逐项一致。

| 已有移动runner输出 | 统一合同可接入用例 | 保留边界 |
| --- | --- | --- |
| Android普通Release APK | build；有完整实际安装／启动观察时另含launch | 临时测试签名，非客户发行 |
| iOS Debug模拟器应用ZIP | build；有同归档普通包完整安装／启动观察时另含launch | 非真机包，启动不代替业务或签名门禁 |
| Android Debug驱动的活动／两进程安全存储 | 原样保留专项结果 | 不能映射到另一个Release APK的storage／lifecycle等用例 |

导出核对固定提交的完整客户端输入和runner实现输入、SDK／锁文件、必填上游摘要、精确工具与命令参数、归档内容、实际退出及清理；Android launch另外核对设备／包名／安装路径／APK／PID／完整PNG及停止观察。iOS记录并复核实际Flutter snapshot和完整Debug iOS engine缓存清单。`count_basis=runner_checks` 表示这些证据核对数量，不能加进框架测试数量。预期的 Android `pidof` 或 iOS `ps` 退出1只用于确认应用已停止，保留为单独观察，不能当作业务命令成功。iOS启动按安装→路径→启动→两次进程观察→截图→停止→消失的实际顺序保留；进程观察固定UTC／英文，避免宿主时区造成错配。必须同时确认所属模拟器删除。主机确认进程消失不等于独立取得应用的OS退出码，该字段仍为unknown。

读取两个完成目录时用 `--runner-output` 替代 `--manifest`，可重复传不同平台；同平台重复、不同提交、候选源码覆盖、缺失摘要、改动日志或清理缺项均拒绝：

## 5. 真机恢复验收时

两台Android手机连接并解锁，开启USB调试并确认授权后，先核对两个不同硬件设备及API／ABI／安装包指纹。每台只运行自己的身份与原生进程。依次验证A→B和B→A：服务器ACK、已送达但未读、实际可见后的已读，并独立查询数据库。

断开接收端的测试连接后，由发送端新增消息；确认断线期间没有新增送达／已读。恢复后先验证设备，再补拉、确认送达、按真实可见性已读，检查连续游标、无漏消息／重复消息和发送端回执恢复。USB转发中断只证明应用连接中断，不能宣称蜂窝网络、飞行模式或系统断电已验收。

只有本轮自有的转发、测试账号数据、安装产物和服务可清理；不得重置用户手机、覆盖已有客户数据或结束其他会话的服务。

## 7. 跨端独立进程群聊、附件及设备失效（2026-10-19）

[本轮结果](verification/p5-02-cross-process-group-files-devices-results.json)绑定固定源 `c61194d9fe07d10ae6c6e24f04c6e8af5d63ca6b`。两台自有 Android API36 AOSP ARM64 模拟器与一台 iOS26.5 iPhone17Pro 模拟器运行三个独立进程／设备；Bob 的 Android 和 iOS 属于同一用户。连接真实产品 API、Outbox／Receipt／File Worker、官方下载审计修复进程，以及 PostgreSQL、Redis、MinIO、绑定实际签名库的 ClamAV。身份源为本地合成刷新服务，联测包为带测试入口的 Debug 包。
