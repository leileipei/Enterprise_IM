# P4-19 跨会话文本搜索 API 验收记录

## 范围与合约

按用户确认设计完成普通员工跨本人历史单聊／群聊的文本搜索 API。管理员不增加参与权限；当前有效任职独立授权，历史会话允许旧任职、退群／再入群以及 ended／policy_blocked 状态；每条正文仍按历史关系、发送者证据、hard_deny、保留期和清理状态过滤。法务保全不延长正文可见期。

`GET /api/v1/messages/search?q=关键词&kind=all&limit=20&cursor=...`

- 仅在生产 im-api 配置 OIDC 时注册；可信租户／用户来自令牌，任职按现有可信请求合约解析。
- q 使用 Go TrimSpace＋简单 Unicode 小写，2～100 码点，字面子串匹配；kind 为 all／direct／group，limit 为规范十进制 1～50；游标最多 2048 字节，严格规范编码并绑定身份／任职／词／kind。
- 返回每条 conversation_id、conversation_kind、id、字符串 seq、sender_user_id、text、server_time；messages 为空时为 []。不返回名称、隐藏占位、候选列表或总命中数。
- 每页最多处理 20 会话、合计 500 条消息；每会话最多额外 1 条 lookahead，实际消息 SQL 返回最多 520 行。三候选流各最多 21 ID，合并最多 21，服务接收来源 ID 最多 63；群区间底层扫描不受 63 行限制。
- 会话 UUID 升序，内部 seq 升序。within／after 游标安全推进，进度不授予授权。结果满 limit 时允许下一页为空；客户端须查询至 has_more=false。无跨页快照，已走过区域新消息需要刷新首页。
- 一个 READ COMMITTED 事务和共同 5 秒 deadline；事务局部 statement_timeout=4s／lock_timeout=1s。40P01／40001 最多重试 2 次，全部尝试共享 deadline。
- 暂存正文最后以同一新时点重新过滤；身份失效、数据库／审计／提交失败返回零值页。成功页一次 message_search_all allow 审计，可信 tenant 资源、cross_conversation_search_page 原因，不保存关键词／正文／查询串。
- HTTP 400／401／403／503／405，405 Allow=GET；no-store，未知路径回交原 handler。拒绝未知／重复参数、GET 正文、坏编码、空／过长游标以及非法 kind／limit。

## 数据库与兼容性

000017 Up 添加 direct low／high 的 `(tenant_id,participant_id,id)` 部分索引；Down 只移除这两个索引。真实 Up／Down／再次 Up 检查会话及已存正文保留。群使用既有历史区间索引，消息使用既有 keyset 索引，无正文副本或全文投影。

旧单会话补拉／搜索包装器保留原审计、错误、事务及序号合约，共用私有历史读取／最终过滤助手。新 API 不修改现有 Web 界面或消息同步游标。

| 查询 | 实际返回／扫描 | 执行时间 |
| --- | --- | --- |
| direct candidate keyset | 主键 Index Scan 返回 21 ID | 0.016 ms |
| group candidate 去重 | Seq Scan 扫描 100 个历史区间，去重成 1 个候选；另过滤 1 区间 | 0.023 ms |
| message keyset | 既有消息唯一索引返回 10 行 | 0.016 ms |

日志 `/private/tmp/enterprise-im-p4-19-task3-green.log`。此处是小规模本地查询样本，不是端到端生产 SLA；不强制 planner 使用新增索引，群历史区间成本仍受 deadline 限制。上线索引窗口、真实租户数据分布和生产容量留部署评估。
