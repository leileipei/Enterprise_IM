## API 与数据边界

- `GET /api/v1/admin/audit-events` 新增可选 `actor_user_id`，完整 UUID 精确匹配，大小写归一为小写。省略时查询全部；显式空值、重复、首尾空白、缺失连字符及非法值返回 400。
- 与 `action`、`outcome`、`limit`、`cursor` 组合使用，默认 20 条、最多 100 条。内部 `AuditEventFilter` 统一承载筛选，避免继续增加位置参数。
- SQL 始终限制当前可信身份的租户；执行人作为 UUID 参数使用，不进行人员存在性查询。不存在或其他租户执行人返回同样的空数组，不能借筛选改变查询租户。
- 游标绑定租户、动作、结果、执行人及 `(occurred_at,id)` 边界。执行人改变、增加或取消后不能复用旧游标；大小写等价的执行人可续页。执行人为空时省略新增游标字段，保留旧版游标格式与可用性。
- 保持任职优先锁顺序、READ COMMITTED、新鲜时间权限复核、查询审计原子提交和提交前授权复核。每页仍要求有效集团管理员；审计失败或权限到期不返回页面数据。

## Web 行为

- 管理审计弹窗增加“执行人用户 ID”，留空查询全部；按完整 UUID 精确查询。非法输入在页面提示且不发送 API 请求。页面与 API 均接受 UUID 大小写。
- 输入变化立即清空记录、游标和已见游标集合，作废旧请求；点击查询从首页开始。刷新和加载更多携带当前执行人筛选。
- 对返回事件逐条核对执行人 ID；与筛选不匹配时拒绝整个页面并清空。保留 bigint 字符串、纳秒顺序、跨页去重和循环游标防护。
- 关闭、Esc、切换任职清空执行人等筛选；权限失效禁用输入和入口；401 沿用退出。未知结果的保留期／保全写入保护保持。

## 验证记录

- HTTP 用例实现前返回 400，失败指出新增执行人参数不被接受；真实数据库用例实现前将另一执行人事件 11 混入第一页，期望事件 10，实际失败。
- 实现后目标 Go 用例通过：同租户不同执行人隔离、过滤后续页、游标执行人不匹配拒绝、未知／其他租户执行人空结果、非法 UUID、不成功查询不新增 allow 审计，以及原有权限撤销、锁等待到期和审计写入失败回归。
- Chrome 使用生产 HTML／JS，新增输入用例先因缺少输入失败；实现后验证含字母大写 UUID、21 条执行人记录两页、无效输入不请求、空结果、响应执行人逃逸拒绝、输入改变后迟到响应不能恢复旧执行人记录。
- 既有审计浏览器异常 DTO、精度、超时、游标循环、权限、关闭／身份／其他筛选变化和待确认写入保护继续覆盖。
- 双生产 im-api 用例用执行人筛选读取允许事件并在另一节点续页，执行人变更后旧游标返回 400。真实 HTTPS OIDC、PostgreSQL、Redis 和 Chrome 流程在页面按实际执行人筛出允许／拒绝事件，数据库核对 3 条 allow 查询审计。
