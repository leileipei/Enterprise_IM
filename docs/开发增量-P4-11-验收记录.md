# P4-11 保留期审批历史查询

## 范围与基线

承接 P4-10 Web 保留期配置，基线 `12c69fe7b12ca0e33557bee6eaff6e5748a7a159` / 草稿 PR #57；分支 `codex/p4-11-retention-history`。复用已有不可修改表 `tenant_retention_policy_history`，新增集团管理员只读历史 API 和现有配置弹窗中的历史列表，无新增数据库迁移。

## API 与分页契约

- `GET /api/v1/admin/retention-policy/history`，可选 `limit` 默认 20、范围 1～100；可选非空 `cursor`。拒绝未知／重复／格式错误参数、非规范十进制 limit、GET 请求体和其他方法。
- 响应为 `history` 数组与 `next_cursor`。每条包含 `message_body_days`、`version`、`approval_reference`、`approved_by_user_id`、`approved_at`；空历史返回 `[]`。不返回正文、摘要或客户端消息重试键。
- 按版本降序做 keyset 分页；游标绑定租户和最后返回版本，采用规范 Base64URL JSON 格式并限制长度。游标不是授权凭据，每次查询独立检查权限。跨租户、未知字段和非规范游标均被拒绝。
- 仅返回成功提交的变更审批记录。版本 0 默认配置不虚构审批历史；失败或拒绝的变更应查审计，不会出现在本列表。
- 每页使用独立事务，不提供跨请求共享快照。翻页只读取更早版本，翻页期间新增版本需刷新首页查看。

## 身份、权限与审计

- 使用生产 API 既有可信身份认证；组织／部门管理员没有租户级读取权限。401 表示认证失败；非集团管理员或已撤销授权不返回历史。
- 显式 READ COMMITTED；先锁执行任职，再按现有授权解析锁定租户、账户、组织、法人及授权记录，保持任职在租户之前的顺序。租户保留期版本用共享锁读取，防止在单页读取中变更。
- 锁等待后、查询后、审计写入后均用新时间检查身份与授权期限。审计 I/O 后失效时回滚允许事件，不返回数据。
- 成功查询与 `retention_policy_history_list` / `listed_approval_history` 允许审计同事务提交；审计失败返回错误，不返回历史。此审计表示已授权查询，不证明用户实际阅读了每条记录。

## Web 行为

- 在“消息保留期配置”弹窗展开“查看审批历史”，每页 20 条；支持刷新首页和加载更多版本，审批时间按本机时区显示。
- 只读显示期限、版本、审批引用、登记人和时间。沿用严格 DTO 校验，要求正版本、真实日历 RFC3339 时间、跨页严格降序及一致游标；引用使用 textContent，不能执行 HTML。
- 单次请求等待上限 15 秒。读取失败清空全部已显示记录和游标，刷新从首页重试；不保留半页结果。默认配置明确没有变更审批历史。
- 折叠、关闭、身份切换、配置刷新／写入均清空历史并废弃迟到响应。写入与未知结果核对沿用 P4-10 状态机，历史读取不会自动发起保存或回滚。
- 403／404 清空配置与历史并禁用入口；401 沿用强制退出。旧身份或旧弹窗的回复不能重新填充页面。
