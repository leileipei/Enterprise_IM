# P4-06 管理员清理批次查询

## 已确认范围

用户已确认按会话查询正文及摘要清理证据，复用集团管理员授权、可信身份、分页与审计。基线为 P4-05 提交 `9eba481` / 草稿 PR #52；本增量分支 `codex/p4-06-retention-batch-query`。沿用已有隔离工作区，无新增迁移。

## API 合约

`GET /api/v1/admin/conversations/{id}/retention-batches?kind=body|digest&limit=100&cursor=...`

- `kind` 必填；limit 为 1～500，默认 100；cursor 原样传回。拒绝未知、重复、空游标参数与 GET 正文。
- 请求使用 Bearer 访问令牌与 `X-Acting-Membership-ID`。租户与操作者来自认证，不接受请求字段声明。
- 当前有效集团管理员可查询本租户任意单聊／群聊会话；普通员工和组织管理员无此权限。身份失效 403；无权限、跨租户、不存在会话 404；格式错误 400；数据库或审计失败 503。
- 返回 `batches` 与 `next_cursor`，空页为 `[]`，末页游标为空字符串。响应 `Cache-Control: no-store`。
- 公共字段：id、conversation_id、kind、processed_at、processed_count、first_seq、last_seq。正文批次附 retention_days、cutoff_at；摘要批次附 min_expires_at、max_expires_at。
- 时间对应数据库原批次记录；按 `(processed_at,id)` 倒序，游标绑定租户、会话、类型。同时间用 UUID 打破排序平局。页间无共享快照，新增批次须刷新首页核查。

## 实现与授权判定

查询使用已有两张不可修改的批次证据表及其会话索引，选择固定 SQL，不把请求值拼入 SQL。每次事务显式 READ COMMITTED。沿用当前管理员服务的锁顺序，先锁任职和授权、再 SHARE 锁会话；锁等待后及结果读取后重新按当前时间验证身份和授权。

`retention_batches_list` 审计与读取同事务；成功原因区分 `listed_body` / `listed_digest`。审计或事务提交失败不返回结果。拒绝按现有管理员契约记录拒绝审计。HTTP 不返回或记录原始数据库错误、连接 URL、正文或摘要。
