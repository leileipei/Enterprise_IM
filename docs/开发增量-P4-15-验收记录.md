# P4-15 按时间区间筛选管理审计

## 基线与范围

基于 P4-14 `a17a54c0b61237f7db0de19584a56ed6fc4bab3e` / 草稿 PR #61；分支 `codex/p4-15-audit-time-filter`。扩展现有管理审计查询 API、Web 弹窗及验证，不新增迁移或写入操作。

## 时间契约与分页

- `GET /api/v1/admin/audit-events` 新增可选 `from`（包含）和 `until`（不包含），即 `[from, until)`。可只传一端；省略不限时间，显式空值和重复参数拒绝。
- 时间须为 RFC3339，包含 `T`、秒及显式时区 `Z` 或 `±HH:MM`，小数秒最多 6 位。真实日历、时分秒及偏移均须合法，原始年份及转换后 UTC 年份限定 1～9999。拒绝无时区、逗号小数、7 位以上精度、闰秒、相等或倒置区间。
- 微秒精度与 PostgreSQL timestamptz 一致，筛选边界不会被舍入至另一时刻。既有事件 DTO 与 Web 排序仍保留原始 RFC3339 小数精度及 bigint ID。
- 与执行人、动作和结果筛选组合使用；SQL 始终限制可信身份租户，增加 `occurred_at >= from` 和 `occurred_at < until` 参数条件。
- 游标绑定规范化 UTC 的时间区间及既有租户／执行人／动作／结果。时区写法、等价尾随零不影响续页；改变、增加或取消时间边界后必须从首页开始。没有时间筛选时省略新游标字段，原有旧版游标兼容。
- 保留任职优先锁顺序、READ COMMITTED、逐页新鲜时间权限复核、查询审计原子提交及提交前授权检查。

## Web 行为

- 弹窗增加开始／结束时间输入，标签明确包含／不包含，提供带时区示例并说明可只填一端。使用文本输入以明确时区，不隐式推断用户本地时区。
- 非法时间及相等／倒置区间仅在页面提示，不请求 API。空端不发送参数；URLSearchParams 对正偏移中的 `+` 进行正确编码。
- 用 BigInt 时间键比较微秒边界，避免 Date.parse 毫秒精度吞掉差异。响应包含区间外事件时整页拒绝并清空。
- 时间输入变化即清空记录、游标和已见游标集合；请求代次与原始输入共同隔离迟到响应。关闭、Esc、任职变更清空时间；权限失效禁用输入。未知结果写入核对保护保持。

## 验证记录

- HTTP 新参数用例先返回 400；真实数据库区间用例先错误返回结束边界上的事件 12；非法时间 `bad` 在旧实现被接受。这些失败均已实际观察。
- 后端目标验证通过：微秒开始／结束边界、三页无遗漏续页、等价 +08:00 与 Z 游标、改变任一边界拒绝旧游标、单端／空结果、组合结果筛选、非法日历／时区／精度及相等倒置区间；失败输入不产生 allow 查询审计。
- 自查将“早于开始时间”异常改为修改末条记录时间，以保持页面原有倒序及去重条件；临时移除前端开始边界核对后，Chrome 错误接受并显示 20 条，实际用例失败。生产检查已在 finally 中恢复。此用例独立证明区间检查，不依赖排序错误拒绝。
- Chrome 使用生产 HTML／JS，新增用例先因缺少时间输入失败；实现后 21 条微秒区间记录两页通过，非法输入不请求，结束边界及开始之前事件拒绝，时间变更后迟到响应不能恢复旧列表，单端／空结果／关闭重开通过。原有执行人、精度、循环游标、异常 DTO、15 秒超时和身份／权限回归继续覆盖。
- 双生产 API 用例增加时间区间并跨节点续页，改变结束时间后旧游标拒绝。真实 OIDC 浏览器在页面填写时间区间并结合实际执行人筛出允许／拒绝事件，查询审计计数继续核对。

## 既有并发测试修正

最终重跑出现 `TestDigestProcessTenantHoldsAndConcurrency/two_workers` 合计处理 1 条、预期 2 条的间歇失败。原测试未协调两个 goroutine 的锁重叠；Worker 单次选择候选后会新鲜复查，允许空批次，单次调用不能保证未协调调度下立即覆盖所有会话。原目标重跑 20 次均通过，不能以重跑结果抹除这次失败。

改为受控重叠：第一 Worker 在记录批次证据前暂停并保持会话 A 锁；第二 Worker 必须真实跳过 A 并处理 A2 一条，随后释放第一 Worker 并核对处理 A 一条。保留两条消息／幂等摘要、匹配退休时间及两个批次证据断言；5 秒 context、sync.Once 幂等关闭释放通道，以及带 context 的结果等待保证可退出。独立评审指出原无缓冲释放 send 在超时后可能无人接收，已按上述方式修正，复核无剩余发现。修改只涉及测试，生产清理逻辑没有变化。受控目标重复 20 次通过，独立复核确认精确断言保留、释放异常路径已修正；最终全量结果见下。
