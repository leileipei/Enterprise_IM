## 原生登录服务

默认关闭 `IM_NATIVE_ENABLED`。开启时必须同时开启 OIDC、设备回执，并先完成数据库迁移000026。启动与就绪检查要求原生请求窗口结构、已验证约束及 SELECT/INSERT/UPDATE/DELETE 四项权限完整；只读账号不能通过。

显式配置以下参数：

- `IM_NATIVE_ENABLED=true`
- `IM_NATIVE_AUTHORIZATION_URL`、`IM_NATIVE_TOKEN_URL`：运营配置的 HTTPS 地址，不由请求决定。
- `IM_NATIVE_SCOPE`：默认 `openid profile`，必须含 `openid`。
- `IM_NATIVE_<WINDOWS|MACOS|ANDROID|IOS>_CLIENT_ID`：四个独立公共客户端，全部须已列入现有 `IM_OIDC_ALLOWED_CLIENT_IDS`。
- `IM_NATIVE_<平台>_REDIRECT_URI`：桌面固定模板 `http://127.0.0.1/oauth/callback`，实际兑换必须带当次动态端口；移动端精确值 `com.enterpriseim.client:/oauth/callback`。
- `IM_NATIVE_<平台>_REFRESH_ENABLED`：默认 false，只有身份源支持时显式开启。

接口为 GET `/api/v1/native/config?platform=...`、POST `/api/v1/native/oauth/token` 与 POST `/api/v1/native/oauth/refresh`。原生入口关闭时返回404。兑换/刷新请求 JSON 最大4KiB，身份源响应最大32KiB；5秒总预算、每进程20并发、跨节点共享每IP每分钟20次，超限429带Retry-After。仅保存规范化IP摘要与限额窗口，不保存原始IP、OAuth code或令牌。

首次兑换验证ID令牌签名、issuer、平台audience、azp、nonce及到期，再验证API access令牌及本地有效人员映射。刷新允许身份源不返回ID令牌；若返回，仍验证签名、audience、到期和subject绑定。响应使用已验证的access令牌到期时间，忽略身份源未验证的expires_in；不回传ID令牌，不转发身份源原始错误。不含新refresh_token时，客户端保留原值。

### 单调租约时钟

新增内存LeaseClock基线：从可信server_time与请求开始的单调时间保守扣除耗时，缓存上限遵循现有Go策略的0～3600秒。零缓存、到期等号、时钟回退、显式失效及重启均不给旧授权；不读取系统壁钟恢复阅读。26项共享测试实际退出0，静态分析无问题，见`verification/p5-02-task3-lease-clock-results.json`。该时钟检查点尚未接入消息数据库与认证会话；后续集成见下文，不能据此单独认定完整客户端验收。

### 原子同步页与认证后恢复检查点

新增强类型PendingSend/PendingReceipt/StoredMessage。正文、连续游标与每页pending proof在同一真实SQLite事务中提交；触发器模拟写入失败时三者全部回滚。多个同步页的证明分别保留，旧receipt_revision、断页或代次不匹配拒绝推进游标。重新授权已提交页不会降低已有游标。

阅读权限由本进程内成功提交页注册的单调LeaseClock决定，数据库中的cache_until不能直接授予权限；换进程或伪造一个日期相同的时钟不能解锁旧缓存。零缓存页只持久化游标/证明，不保存正文。新遮蔽页先撤销旧内存阅读权限，即使磁盘事务失败、旧密文尚存，也不可继续显示旧正文。在线零缓存显示及5秒授权将在Task4内存同步引擎接入。

SessionStore只在新认证有效后打开账号库；access JWT保持内存。数据库密钥、refresh和device凭据放在同账号的一条系统安全存储bundle中，避免部分轮换混用。安全存储明确返回缺失才清除不可读数据库并生成新密钥；安全存储不可用或bundle损坏会报错，既有数据保留，不降级明文。退出即时阻断数据库迟到结果，等迟到凭据写入完成后删除bundle与数据库；关闭/失败清理会清零持有的密钥字节副本。

## 同步、设备送达与可见已读核心检查点（Task4未完成）

实现ClientContext的账号/任职/会话/设备/代次绑定，以及严格设备请求头和回执状态DTO。每次调用处理一个完整连续同步页，先提交密文正文、游标、pending proof，再PUT delivered；成功后删除已确认页的pending记录。断页或本地事务失败不能发出delivered；503保留相同proof，410证明过期重拉原扫描区间，已提交游标不倒退。重启有未确认页时从0安全重放，不猜旧分页大小；同上下文并发请求合并，停止后丢弃迟到响应。

ReceiptQueue仅接受引擎成功送达的结果作为本机阅读资格。要求前台、焦点、激活会话、非预览/弹窗、至少50%可见连续500ms，再等待300ms合批；精确seq排序，每批上限500。测试确认请求不得早于完整800ms，没有提前容差。焦点、后台、弹窗或上下文变化会中断连续曝光并取消旧批次；返回的用户read_seq不会自动把其它消息或其它设备状态记成本机已读。当前测试使用注入的跨设备用户游标边界，不替代真实两台原生客户端验收。

设备/身份失效、hard_deny、sync_context_changed或扫描缺口会停止旧上下文并清除接收正文记录、游标与证明，保留待确认发送队列；采用账号范围的保守清理，后续重新同步。租约到期锁定显示，并提供正文记录清理；旧清理按opaque key及已观察nonce删除，不能删除并发重新授权的新密文。RetryPolicy区分重登、停止、重新同步、业务冲突、到期和重试，429遵循Retry-After，退避1～30秒；断线/健康连接轮询间隔策略分别为5秒和30～40秒。
