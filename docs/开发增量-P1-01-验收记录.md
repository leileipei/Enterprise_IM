# 开发增量 P1-01 验收记录

**范围：**集团基础模型与通信边界判定核心。需求依据为 v2.2 第 3、5、6、11 章；具体边界见 [首增量规格](superpowers/specs/2026-09-28-group-foundation-design.md)。

## 已实现

- Go 工程与本地 Git 开发分支；远程仓库为 `leileipei/Enterprise_IM`。
- PostgreSQL 16 迁移：Tenant、Legal Entity、Organization、Department、User、组织任职与部门任职。
- 数据库约束：同租户外键、运营组织法人归属、虚拟节点不得任职、组织和部门层级禁止循环、任职区间不重叠、同一时点主任职唯一、部门归属及有效期包含；反向更新也不能破坏部门任职区间。
- Go 通信策略判定：未知操作、跨租户和失效任职拒绝；hard_deny 优先且记录所有命中规则；已审批、定向且有期限的 exception_allow 只能覆盖引用的隔离规则；跨组织默认拒绝、跨法人群须显式审批。
- 仅健康探针的 API 进程，`GET /health/live` 和 `GET /health/ready`。

## 本地验证证据

测试环境为 macOS 本机、Go 1.27.1，以及仅绑定 `127.0.0.1:55432` 的临时 `postgres:16-alpine` 容器。数据库集成测试对每个用例创建独立 schema。

| 检查 | 命令或操作 | 结果 |
| --- | --- | --- |
| 完整测试 | 设置 `IM_TEST_DATABASE_URL` 后运行 `go test ./... -count=1` | 数据库约束、迁移回滚重建、策略和 HTTP 测试通过 |
| 静态检查 | `go vet ./...` | 退出码 0 |
| 正常数据库探针 | 实际启动 `go run ./cmd/im-api` 并请求 `/health/live`、`/health/ready` | 两个接口均返回 HTTP 200 |
| 数据库故障探针 | 服务连接不可达的本机数据库端口，重新请求两个探针 | live 返回 HTTP 200；ready 返回 HTTP 503，不泄露连接细节 |
| 迁移原子性 | 在临时数据库向迁移中插入除零错误，用 `psql -v ON_ERROR_STOP=1` 执行，再查询 `to_regclass('public.tenants')` | 命令退出码 3，表不存在；有效迁移重试成功 |

上述验证只证明当前本地增量。未进行第 14 章容量、延迟、可用性和灾难恢复验收，也未接入客户真实身份源和组织数据。

## 尚未实现与限制

- 尚无登录、SSO、角色授权、组织/任职管理 API、管理后台和通讯录界面。策略判定接收已鉴权的任职、Scope 和资源状态；调用方必须在后续增量提供并验证这些输入。
- 尚无策略表、版本发布与审计持久化。当前策略由纯函数接收规则列表，不能作为可配置管理能力交付。
- 尚无会话、消息、WebSocket 推送、客户端、文件、搜索、Redis、MinIO 和高可用部署。
- `/health/ready` 只验证数据库连接，尚不校验迁移版本或其他未来必需依赖。
- `btree_gist` 扩展的首次安装需要数据库权限；生产迁移和回滚须按部署流程审批，不应直接对有数据的环境执行 Down 脚本。
