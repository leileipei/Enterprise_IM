# P4-07 Web 清理记录查看

## 已确认范围

基线为 P4-06 `1005d4d` / 草稿 PR #53；本增量分支 `codex/p4-07-web-retention-records`。用户已确认在既有会话界面加入清理记录查看，使用当前任职的集团管理员权限，提供正文／摘要切换、分页、刷新，并防止身份及会话变化后显示旧结果。沿用隔离工作区，无新增数据库迁移。

## 实现

- 新增独立只读 `retention.js`，生产资源随 Go API 嵌入；沿用同源脚本、CSP 与禁止缓存响应头。
- 使用既有 `GET /api/v1/admin/retention-policy` 核验选定任职。普通员工／组织管理员不显示记录入口；网络／5xx 失败显示权限检查重试按钮。入口不是服务端授权凭证，每页仍由 P4-06 API 核验并提交审计。
- 仅查询当前选中的单聊／群聊，`kind=body|digest`、`limit=20`，游标原样回传。切类型或刷新回首页，下一页追加；没有跨页共享快照。
- 展示批次 ID、处理时间、实际数量、序号边界；正文另显示期限与截止时间，摘要另显示最早／最晚到期时间。时间使用浏览器本机时区。
- 数据校验包括页长、游标、批次 ID、会话／类型匹配、数值及时间字段、重复 ID；异常不展示部分结果。仅保留展示字段，全部通过 `textContent` 渲染。
- 关闭弹窗、切任职、切会话、退出均清空记录及游标。身份 epoch、会话 epoch 与请求 generation 共同判定延迟响应；旧权限检查也不能恢复新身份入口。无 localStorage／sessionStorage 记录缓存。
- 403／404 清空记录、隐藏入口并禁用查询；401 由现有请求层退出。网络／503／响应格式异常清空记录，保留刷新重试路径。

## 验证过程

1. 新浏览器用例先因缺少记录入口失败，资源安全头用例先因新脚本路径 404 失败；实现后通过。
2. 真 Chrome 的边界测试覆盖管理员／普通员工、正文／摘要、实际数量与不连续序号、分页、末页、空页、503、非法字段、会话错配、循环游标、类型／会话／任职／权限探测延迟响应、群路由、撤权、令牌失效与手机布局。
3. 第一次竞态测试等待旧响应正文读完而超时。客户端身份变化会在读取正文前丢弃响应；改为观测真实 fetch 返回并等待事件处理，再断言旧数据未恢复。产品行为未因该测试等待问题更改。
4. 真实集成使用本地 HTTPS OIDC PKCE、生产 im-api／Outbox Worker、PostgreSQL／Redis 和 Chrome。浏览器读取已插入的不可修改正文／摘要证据，数据库断言 `listed_body`／`listed_digest` 审计各一条，并继续原实时通知及离线恢复流程。此测试未启动清理 Worker，不能代替前序清理算法验收。
5. 独立评审发现首次权限探测临时故障无恢复路径；新增浏览器断言先因缺少重试按钮失败，再补齐重试并通过。按评审建议将内存记录改为展示字段白名单。
6. 1280×850 与 390×844 截图均已查看，未发现卡片／UUID／说明裁切或横向溢出。

## 验收边界

页面只读，不提供配置期限、登记／解除保全、主动执行清理、导出证据、跨租户总览或任意会话 ID 的后台检索。序号边界可能有间隔，以实际数量为准。记录证明在线库提交了清理批次，不证明 WAL、备份或外部副本已擦除。已显示数据不会在服务器撤权瞬间自动消失；下一次查询得到 403／404 后清空。生产权限仍由服务端逐次检查。客户 IdP、真实 HTTPS 代理、浏览器兼容性及容量验收仍待客户环境联调。
