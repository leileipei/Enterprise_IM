# P4-18 Web 会话内消息搜索

## 范围与基线

沿用户“继续”授权，完成 P4-17 API 的 Web 单聊／群聊搜索入口。基线 `660ed4ad6551d2d46f4400385585220843977a6b` / 草稿 PR #64；分支 `codex/p4-18-web-message-search`，复用既有隔离工作树。本增量不修改后端搜索契约、权限规则或数据模型。

## 用户流程

1. 登录并选择任职，打开单聊或群聊历史，标题栏显示“搜索消息”。普通员工无需集团管理员权限；群策略暂停状态仍可查询已授权历史，最终权限由搜索 API 判定。
2. 弹窗显示会话及查询任职。输入 2～100 字的正文片段，点击“搜索”；打开弹窗不自动提交空关键词。
3. 展示消息序号、正文、发送者 ID 和服务端时间。“刷新，从头查询”重新授权并从首页开始；“继续查询”沿用服务端游标。
4. 空页但有游标时明确提示“本页未找到匹配正文；仍可继续查询”，保留续查按钮。只报告已展示条数，不显示总命中数。
5. 更改关键词清空结果与游标，关闭／Esc、切换会话／任职、退出或登录失效会清空关键词和结果。数据仅留在当前页面内存，不写浏览器存储。

匹配结果独立于消息同步时间线，不修改 after_seq、消息 ACK、待确认发送或历史补拉；不增加自动发送、跳转定位或权限授予。已有法务保全／保留期写操作的上下文切换约束继续生效。

## 页面与防护

- 独立 `message-search.js` 组件，通过现有可信请求函数携带访问令牌和当前任职；脚本在生产资源白名单注册，继续使用 no-store、安全响应头及同源资源策略。
- 提交去除首尾空白的关键词，字面匹配与 P4-17 一致。前端以逐 Unicode 码点小写并处理 `İ` 的简单小写差异，避免 JS 整串上下文小写的希腊 sigma 与 Go 字面匹配不一致。Chrome 覆盖 `İABC` 和 `ΟΣ`，真实 Go API／浏览器覆盖 U+FEFF＋`İ工单`。去空白使用与 Go 一致的 Unicode White_Space 集合，覆盖 U+0085 去除及非空白 U+FEFF 保留。
- 使用 BigInt 比较规范十进制字符串序号，允许非连续匹配，拒绝数字类型、前导零、溢出、重复 ID／序号和跨页倒退。不把搜索结果的稀疏序号当作同步时间线缺口。
- 整页检查会话 ID、数组上限、has_more／游标一致性、游标长度／循环、UUID、真实日期、UTF-8 字节上限、关键词匹配和 redacted 字段。校验通过后才复制指定字段和展示。
- 正文使用 textContent，保留换行与长文本换行；不会渲染 HTML、脚本或图片。响应内的大序号不会转换成 Number。
- 请求代次、身份、会话 epoch、类型及原始输入快照阻止迟到响应回填。关闭／改词／切换会取消请求；测试在忽略 AbortSignal 的受控请求中另行验证快照保护。
- 单次请求 15 秒超时。400／503、超时或异常 DTO 清空结果及续查游标，可从首页重试；403／404 清空并显示不可搜索或无权限。401 沿既有流程退出登录，invalid_identity 的 403 沿既有流程撤销当前任职并关闭弹窗。
