## 固定工具与SDK查找

```sh

export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
exec /usr/bin/xcrun "$@"
```

## Android 最终复制阶段的提供程序故障（2026-10-16）

### 受控范围与已发现问题

本节使用独立测试APK `com.enterpriseim.exportfixture`，在真实DocumentsUI侧栏选择 **IM Export Faults**。它是故障夹具，不是客户云盘：通过Android代理文件描述符，将真实文件写入4096字节后返回EIO；提供程序可持续拒绝delete，只有主机独立核验残留后才解除所属测试门禁。没有替换MainActivity／MethodChannel返回值，没有向业务应用注入URI或选择结果。

父提交bf3fefb的原生实测失败：4096字节部分目标保留，提供程序记录write_error、release、delete_error；应用仅返回export_unavailable，丢失原票据。独立契约测试也发现delete抛错或false被当作成功。修正为仅在delete成功后释放活动票据，失败返回export_cleanup_failed；保留URI／票据以供同一FileExport实例重试，清空当前RAM内容并拒绝后续write／finish。Dart既有pendingAbort流程会先重试所属票据，清理成功前不打开新选择器或源内容。失效票据不能清理另一活动会话。

原生资源生命周期提取到ExportSession，真实文件上的受控同步write／close异常由测试包装器产生；包装器仅存在test_support。检查真实文件字节、文件描述符已关闭、同时write／close失败保留原异常及suppressed关闭异常、delete抛错／false的明确失败和重试，以及完整复制。

另一个原生实测失败来自Android可靠描述符：接收端实际读取并保存70000字节后closeWithError，测试夹具确保该状态已报告，再执行客户端关闭。原来的AutoCloseOutputStream.close未检查状态，导致错误被当作成功。新ProviderOutput保留AssetFileDescriptor的原始区段语义，关闭前对支持错误检测的描述符调用checkError，同时无论检查结果如何均关闭流；已报告终态错误进入同一清理流程。对应测试通过instrumentation链接已安装目标APK的生产类，ExportSession／ProviderOutput不编入测试dex。

这不等于等待提供程序远端提交：checkError检查当时可用的状态，不等待任意异步上传；不支持可靠错误通道、关闭后才发生的云盘提交失败，以及Activity销毁／进程死亡后清理票据的持久恢复仍未验证。当前票据保留适用于存活的原生Activity与FileExport实例，不能据此承诺跨进程恢复。关闭异常的真实文件包装器与可靠描述符测试均明确归类，不声称已复现所有提供程序的底层close故障。

Android参考：[ParcelFileDescriptor.checkError](https://developer.android.com/reference/android/os/ParcelFileDescriptor#checkError())、[AOSP AutoCloseOutputStream实现](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/os/ParcelFileDescriptor.java)、[代理文件描述符回调](https://developer.android.com/reference/android/os/ProxyFileDescriptorCallback)。AOSP主线用于解释接口机制，不声称与模拟器二进制构建提交一致。

## Android 清理票据的 Activity／进程恢复（2026-10-16）

本节接续父提交 `d592aeb`，覆盖**原生已经确认的导出票据**。前一节关于“不支持跨进程票据恢复”的结论是当时快照；本节提供新的实现及专项结果，不改写历史证据。

### 持久化与恢复规则

- 应用私有 `no_backup/export-cleanup.json` 使用 Android `AtomicFile`。只保存版本、随机票据、目标 content URI、本次新增的持久 URI 授权位及状态；不保存正文、消息内容或源文件，也不重放中断的导出。
- 系统选择返回后，先落盘 PREPARED，再取得并检查 `takePersistableUriPermission`，最后落盘 PENDING，才把票据返回 Dart。提供程序不支持持久授权时不进入正文写入。
- Application 生命周期的单一串行 worker 执行提供程序与票据 IO。Activity 只负责系统选择器和通道适配；旧 Activity 的销毁不能清理新 owner 的会话。新导出在选择器／内容源打开前恢复遗留票据。
- PREPARED／PENDING 仅删除记录中所属目标。delete 返回 false、抛错、权限或提供程序不可用、不能确认已不存在时，保留票据并明确失败。确认删除后先落盘 DELETED，再释放本次新增授权并清除票据。不会释放进入本次导出前已有的授权位。
- 完整复制、flush、close 成功后先持久写入 COMMITTED。恢复遇到 COMMITTED／DELETED 只重试授权释放与票据清除，不再删除目标。COMMITTED 之前被杀的导出未向调用方报告成功，按未完成目标清理。
- 原子替换中断时可读上次有效记录；无有效原记录的残留 `.new`、损坏／过大／未知版本记录均阻止新导出。不会猜测 URI、扫描并删除目录内其它文件。

参考：[Android 持久 URI 授权](https://developer.android.com/training/data-storage/shared/documents-files#persist-permissions)、[AtomicFile](https://developer.android.com/reference/android/util/AtomicFile)、[Flutter MethodChannel.Result 线程约定](https://api.flutter.dev/javadoc/io/flutter/plugin/common/MethodChannel.Result.html)。

## 真实移动端挂起、设备绑定重验证和补拉专项

统一命令新增 `--verify-mobile-resume`，要求同时开启 `--verify-simulator`；Android 继续使用已固定的 API24／API36 镜像，iOS 使用明确指定的可用运行时与设备类型。每次必须使用新的输出目录，程序只新建和清理本轮自有设备。该开关可与 Android 的 `--verify-mobile-boundaries` 同时使用，分别执行两个不同的集成目标。

专项使用生产移动活动适配器、同步协调器、同步引擎、已读队列，以及应用支持目录中的真实加密 SQLite。系统事件来自 Android HOME／MAIN 或 iOS 启动 Safari／返回应用，不直接调用生命周期回调。夹具 `LifecycleProbe` 仅观察系统通知：paused 时同步原子写本轮 nonce/PID 标识；主机确认后等待1.15秒再返回前台；resumed 时用单调时钟记录实际后台间隔。这样即使系统停止后台 Dart 定时器，验证仍能恢复。系统回调只记录和检查状态，测试框架断言在已注册的测试主体内执行。

三个后台／恢复周期验证：

1. 正在等待 read ACK 时进入后台，旧正文授权撤回，迟到 ACK 不加入本地已读集合；先实际建立 ready 连接，再确认后台关闭旧连接。
2. 返回前台发起携带当前设备 ID/Token 的 `after_seq=0` 补拉；响应暂缓时旧页不能上报已读。新页 seq1/seq2 提交且确认设备送达后，seq2 全新可见曝光收到已读 ACK。
3. 下一次恢复收到明确 `401 invalid_device` 后清理接收状态，旧页失效、回执停止；再一次后台／前台切换不能自动重启已终止会话。

同一集成用例内有七个主机握手阶段，不能计为七个独立用例。每个平台在基础活动＋安全存储写／校验三个既有用例之外，先执行一个原生存储打开／查询用例，再执行一个挂起恢复用例，共5个；不把 `tearDownAll` 计入业务数量。控制器同时要求完整阶段、同一原生 PID、随机 probe、原生断言结果及标准 driver 真实退出0；仅看到 `All tests passed` 文本不够。失败时先通知控制线程停止，阻塞调用后和系统动作前再次检查取消，线程退出后才开始设备清理。

**覆盖边界：** API 和 socket 使用受控协议响应，专项页面是测试夹具。本项设备重验证指 fresh sync 携带当前设备凭据并处理服务端拒绝，不是设备续期 `renew`。Go 后端源码 `internal/policystore/device_sync.go` 在同步返回前锁定核对设备凭据并检查过期，但本专项不执行该 Go 服务、数据库、真实身份源或真实后端撤销流程。真机、进程被杀后的会话恢复、通知、分发签名和 CI 继续单独验收。

### 原生运行发现并修正的产品阻断

- Android 在应用命名空间中将 `/data/user/0` 暴露为指向 `/data/data` 的链接；同设备 adb shell 视图却显示目录。应用内逐级路径类型及 `Link.target()` 的两轮独立诊断证实这一差异，原加密存储祖先链接守卫因此拒绝正常支持目录。生产入口现仅在 Android、精确此前缀且原始目标完全等于 `/data/data` 时转换前缀。未知／相对目标拒绝；不解析应用子路径，应用目录及 SQLite／WAL／SHM 链接守卫不变。登录存储与专项夹具共用该入口，真实文件系统回归检查拒绝路径及未受影响的哨兵内容。
- 真实 iOS 恢复后，授权页 `after=0,next=2` 跨过已提交游标1，被存储旧交叉条件拒绝。最小共享回归独立复现 `StoreFailure`。修正只删除该交叉拒绝；`SyncPage` 仍要求严格连续消息且末项等于next，存储继续要求after不大于旧游标、同任职、receipt_revision不倒退、generation/proof一致，并保留最大游标。新回归同时覆盖跨游标扩展、较短历史页不回退及任职／revision拒绝；既有缺口拒绝继续通过。

两项产品RED与准备期失败分别保留。新的共享回归为248项通过、静态检查零问题；各平台原生解除结论以新的运行结果为准。
