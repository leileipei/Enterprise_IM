# P4-09 Web 登记与解除法务保全

## 范围与基线

继续完成前序已明确的 Web 登记／解除保全入口。基线 P4-08 `e71ce84` / 草稿 PR #55；分支 `codex/p4-09-web-legal-hold-actions`，沿用原隔离工作区。复用现有 POST 登记及解除 API；无新增迁移、后端合约或清理 Worker 配置变更。

## 操作与状态

- 当前集团管理员在选中会话内填写案件引用登记保全；引用按 Unicode 码点计 1～128 字符，去掉首尾空白，拒绝控制字符及孤立 UTF-16 代理。
- 只有未解除记录显示“解除此项保全”。选择后固定目标保全 ID 和案件引用，填写已取得的审批引用，勾选确认仅解除此项后提交。服务端只记录引用，不核验外部审批。
- 每项操作生成随机 UUID request_id，绑定身份 epoch、任职、会话 epoch、类型、保全 ID、引用和会话标题。发送期间冻结表单、禁止重复提交／放弃；查询与刷新暂停。
- 网络失败、503、15 秒无响应或不符合绑定的成功 DTO，显示“结果待确认”，原编号及请求内容保留用于重试。超时取消等待不代表服务器未执行。
- 校验完整成功 DTO、会话及案件、登记／解除操作者与任职；解除另校验目标 ID 和审批引用。登记幂等回放可返回后来已解除的记录，不宣称此刻仍处于保全中。
- 成功只表述“服务器已确认保全记录”，随后重新读取列表；单独操作提示不被列表刷新覆盖。解除一项不影响其他有效保全，实际状态以刷新记录为准。
- 400／409 清除当前重试状态并要求检查／核对；403／404 清空记录、禁用入口；强制 401 或身份失效沿用原认证清空，旧 ACK 不恢复页面。
- 关闭弹窗仍保留待确认操作。用户切会话／任职或主动退出被阻止并重开待确认操作，显示冻结的原会话名及 ID。明确确认放弃重试后解除阻止，并说明不代表撤销服务器操作，须核查记录。
- 引用与重试数据仅保留在页面内存；刷新、强制退出会丢失本页恢复信息。beforeunload 对待确认操作发出离页提示，无法强制所有浏览器阻止离页。服务端 request_id／事件语义保持不变。

## 验证过程

1. 新浏览器测试先因缺少未解除项的操作按钮失败，实现后登记／解除字段与请求契约可验证。
2. 真 Chrome 的确定性 HTTP 边界验证空白／控制／超长引用不发送，解除不勾选不发送，已解除项无按钮；提交后响应正文截断导致结果未知，重试沿用原 ID、原 actor 与引用，服务边界只记录一次提交。
3. 直接在响应头前断开会触发 Chrome 自动重传并透明恢复，不能保证测试进入待确认路径。改为已提交后发送不完整正文并明确关闭连接，验证客户端在结果未确认时保留原请求；没有以该工具等待问题修改产品行为。
4. 持续无响应用例先因一直停在提交状态失败，加入 15 秒等待上限后原 ID 重试可恢复。发送中不能重复提交或放弃。
5. DTO 会话错配及登记人错配转待确认；503、400、403、404、409 按状态处理。切会话／任职／退出被阻止；放弃对话框取消保留 pending，确认解除阻止但不宣称服务器操作撤销。
6. 真实 HTTP 定时补拉收到 401 时强制退出，再释放旧 POST ACK，弹窗／字段／列表不恢复。待确认 beforeunload 处理器取消事件的断言通过，未将此当成客户原生离页提示验收。
7. 真实生产 API／Worker、本地 HTTPS OIDC PKCE、PostgreSQL／Redis 与 Chrome：浏览器登记新案件再解除它，其他有效案件保持保全中。数据库验证新保全行一条、事件两条、登记／解除审计与三次列表查询一致；既有清理记录、实时通知和离线恢复继续通过。
8. 桌面与手机操作表单截图已查看，长案件／目标 ID 可换行，确认项与按钮未横向溢出，长列表可滚动。
9. 独立评审唯一 Minor 为待确认弹窗重开丢失会话标题；新增断言先因标题为空失败，再恢复冻结会话名称及 ID。复查后无 Critical、Important 或 Minor。
