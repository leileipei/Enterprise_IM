## 2. Windows启动门禁

使用PowerShell7、本机Windows x64、Visual Studio的Desktop development with C++工具链和Windows SDK。专用一次性OS测试账号中不得有真实IM服务、账号或保存的凭据。正常启动会读取该账号的应用配置／安全存储；不可在个人已登录账号中执行此门禁。脚本不删除用户账号缓存或凭据。

在仓库根执行：

```powershell
./scripts/build-client-windows.ps1 -FlutterSdk <固定SDK绝对路径>
./scripts/test-client-windows-startup.ps1 -Executable ./clients/enterprise_im/build/windows/x64/runner/Release/enterprise_im.exe -Output ./startup.json -IsolatedTestAccount
```

门禁实际启动同一个固定摘要的`.exe`。无参数应出现窗口，正常关闭实际退出0；8组自有假参数应在10秒内实际退出1，含token、拆分token、业务HTTPS／本机回调／custom URI、文件路径、空参数及不支持的COM冷启动参数。失败或超时只清理本次由脚本启动的Process；报告逐项退出码、强制清理及失败，不能把清理后的退出码记成业务PASS。解析失败／异常argc仅能由宿主入口夹具验证，Windows原生参数解析另由此门禁覆盖。

结果仅证明启动边界／窗口启动，不验证登录、IME、回执、系统通知显示或真实后端。所有参数为假输入；不得把真实令牌、回调code或秘密放入命令行。

## 3. 原生回调与系统安全存储

在客户端目录以固定SDK执行：

```text
flutter test integration_test/desktop_lifecycle_test.dart -d windows --no-pub
flutter test integration_test/desktop_lifecycle_test.dart -d macos --no-pub
```

该入口只测试编译后桌面应用的真实127.0.0.1回调取消／端口关闭及旧回调不可重新打开。它不注入窗口事件，也不证明最小化、焦点或真实后端恢复，文件名不是验收范围。

生成一次全新的随机64字符hex命名空间（32字节，不是账号或认证秘密），以相同ID启动两个独立原生进程：

```text
flutter test integration_test/secure_storage_test.dart -d <windows或macos> --no-pub --dart-define=IM_VAULT_PROBE_ID=<全新64字符hex> --dart-define=IM_VAULT_PROBE_PHASE=write
flutter test integration_test/secure_storage_test.dart -d <windows或macos> --no-pub --dart-define=IM_VAULT_PROBE_ID=<同一ID> --dart-define=IM_VAULT_PROBE_PHASE=verify
```

write拒绝覆盖已有值；verify校验自有marker后删除该记录并复读为空。无论write步骤结果，均尝试verify以核实所属记录清理；失败时不得声称已清理，记录该命名空间待人工核实。不得deleteAll或清除其它访问组／账号。单个write进程中的读回不能替代重启验证。未准备开发证书的macOS不应关闭沙盒／移除Keychain权限以获取PASS。

## 6. 原生真实后端编排（2026-10-13准备，未运行）

正式入口为`scripts/test-client-macos-backend.py`，默认目标macos。准备一次性空OS测试账号、固定SDK及包缓存，操作者提供已有开发团队和**有效证书的完整SHA1或完整名称**；不接受名称片段或“Apple Development”通用标签。所有路径须为绝对路径，output的父目录必须存在，output目录本身须全新，脚本拒绝覆盖已有结果。

```text
python3 scripts/test-client-macos-backend.py --flutter-sdk <固定SDK绝对路径> --pub-cache <已准备缓存绝对路径> --go <Go程序绝对路径> --output <全新结果目录绝对路径> --isolated-test-account
```

原生预检检查macOS ARM64、固定SDK无已跟踪改动、Xcode首次启动和有效签名身份、明确的一次性账号声明及团队／证书选择。缺失时实际退出2、保存preflight.json并在创建数据库／应用之前停止，不接受许可、不创建或导入证书、不关闭签名。结果目录内包含命令、来源摘要、实际退出、注册／ready／清理证据及边界。

原生消息模式建立自有PostgreSQL／Redis和正式API／Outbox／Receipt服务，复制已跟踪macOS工程，在自有副本执行离线锁定pub get，然后启动编译的Debug `real_backend_test`消息场景。运行时须由现有登记器核对父进程、实际可执行路径和摘要；目标为副本内的Debug enterprise_im.app，而非flutter_tester。原生模式预计5个直属登记进程（包括pub get和Flutter命令）；宿主模式为4个。Flutter父进程实际退出和应用在等待后已不存在分别记录，不凭空填写被父进程回收的应用OS退出码。

沙盒应用不读取宿主/tmp中的配置或CA，也不向该目录写数据库。新鲜的自有短期凭据和公共测试CA仅打包到该次临时Debug测试应用的`assets/owned_backend.json`；普通客户端pubspec及entitlements不变，不将令牌写入命令行或导入系统CA。此Debug应用含测试凭据，仅用于自有测试，**不得归档分发或当作正式安装包**；编排结束删除自有构建副本。原生存储由应用支持目录API创建全新子目录，消息结束逐项关闭会话、复读所属安全存储记录为空，再删除所属私有目录；失败保留未验证状态和opaque恢复句柄，不清除其它账号。

消息页面出现提示后，将实际窗口最小化，等待5秒，再恢复并点击窗口。入口须观察真实hidden状态（仅inactive不足）、至少700ms内没有本地已读、服务器恰好两条回执均未读，再等待新的前台与焦点、同步准入及两条已读。窗口操作等待各90秒，原生编排预算15分钟。它使用实际尺寸和生产NativeActivityAdapter，不注入窗口事件。原生签名构建／插件／窗口分支当前尚未运行，不能用源码或宿主通过替代。

明确加`--target host`可运行同一正式脚本的宿主验证；此模式替代OS安全存储和焦点，只证明正式API／数据库／共享控制器及widgets。不要在宿主结果上改写原生状态。

附件Go场景已接相同macOS启动、临时资源和私有存储机制，但正式脚本当前只编排消息；附件的MinIO／扫描器专用原生启动尚待运行入口补齐。附件仍使用自有生成文件和内存导出目的地，不验证系统选择器／实际导出／附件原生UI。两类场景使用真实broker刷新及冷恢复，不代表交互式浏览器OIDC登录或两个原生进程重启。Windows原生编排不受该macOS脚本支持，CI没有发布或执行。
